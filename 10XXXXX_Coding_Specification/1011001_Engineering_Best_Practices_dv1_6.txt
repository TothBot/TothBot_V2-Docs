ENGINEERING BEST PRACTICES
============================================================

============================================================
1. PURPOSE
============================================================

This document defines non-negotiable engineering standards
that apply to ALL TothBot V2 Pathway 2 code. Every coding
spec (1011002 through 1011014) must conform to these
standards without exception. Quality is built in — not
inspected in (Deming Principle 1).

Primary mission lens: every engineering decision serves
maximizing profit and minimizing loss, with emphasis on
minimizing loss. Slow, imprecise, or unreliable code is
a loss event.

This document is a pre-requisite for all other AA=10
Pathway 2 instance documents. All coding must comply.

4. RUNTIME ENVIRONMENT
============================================================

BP-ENV-001  Python version: 3.12.3 EXACTLY.
            No other version is permitted.
            Runtime: Hetzner VPS, Ubuntu 24.04.4 LTS.

BP-ENV-002  Single Python process. asyncio-based.
            All I/O-bound operations use async/await.
            No multiprocessing. No threading except
            Logger's QueueListener (explicitly permitted).

BP-ENV-003  uvloop MANDATORY on Linux deployment:
              import asyncio
              import uvloop

              # Python 3.11+ pattern (required):
              asyncio.run(main(), loop_factory=uvloop.new_event_loop)

              # Alternative using asyncio.Runner:
              with asyncio.Runner(
                  loop_factory=uvloop.new_event_loop) as runner:
                  runner.run(main())

            uvloop replaces the default asyncio event loop.
            Provides ~2-4x asyncio performance improvement.
            Required on all Linux VPS deployments.
            DO NOT use uvloop in unit tests (compatibility).

BP-ENV-004  TCP_NODELAY on all WebSocket connections.
            Eliminates Nagle's algorithm delay on small
            packets. Required for low-latency WS messaging.

              import websockets
              # In websockets library: use create_connection
              # with sock option or set at OS level.
              # Implementation detail: set
              # socket.TCP_NODELAY = True on the underlying
              # socket after connection establishment.

BP-ENV-005  All code runs in UTC. No local timezone.
            All timestamps: ISO 8601, UTC, with microseconds.
              from datetime import datetime, timezone
              ts = datetime.now(timezone.utc).isoformat()

5. JSON HANDLING — orjson
============================================================

BP-JSON-001  All JSON parsing: orjson.loads()
             3-5x faster than stdlib json.loads().
             Required on all Kraken WS and REST message
             parsing (high-volume hot path).

BP-JSON-002  All JSON serialization:
               orjson.dumps(data, default=_json_default).decode()
             orjson.dumps() returns bytes. .decode() converts
             to str where str is required.

BP-JSON-003  DO NOT use stdlib json module anywhere
             in Pathway 2 code. orjson is the sole
             JSON library.

BP-JSON-004  Financial values from JSON must be converted
             to Python Decimal from string, NEVER from float:
               price = Decimal(str(msg["price"]))
             See Section 8 (Decimal Precision) for full rules.

BP-JSON-005  orjson Decimal serialization callback — MANDATORY:
             orjson does not natively serialize Decimal.
             All serializers MUST provide this callback:

               def _json_default(obj):
                   if isinstance(obj, Decimal):
                       return str(obj)
                   raise TypeError(
                       f"Object of type {type(obj)} is not"
                       f" JSON serializable"
                   )

               # Usage:
               data = orjson.dumps(
                   record, default=_json_default).decode()

             Without this callback, orjson will raise
             TypeError on any Decimal value.

BP-JSON-006  All log records serialized via orjson with
             _json_default. No other serializer in Logger.

6. ASYNC DESIGN RULES
============================================================

BP-ASYNC-001  Async-first design. All I/O operations use
              async/await. No synchronous blocking calls
              on the asyncio event loop thread.

BP-ASYNC-002  NEVER use time.sleep() on the event loop.
              Use await asyncio.sleep() instead.

BP-ASYNC-003  NEVER use requests library. Use aiohttp
              for all HTTP operations (async HTTP client).

BP-ASYNC-004  All aiohttp.ClientSession: explicit timeout
              and connector. NEVER bare ClientSession():

                timeout = aiohttp.ClientTimeout(
                    total=10,
                    connect=5,
                    sock_read=8
                )
                connector = aiohttp.TCPConnector(
                    limit=10,
                    limit_per_host=5,
                    force_close=False
                )
                session = aiohttp.ClientSession(
                    timeout=timeout,
                    connector=connector
                )

BP-ASYNC-005  Logger QueueListener is the ONLY permitted
              non-asyncio thread. No other thread creation
              permitted in Pathway 2.

BP-ASYNC-006  asyncio.Queue for inter-coroutine communication.
              queue.Queue (stdlib) for Logger QueueHandler/
              QueueListener pattern ONLY (non-asyncio thread
              boundary). These are distinct use cases with
              different queue types — do not substitute.

BP-ASYNC-007  Graceful shutdown: cancel all running tasks
              before closing event loop:
                tasks = asyncio.all_tasks(loop)
                for task in tasks:
                    task.cancel()
                await asyncio.gather(*tasks,
                                     return_exceptions=True)

7. HTTP CLIENT RULES
============================================================

BP-HTTP-001  All aiohttp.ClientSession requires explicit
             timeout and connector per BP-ASYNC-004.

BP-HTTP-002  ClientTimeout values:
               total=10    (full request timeout)
               connect=5   (connection timeout)
               sock_read=8 (read timeout)

BP-HTTP-003  TCPConnector values:
               limit=10          (total connections)
               limit_per_host=5  (per-host connections)
               force_close=False (reuse connections)

BP-HTTP-004  All REST API calls: retry on 429 and 5xx
             with exponential backoff. Max 3 retries.
             Do not retry on 4xx (client errors).

BP-HTTP-005  All REST responses: parse via orjson.loads()
             per BP-JSON-001. Never stdlib json.

8. DECIMAL PRECISION FOR PRICE AND QUANTITY ROUNDING
============================================================

BACKGROUND (AR-047 amendment):
Python float arithmetic produces binary representation
errors for decimal increments:
  math.floor(42350.15 / 0.1) * 0.1
    = 42350.099999999985  ← WRONG
Kraken matching engine requires prices that are exact
multiples of price_increment. A float-rounded price
is rejected with EOrder:Invalid price. This is a loss
event. All rounding uses Decimal.quantize().

BP-DEC-001  ALL Kraken-sourced numeric values MUST be
            converted to Decimal using the STRING constructor
            immediately on receipt:

              price = Decimal(str(msg["price"]))
              qty   = Decimal(str(msg["qty"]))

            NEVER use the float constructor:
              WRONG: Decimal(msg["price"])   # float error
              WRONG: Decimal(0.1)            # float error
              CORRECT: Decimal(str(0.1))     # exact

            Applies to ALL Kraken-sourced values:
              - ticker bid, ask prices
              - executions avg_price, last_price, cum_cost
              - instrument price_increment, qty_increment,
                qty_min, cost_min
              - balances channel balance, amount
              - GetOHLCData OHLC candle values

BP-DEC-002  ROUNDING FOR ORDER QUANTITY:
            Round DOWN (toward zero). Conservative size.

              from decimal import Decimal, ROUND_DOWN
              def round_qty(raw_qty: Decimal,
                            qty_increment: Decimal) -> Decimal:
                  return raw_qty.quantize(
                      qty_increment,
                      rounding=ROUND_DOWN
                  )

BP-DEC-003  ROUNDING FOR ENTRY LIMIT PRICE:
            Round DOWN (toward zero for buy limit).
            Ensures limit buy rests on book as maker order.

              def round_entry_price(raw_price: Decimal,
                                    price_increment: Decimal
                                    ) -> Decimal:
                  return raw_price.quantize(
                      price_increment,
                      rounding=ROUND_DOWN
                  )

BP-DEC-004  ROUNDING FOR TP LIMIT PRICE:
            Round UP (toward positive infinity).
            TP is a SELL limit. Higher price preserves R:R.

              from decimal import Decimal, ROUND_UP
              def round_tp_price(raw_tp: Decimal,
                                 price_increment: Decimal
                                 ) -> Decimal:
                  return raw_tp.quantize(
                      price_increment,
                      rounding=ROUND_UP
                  )

BP-DEC-005  ROUNDING FOR EMERGSL TRIGGER PRICE:
            Round DOWN (toward zero).
            Lower trigger fires earlier — limits loss.

              def round_emergsl_price(raw_sl: Decimal,
                                      price_increment: Decimal
                                      ) -> Decimal:
                  return raw_sl.quantize(
                      price_increment,
                      rounding=ROUND_DOWN
                  )

BP-DEC-006  ROUNDING DIRECTION SUMMARY:

            Value                  Round   Rationale
            ─────────────────────  ──────  ──────────────────
            order_qty (entry)      DOWN    Conservative size
            entry limit_price      DOWN    Rest on book (maker)
            tp_price (sell limit)  UP      Better exit, R:R
            emergSL trigger price  DOWN    Earlier fire, safer
            qty (partial fill TP)  DOWN    Conservative exit

BP-DEC-007  INSTRUMENT INCREMENT CONVERSION:
            All instrument channel snapshot values converted
            to Decimal at parse time (once, at startup):

              for pair in instrument_snapshot["pairs"]:
                  pair_cache[pair["symbol"]] = {
                      "price_increment": Decimal(
                          str(pair["price_increment"])),
                      "qty_increment": Decimal(
                          str(pair["qty_increment"])),
                      "qty_min": Decimal(str(pair["qty_min"])),
                      "cost_min": Decimal(str(pair["cost_min"])),
                      "status": pair["status"],
                  }

BP-DEC-008  PROHIBITION:
            math.floor() and math.ceil() MUST NOT be used
            for any price or quantity rounding.
            Code review MUST reject any use of math.floor/
            math.ceil for financial value rounding.

            Permitted uses of math.floor/ceil:
              - Non-financial array indexing
              - Statistical computations (EWMA, CUSUM)
                where float precision is acceptable

9. ERROR HANDLING
============================================================

BP-ERR-001  No bare except clauses:
              WRONG: except:
              CORRECT: except Exception as e:
              CORRECT: except (ValueError, KeyError) as e:

BP-ERR-002  All exceptions must be logged before re-raising
            or handling. Use Logger (never print() on hot path).

BP-ERR-003  Unhandled exceptions in asyncio tasks:
            Attach exception handler to event loop:
              loop.set_exception_handler(handle_exception)
            All unhandled exceptions: log CRITICAL + alert.

BP-ERR-004  Never suppress exceptions silently. If an
            exception cannot be handled, log it and let
            it propagate. Suppressed exceptions hide
            system failures.

BP-ERR-005  KeyError on Kraken message parsing: log WARN
            with the raw message. Do not crash the hot path.
            Continue processing next message.

10. LOGGING RULES
============================================================

BP-LOG-001  All logging through the Logger component.
            No print() statements in production code.
            No direct file writes from non-Logger modules.

BP-LOG-002  Logger is never blocked by callers.
            Callers fire-and-forget via QueueHandler.

BP-LOG-003  All log records: structured JSON via orjson
            with _json_default per BP-JSON-005.

BP-LOG-004  All financial values in log records: store as
            string representation of Decimal. Never float.

BP-LOG-005  All log event codes: SCREAMING_SNAKE_CASE.
            All registered in 1011007 Logger_Coding_Spec
            Section 5. No undocumented event codes.
