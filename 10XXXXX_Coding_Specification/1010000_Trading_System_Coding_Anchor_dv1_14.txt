3. PATHWAY 2 — TRADING SYSTEM SCOPE
============================================================

Pathway 2 governs the TothBot V2 automated cryptocurrency
spot trading system running on Kraken exchange, plus its
supporting operational scripts.

Execution environment:
  Platform:    Hetzner VPS (87.99.141.44)
  OS:          Ubuntu 24.04.4 LTS
  Python:      3.12.3
  Exchange:    Kraken Spot (WebSocket v2 + REST)
  Clock:       Kraken OHLC 5-minute candle close (WS push)
  Repository:  github.com/TothBot/TothBot_V2-Code

Pathway 2 runs ONLY on the VPS. It never runs in GitHub
Actions. It has no awareness of document control state.
See TB00000 Section 3.4.3 — Pathway Separation Rules.

Repository subfolder layout (TothBot_V2-Code):
  tothbot/      Python package — trading system modules
                (ws_manager.py, signal_pipeline.py,
                execution_engine.py, exit_controller.py,
                position_mirror.py, logger.py,
                long_module.py, selection_ctrl.py,
                ciats.py, risk_engine.py,
                regime_engine.py, vps_deployment.py,
                startup_sequence.py, __init__.py,
                __main__.py).
  operations/   Operational support scripts — non-Python.
                VPS monitoring, deployment helpers,
                maintenance utilities. Parallel to
                tothbot/. All files are controlled
                documents per 0311001 HR-DC-001.
                Example: operations/tothbot_sweep.sh
                (VPS health monitor; deployed to VPS
                via git pull; executed as
                /root/TothBot_V2-Code/operations/
                tothbot_sweep.sh or from a symlink).
  tests/        Test suites (pytest).
  config/       Configuration placeholder.
  deploy/       Deploy placeholder.
  scripts/      Scripts placeholder.

All files in all subfolders are controlled documents
with 7-field DC headers, Revision History, and registry
entries in Section 5 below.

    Observed Kraken REST `EAPI:Invalid key` outages of

    (2026-04-19 02:49:21–02:51:54 UTC) each exceeded the
    prior N=10 / ~181s retry window, producing WS_MGR_FATAL

    sites (_rest_get_ws_token, _rest_get_open_orders,

    live-mode entry, balance, and order-query calls would
    have failed 100%. Fix in dv1_22 spec / ws_manager.py
    dv1_23: new _sign_rest_request helper computes
    HMAC-SHA512 per REST-AUTH-001; all three call sites
    attach API-Key + API-Sign + Content-Type headers.

    WM-REST-SIGN-003 and HR-WM-023.

PARKING LOT — NEW TB00108 (OI-024):
  CIATS currently derives its 200-trade statistical
  corpus by tailing tothbot.log. With 1011007 dv1_4
  landing the permanent trade record file
  (/home/tothbot/records/trades_<YYYY>.jsonl), the
  authoritative long-term source for TRADE_CLOSE
  records is no longer tothbot.log. The practical
  consequence today is benign (both files currently
  carry identical TRADE_CLOSE payloads — enforced by
  1011007 dv1_4 LG-TOB-003). The structural consequence
  is that once tothbot.log rotates past retention, the
  CIATS read path loses access to older trades while
  the permanent file still has them — defeating the
  OI-023 fix for CIATS's own purposes. Migrate CIATS's
  corpus read from tothbot.log tail to
  trades_<YYYY>.jsonl (plus prior-year files for
  cross-year spans) in a future session. Out of TB00108
  scope per TB00107 NSI Section 6. Address when paper-
  trading throughput begins to surface the corpus-
  truncation risk in practice, or at the next CIATS
  spec revision — whichever comes first.
