REGIME ENGINE CODING SPECIFICATION
============================================================

============================================================
1. PURPOSE
============================================================

This document is the complete, unambiguous coding contract
for the TothBot V2 Regime Engine. It classifies the market
regime for each pair daily at 00:00 UTC. Regime classification
is the highest-priority correctness requirement in the system.
An incorrect regime classification directly causes loss.

3. FIVE CODING-READINESS QUESTIONS
============================================================

(1) What does Regime Engine DO?
    Classifies the current market regime for each pair
    in the trading universe daily at 00:00 UTC using
    committed daily OHLC candles from Kraken REST API.
    Staggered 1.1s between pairs (rate limit compliance).
    Stores result in regime_cache. Provides stale fallback
    on failure. Two-level tagging: asset regime + BTC/USD
    market regime. Gate 3 and Gate 6 read this cache.

(2) Interfaces?
    Input: Kraken REST GetOHLCData (interval=1440, interval=5)
    Output: regime_cache dict[str, RegimeState]
            market_regime (BTC/USD) tagged at entry
    Consumers: Signal Pipeline Gate 3 (pre-filter),
               Gate 6 (sizing modifier),
               Position Mirror (regime tag on trade entry),
               CIATS (per-regime P&L archiving)

(3) Hard rules?
    ALWAYS exclude response[-1] (uncommitted candle).
    ALWAYS use committed_candles = candles[:-1].
    ALWAYS stagger 1.1s between pair REST calls.
    NEVER use asyncio.gather() for regime OHLC calls.
    NEVER halt on regime computation failure — use stale.
    ADX batch computation on full history (all committed).
    NEVER compute ADX incrementally in Regime Engine.
    BTC/USD ALWAYS in trading universe (market regime proxy).
    regime_cache updated atomically per pair.
    Stale regime: use prior day, log REGIME_STALE_WARNING.

(4) What triggers it?
    00:00 UTC daily — asyncio.Task scheduled at midnight.
    Also at startup (Step 8 Call C per 1011014 SS-WARMUP-004).

(5) What does it log?
    REGIME_COMPUTED: market_regime, asset_regime per pair,
      adx_14, ema_20, ema_50, atr_pct, computed_at.
    REGIME_STALE_WARNING: hours_since_update, pair.
    WARMUP_REST_FAILED: pair, interval, error.
    REGIME_RATE_LIMIT_HIT: pair, retry_count.

============================================================
4. REGIME TAXONOMY
============================================================

Six regimes from 0711002 Regime_Taxonomy_Specification.
All thresholds are CIATS-owned starting values.

4.1 Directional Regime (from ADX and EMA):

  TRENDING_POSITIVE:  ADX(14) > 25 AND EMA(20) > EMA(50)
  TRENDING_NEGATIVE:  ADX(14) > 25 AND EMA(20) < EMA(50)
  NON_DIRECTIONAL:    ADX(14) <= 25

  adx_threshold:     25  (CIATS-owned starting value)
  htf_ema_periods:   20 / 50  (CIATS-owned starting value)
  window:            50 days rolling

4.2 Volatility Regime (from ATR percentile):

  NORMAL_VOL:         ATR percentile <= 67th
  ELEVATED_VOL:       ATR percentile > 67th

  atr_percentile_thresh: 67th percentile (CIATS-owned)
  window:             trailing 50 daily ATR values

4.3 Complete 6-regime cross:

  TRENDING_POS + NORMAL_VOL     ← ENTRY ALLOWED
  TRENDING_POS + ELEVATED_VOL   ← ENTRY ALLOWED (50% size)
  NON_DIR + NORMAL_VOL          ← NO ENTRY
  NON_DIR + ELEVATED_VOL        ← NO ENTRY
  TRENDING_NEG + NORMAL_VOL     ← NO ENTRY
  TRENDING_NEG + ELEVATED_VOL   ← NO ENTRY

  Gate 3 blocks: TRENDING_NEG (any vol), NON_DIR + ELEVATED.
  Gate 6 sizes at 50% for NON_DIR + NORMAL (no, blocked by Gate 3).
  Gate 6 sizes at 50% for TRENDING_POS + ELEVATED (allowed entry,
    reduced size due to elevated volatility risk).

5. DATA SOURCING — GETOHCLDATA REQUIREMENTS
============================================================

RE-OHLC-001  CRITICAL: The LAST candle in any GetOHLCData
             response is ALWAYS the current not-yet-committed
             candle. Its data is incomplete (mid-candle).
             ALWAYS exclude it.

RE-OHLC-002  MANDATORY pattern for all OHLC data usage:
               data = await get_ohlc_data(pair, interval=1440)
               committed_candles = data[:-1]  # ALWAYS exclude last
             NO EXCEPTIONS. Using data[-1] in any computation
             corrupts all indicators: ADX (zero DM), EMA (biased
             close), ATR (zero range). This is a silent error —
             the computation runs but produces wrong values.

RE-OHLC-003  Available daily candles (Kraken API returns 720):
               response length: 720 candles
               committed_candles = response[:-1] = 719 candles
               This is confirmed available for all pairs
               in the Kraken trading universe.

RE-OHLC-004  Decimal conversion immediately on parse:
               for candle in committed_candles:
                   open_d  = Decimal(str(candle["open"]))
                   high_d  = Decimal(str(candle["high"]))
                   low_d   = Decimal(str(candle["low"]))
                   close_d = Decimal(str(candle["close"]))
                   volume_d = Decimal(str(candle["volume"]))
             Per BP-DEC-001: all OHLC values converted to
             Decimal via string constructor immediately.

6. INDICATOR COMPUTATION
============================================================

------------------------------------------------------------
6.1 ATR(14) — Wilder's True Range (daily)
------------------------------------------------------------

RE-IND-001  ATR computation uses committed_candles only.
            This is the DAILY ATR used for VOLATILITY REGIME.
            It is a different value from the 5-min ATR used
            for MAE threshold in the pipeline.

RE-IND-002  True Range computation:
              prev_close = committed_candles[0].close
              for i, candle in enumerate(committed_candles[1:]):
                  TR = max(
                      candle.high - candle.low,
                      abs(candle.high - prev_close),
                      abs(candle.low  - prev_close)
                  )
                  tr_list.append(TR)
                  prev_close = candle.close

RE-IND-003  ATR(14) — Initial + Wilder smoothing:
              if len(tr_list) < 14:
                  # Insufficient data — use stale or skip
                  return None
              # Simple average for first 14 values
              atr = sum(tr_list[:14]) / 14
              # Wilder smoothing forward
              for tr in tr_list[14:]:
                  atr = (atr * 13 + tr) / 14
              # All operations in Decimal

RE-IND-004  ATR percentile (trailing 50 daily ATR values):
              from statistics import quantiles
              atr_window = [daily_atr[i] for i in -50:]
              p67 = quantiles(atr_window, n=100)[66]
              vol_regime = (ELEVATED_VOL if daily_atr[-1] > p67
                            else NORMAL_VOL)
              Minimum window: 30 values for stability.
              With 719 candles: confirmed adequate.

------------------------------------------------------------
6.2 ADX(14) — Wilder's Average Directional Index
------------------------------------------------------------

RE-IND-005  ADX CONVERGENCE:
            First valid value: 28 committed candles.
            Full convergence accuracy: 128 candles.
            Available: 719 candles (5.6x convergence requirement).
            Regime Engine uses BATCH computation on all 719
            committed candles. Full convergence guaranteed.
            DO NOT compute ADX incrementally in Regime Engine.

RE-IND-006  ADX computation — batch Wilder's method:

              from decimal import Decimal
              import statistics

              def compute_adx_14(committed_candles):
                  """Batch ADX(14) on all committed daily candles."""
                  N = 14
                  alpha = Decimal("1") / N  # Wilder: 1/N not 2/(N+1)

                  plus_dm_list = []
                  minus_dm_list = []
                  tr_list = []

                  prev_high  = committed_candles[0].high
                  prev_low   = committed_candles[0].low
                  prev_close = committed_candles[0].close

                  for candle in committed_candles[1:]:
                      H, L, C = candle.high, candle.low, candle.close
                      move_up   = H - prev_high
                      move_down = prev_low - L
                      plus_dm   = move_up if move_up > move_down and move_up > 0 else Decimal("0")
                      minus_dm  = move_down if move_down > move_up and move_down > 0 else Decimal("0")
                      TR = max(H - L, abs(H - prev_close), abs(L - prev_close))
                      plus_dm_list.append(plus_dm)
                      minus_dm_list.append(minus_dm)
                      tr_list.append(TR)
                      prev_high, prev_low, prev_close = H, L, C

                  # Wilder smoothing — initialize
                  tr_s    = sum(tr_list[:N])
                  pdm_s   = sum(plus_dm_list[:N])
                  mdm_s   = sum(minus_dm_list[:N])

                  dx_list = []
                  for i in range(N, len(tr_list)):
                      tr_s    = tr_s    - (tr_s   / N) + tr_list[i]
                      pdm_s   = pdm_s   - (pdm_s  / N) + plus_dm_list[i]
                      mdm_s   = mdm_s   - (mdm_s  / N) + minus_dm_list[i]
                      pdi = (pdm_s / tr_s * 100) if tr_s != 0 else Decimal("0")
                      mdi = (mdm_s / tr_s * 100) if tr_s != 0 else Decimal("0")
                      dx = (abs(pdi - mdi) / (pdi + mdi) * 100
                            if (pdi + mdi) != 0 else Decimal("0"))
                      dx_list.append(dx)

                  # ADX = Wilder smoothed DX
                  if len(dx_list) < N:
                      return None
                  adx = sum(dx_list[:N]) / N
                  for dx in dx_list[N:]:
                      adx = adx - (adx / N) + dx / N
                  return adx  # Final ADX value for this pair

------------------------------------------------------------
6.3 EMA(20) and EMA(50) on daily closes
------------------------------------------------------------

RE-IND-007  Directional regime uses daily EMA(20) and EMA(50):

              def compute_ema(closes, period):
                  """EMA on list of Decimal close values."""
                  if len(closes) < period:
                      return None
                  alpha = Decimal("2") / (period + 1)
                  # Warm-up: simple average of first N periods
                  ema = sum(closes[:period]) / period
                  for close in closes[period:]:
                      ema = alpha * close + (1 - alpha) * ema
                  return ema

              closes = [candle.close for candle in committed_candles]
              ema_20 = compute_ema(closes, 20)
              ema_50 = compute_ema(closes, 50)

RE-IND-008  Directional regime classification:
              if adx_14 > adx_threshold:  # 25 CIATS-owned
                  if ema_20 > ema_50:
                      directional = TRENDING_POSITIVE
                  else:
                      directional = TRENDING_NEGATIVE
              else:
                  directional = NON_DIRECTIONAL

7. SCHEDULING AND RATE LIMITING
============================================================

RE-SCH-001  Runs once daily at 00:00 UTC for ALL pairs.
            Implemented as asyncio.Task with asyncio.sleep
            until next midnight. Persistent task.

RE-SCH-002  Must complete before first 5m candle close
            of the new day (~00:05 UTC worst case).
            With 50 pairs x 1.1s stagger = 55 seconds.
            Completion by ~00:01 UTC. No risk of race.

RE-SCH-003  On regime computation failure: use stale
            regime from prior computation. Log
            REGIME_STALE_WARNING. Alert if stale > 24h.
            Never halt TothBot on regime failure.

RE-RL-001   CRITICAL: Kraken REST GetOHLCData rate limit
            is 1 call/second per pair. MUST stagger.

RE-RL-002   MANDATORY stagger pattern:
              for pair in trading_universe:
                  data = await get_ohlcdata(pair, interval=1440)
                  compute_and_cache_regime(pair, data)
                  await asyncio.sleep(1.1)

RE-RL-003   NEVER use asyncio.gather() for regime OHLC calls.
            asyncio.gather() parallelizes calls — all hit
            Kraken at the same time → rate limit rejection.
            50 pairs x 1.1s = 55s sequential. Acceptable.

RE-RL-004   On HTTP 429: backoff 2s, 4s, 8s. Max 3 retries.
            If all fail: log WARMUP_REST_FAILED. Use stale.

8. REGIME CACHE AND TAGGING
============================================================

RE-TAX-001  Six regimes, each is a combination of
            directional + volatility:
              TRENDING_POSITIVE + NORMAL_VOL
              TRENDING_POSITIVE + ELEVATED_VOL
              TRENDING_NEGATIVE + NORMAL_VOL
              TRENDING_NEGATIVE + ELEVATED_VOL
              NON_DIRECTIONAL + NORMAL_VOL
              NON_DIRECTIONAL + ELEVATED_VOL

RE-TAX-002  regime_cache structure:
              from dataclasses import dataclass

              @dataclass
              class RegimeState:
                  directional:  str   # TRENDING_POS/NEG/NON_DIR
                  vol_regime:   str   # NORMAL_VOL/ELEVATED_VOL
                  adx_14:       Decimal
                  ema_20:       Decimal
                  ema_50:       Decimal
                  atr_daily:    Decimal
                  atr_pct_rank: Decimal
                  computed_at:  str   # ISO 8601 UTC

              regime_cache: dict[str, RegimeState] = {}
              # Keys: pair symbols e.g. "BTC/USD", "ETH/USD"

RE-TAX-003  Gate 3 (Regime Pre-Filter) reads regime_cache:
              state = regime_cache.get(symbol)
              if state is None:
                  return BLOCK  # No regime data
              if state.directional == TRENDING_NEGATIVE:
                  return STOP   # No entry
              if (state.directional == NON_DIRECTIONAL
                  and state.vol_regime == ELEVATED_VOL):
                  return STOP   # No entry

RE-TAG-001  TWO regime tags on every trade:
            asset_regime:  regime_cache[symbol]
            market_regime: regime_cache["BTC/USD"]
            Both written to Position Mirror at entry.
            Both written to TRADE_CLOSE Logger record.

RE-TAG-002  BTC/USD ALWAYS in trading universe.
            Computed daily alongside all other pairs.
            market_regime serves as systemic risk proxy.

RE-STL-001  Stale regime: use prior RegimeState if fresh
            computation fails. Log REGIME_STALE_WARNING.
            computed_at timestamp used to detect staleness.

RE-STL-002  Never halt TothBot on stale regime.
            If stale > 24h: alert operator HIGH.
            If regime_cache[symbol] is None:
              Gate 3 returns STOP (no entry permitted).

RE-STL-003  On successful computation, write:
              regime_cache[symbol] = RegimeState(
                  directional=..., vol_regime=...,
                  adx_14=..., ema_20=..., ema_50=...,
                  atr_daily=..., atr_pct_rank=...,
                  computed_at=datetime.now(timezone.utc).isoformat()
              )
            Log REGIME_COMPUTED with all field values.

9. ADX CONVERGENCE — CONFIRMED ADEQUATE
============================================================

RE-FPD-001  ADX(14): 28 candle minimum for first valid value.
            EMA(20): 20 minimum. ATR(14): 14 minimum.
            Overall minimum: 28 committed candles.

RE-FPD-002  Available committed candles: 719 (from 720 returned).
            691+ candles beyond minimum. Data confirmed sufficient.

RE-FPD-003  ATR percentile: 30 candle minimum for stability.
            With 719 candles: confirmed adequate.

RE-FPD-004  Full ADX convergence accuracy: 2xN+100 = 128 candles.
            Available: 719 candles = 5.6x the convergence requirement.
            TothBot uses batch computation on all 719 candles.
            Full convergence guaranteed.

RE-FPD-005  Regime Engine computes ADX in BATCH on the full
            719-candle history. NOT incrementally. Wilder
            smoothing recursion runs on all available data
            every day at 00:00 UTC.

RE-FPD-006  TWO ATR computations in TothBot — DISTINCT:
            (1) Regime Engine: daily ATR from 1440-interval candles
                (batch, 719 candles, for volatility regime)
            (2) Pipeline: 5-min ATR from incremental candle events
                (running, 14-candle warm-up, for MAE/emergSL)
            These are different computations for different purposes.
            Never confuse them. Single source of truth per type.
