============================================================
1. PURPOSE
============================================================

This document is the complete, unambiguous coding contract
for TothBot V2 VPS deployment, process management,
watchdog, and log management. Code and configuration are
derived from this document and no other.

Process reliability is not optional. A crashed and
unmonitored TothBot with open positions is a direct loss
event. This document eliminates that risk.

3. FIVE CODING-READINESS QUESTIONS
============================================================

(1) What does this component DO?
    Specifies all VPS infrastructure configuration,
    process management, watchdog, API key storage,
    log rotation, and startup validation for 24/7
    TothBot V2 operation on Hetzner VPS.

(2) Interfaces?
    systemd ↔ TothBot process (start/stop/restart/watchdog)
    logrotate ↔ Logger file handler (file rotation)
    .tothbot.env ↔ TothBot startup (API keys)
    Kraken Status API ↔ startup validation (HTTP GET)
    sdnotify ↔ systemd (READY, WATCHDOG signals)
    alert@tothbot.com ↔ SMTP (maintenance alerts)

(3) Hard rules?
    LimitNOFILE=65535 — mandatory in service unit.
    WatchdogSec=120 — mandatory in service unit.
    30-second watchdog ping loop — mandatory in code.
    API keys in .tothbot.env ONLY — never in code or logs.
    Both API keys IP-whitelisted to VPS IP — mandatory.
    logrotate configured BEFORE first live run.
    IP whitelist updated BEFORE any VPS migration.
    Kraken Status API checked at startup — non-blocking.
    sd_notify READY=1 sent ONLY after all startup steps pass.

(4) What triggers it?
    System boot (WantedBy=multi-user.target).
    Process crash (Restart=on-failure, RestartSec=5).
    Watchdog timeout (WatchdogSec=120, systemd restart).
    Manual: systemctl start/stop/restart tothbot.

(5) What does it log?
    VPS_STARTUP_BEGIN, VPS_STARTUP_COMPLETE (INFO)
    KRAKEN_MAINTENANCE_SCHEDULED (CRITICAL if <2hrs)
    KRAKEN_STATUS_CLEAN (INFO if no maintenance)
    KRAKEN_STATUS_CHECK_FAILED (INFO if API unreachable)
    SYSTEMD_WATCHDOG_PING (DEBUG every 30s)
    VPS_SHUTDOWN_INITIATED (INFO)

6. SYSTEMD SERVICE UNIT
============================================================

VD-SYS-001  TothBot MUST run as a systemd service.
            Unit file: /etc/systemd/system/tothbot.service

VD-SYS-002  Service unit content:

              [Unit]
              Description=TothBot V2 Trading System
              After=network-online.target
              Wants=network-online.target

              [Service]
              Type=notify
              User=root
              WorkingDirectory=/root/TothBot_V2-Code
              EnvironmentFile=/root/.tothbot.env
              ExecStart=/root/tothbot_env/bin/python3 \
                        -m tothbot
              Restart=on-failure
              RestartSec=5
              WatchdogSec=120
              LimitNOFILE=65535
              StandardOutput=journal
              StandardError=journal
              SyslogIdentifier=tothbot

              [Install]
              WantedBy=multi-user.target

VD-SYS-003  WatchdogSec=120: systemd detects frozen event
            loop after 120s and restarts TothBot. Prevents
            undetected frozen process with open positions.

VD-SYS-004  Type=notify: TothBot sends sd_notify READY=1
            after startup validation. Systemd knows when
            TothBot is actually ready — not just started.

VD-SYS-005  LimitNOFILE=65535: prevents EMFILE errors
            under high WS subscription load.

VD-SYS-006  Restart=on-failure + RestartSec=5: auto-restarts
            on crash after 5-second delay. Allows emergSL
            resting stop-market orders to protect positions
            if crash is sustained.

VD-SYS-007  Service installation commands:
              # Copy unit file to systemd
              cp tothbot.service /etc/systemd/system/
              # Reload systemd daemon
              systemctl daemon-reload
              # Enable auto-start on boot
              systemctl enable tothbot
              # Start service
              systemctl start tothbot
              # Verify status
              systemctl status tothbot

7. SYSTEMD WATCHDOG IMPLEMENTATION
============================================================

VD-WD-001   Separate asyncio.Task (watchdog_loop) runs 24/7.
            Started by TothBot main() after all startup
            validation passes.

VD-WD-002   Watchdog loop implementation:

              import sdnotify

              async def watchdog_loop():
                  """Sends systemd watchdog pings every 30s.
                  If event loop hangs, pings stop.
                  WatchdogSec=120 triggers systemd restart."""
                  notifier = sdnotify.SystemdNotifier()
                  while True:
                      notifier.notify("WATCHDOG=1")
                      logger.debug({
                          "ts": _ts(),
                          "event": "SYSTEMD_WATCHDOG_PING",
                          "level": "DEBUG",
                          "component": "LOGGER"
                      })
                      await asyncio.sleep(30)

VD-WD-003   If event loop hangs, watchdog_loop coroutine
            is not scheduled. Pings stop. After 120s,
            systemd restarts TothBot. emergSL resting orders
            protect open positions during restart interval.

VD-WD-004   READY notification after startup:
              notifier.notify("READY=1")
            Send ONLY after:
              (a) All WS channels subscribed
              (b) All pairs in READY state
              (c) Position Mirror reconciled
              (d) Kraken Status API check complete
              See 1011014 Startup_Sequence_Coding_Spec.

VD-WD-005   Watchdog task must be stored as a named instance
            variable and not allowed to be garbage collected:
              self.watchdog_task = asyncio.create_task(
                  self.watchdog_loop(),
                  name="watchdog"
              )

8. LOG ROTATION (logrotate)
============================================================

VD-LOG-001  logrotate MUST be configured before first
            live run. Required — not optional.

VD-LOG-002  Configuration file: /etc/logrotate.d/tothbot

              /root/TothBot_V2-Code/logs/tothbot.log {
                  daily
                  rotate 90
                  compress
                  delaycompress
                  missingok
                  notifempty
                  copytruncate
              }

VD-LOG-003  copytruncate: Logger's QueueListener writes to
            the same file descriptor continuously. copytruncate
            copies the current log to a backup, then truncates
            the original in place. Logger continues writing
            to the same fd without interruption.

VD-LOG-004  90-day retention: 90 daily files x ~16 MB/day
            = ~1.44 GB. Provides CIATS with full history.
            Logger's RotatingFileHandler (50 MB, 90 files)
            handles in-process rotation. logrotate handles
            OS-level archival and compression.

VD-LOG-005  Install logrotate and apply:
              apt install logrotate  # if not present
              # Create config:
              vi /etc/logrotate.d/tothbot
              # Test (dry run):
              logrotate -d /etc/logrotate.d/tothbot
              # Force rotation now:
              logrotate -f /etc/logrotate.d/tothbot

10. EMAIL ALERT CONFIGURATION
============================================================

VD-ALT-001  All alerts to alert@tothbot.com via SMTP.
            Credentials from EnvironmentFile.

VD-ALT-002  Async SMTP delivery. Never block hot path.
            Alert function is fire-and-forget:
              async def send_alert(level: str, message: str):
                  """Non-blocking SMTP alert. 5s timeout."""
                  try:
                      import aiosmtplib
                      async with aiosmtplib.SMTP(
                          hostname=os.environ["SMTP_HOST"],
                          port=int(os.environ["SMTP_PORT"]),
                          timeout=5
                      ) as smtp:
                          await smtp.login(
                              os.environ["SMTP_USER"],
                              os.environ["SMTP_PASS"]
                          )
                          msg = (
                              f"TothBot Alert [{level}]\n\n"
                              f"{message}"
                          )
                          await smtp.sendmail(
                              os.environ["ALERT_EMAIL_FROM"],
                              [os.environ["ALERT_EMAIL_TO"]],
                              msg
                          )
                  except Exception as e:
                      import sys
                      print(f"ALERT FAILED: {e}", file=sys.stderr)

VD-ALT-003  Rate limit: 1 alert per event type per 60s window.
            Prevents alert flooding on rapid repeated events:
              _alert_last_sent: dict[str, float] = {}

              def _should_alert(event_type: str) -> bool:
                  import time
                  now = time.monotonic()
                  last = _alert_last_sent.get(event_type, 0)
                  if now - last >= 60:
                      _alert_last_sent[event_type] = now
                      return True
                  return False

VD-ALT-004  Add aiosmtplib to requirements.txt (pinned).

11. KRAKEN STATUS API STARTUP CHECK
============================================================

VD-STAT-001  Query Kraken Status API during startup,
             before entering main event loop.

             Endpoint (public, no auth required):
               GET https://status.kraken.com/api/v2/
                   scheduled-maintenances/upcoming.json

VD-STAT-002  Implementation:

               async def check_upcoming_maintenance(
                       session: aiohttp.ClientSession
               ) -> None:
                   url = (
                       "https://status.kraken.com/api/v2/"
                       "scheduled-maintenances/upcoming.json"
                   )
                   try:
                       async with session.get(
                           url,
                           timeout=aiohttp.ClientTimeout(total=10)
                       ) as resp:
                           data = await resp.json(
                               loads=orjson.loads)
                       maintenances = data.get(
                           "scheduled_maintenances", [])
                       now = datetime.now(timezone.utc)
                       warn_threshold = now + timedelta(hours=2)
                       clean = True
                       for m in maintenances:
                           start_str = m.get("scheduled_for", "")
                           if not start_str:
                               continue
                           start_time = datetime.fromisoformat(
                               start_str.replace("Z", "+00:00"))
                           if start_time <= warn_threshold:
                               clean = False
                               _log("KRAKEN_MAINTENANCE_SCHEDULED",
                                    "CRITICAL",
                                    within_hours=round(
                                        (start_time - now
                                        ).total_seconds() / 3600,
                                        1),
                                    description=m.get("name", ""))
                               await send_alert(
                                   "CRITICAL",
                                   f"Kraken maintenance in "
                                   f"<2 hrs: {m.get('name','')}"
                                   f" at {start_time} UTC"
                               )
                       if clean:
                           _log("KRAKEN_STATUS_CLEAN", "INFO")
                   except Exception as e:
                       _log("KRAKEN_STATUS_CHECK_FAILED",
                            "INFO", error=str(e))
                   # Always continue startup regardless of result

VD-STAT-003  Behavior rules:
             (a) Maintenance within 2 hours: CRITICAL + email.
             (b) No maintenance within 2 hours: INFO log only.
             (c) API unreachable: INFO log only.
             In all cases: startup continues. Never blocking.

    (a) Check journalctl -u tothbot --since "10 min ago"
    (b) Verify no FULL_HALT_TRIGGERED
    (c) Verify Position Mirror reconciled correctly
    (d) Verify all pairs in READY state
    (e) Verify no positions closed during restart gap
        (check GAP_CLOSED_POSITION in logs)
