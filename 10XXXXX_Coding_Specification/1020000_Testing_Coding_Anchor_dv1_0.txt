3. TESTING PHILOSOPHY
============================================================

3.1 Testing verifies that code matches specification.
A test suite is complete when every rule, constraint,
and behavior defined in the corresponding AA=10 coding
spec has a test that confirms correct implementation.

3.2 Testing scope excludes market validation.
Testing verifies code correctness, not trading strategy
profitability. Strategy validation is paper trading (Phase
10). Code correctness is unit and integration testing
(Phase 9).

3.3 Tests are deterministic.
Every test produces a pass or fail with no ambiguity.
Test outcomes do not depend on live market data.
Kraken WS and REST responses are mocked in all unit and
integration tests.

3.4 Testing is mandatory before paper trading.
No TothBot V2 code is deployed to live paper trading
without passing all unit tests and integration tests.
This is a hard gate per 0311002.

============================================================
5. TESTING SEQUENCE
============================================================

  Phase 9 (Code Development):
    Unit tests written alongside each module.
    Module is not complete until its unit tests pass.

  Phase 9 completion gate:
    All unit tests pass. 100% of coding spec rules covered.

  Phase 10 (Integration Testing):
    Integration test suite executed.
    Full pipeline from WS event to order dispatch mocked.
    All integration tests pass before paper trading.

  Phase 11 (Paper Trading):
    Paper trading per 1021003 Paper_Trading_Test_Spec.
    Minimum 200 closed trades before live capital.
    CIATS activates at 200 closed trades.
    Per-regime analysis valid at 600 closed trades.
