============================================================
STARTUP SEQUENCE CODING SPECIFICATION
============================================================

============================================================
1. PURPOSE
============================================================

This document specifies:
  Section 1 — The complete 10-step startup sequence for
               TothBot V2. No pipeline evaluation is
               permitted until at least one pair reaches
               READY state.
  Section 2 — The 11-step mid-session WS reconnect sequence.
               Distinct from startup. Preserves all baseline
               state. No pipeline evaluation during reconnect.

2. PARENT CHAIN
============================================================

  Parent specification: 0500000 System_Architecture_Overview

Governing ARs: AR-049 (startup), AR-056 (reconnect)

3. GOVERNING ARCHITECTURAL REQUIREMENTS
============================================================

All of the following ARs must be satisfied before READY:
  AR-003  Restart reconciliation: snap_orders preferred
  AR-004  Two API key pairs (DATA + TRADE)
  AR-017  Regime Engine GetOHLCData at startup
  AR-020  Per-pair instrument status cache populated
  AR-025  aiohttp, asyncio TaskManager, systemd watchdog
  AR-029  WS connect max_size=10MB + open_timeout=10
  AR-031  Subscription ACK warnings[] parsed
  AR-034  Ticker event_trigger per position state
  AR-035  aiohttp ClientSession timeout + connector config
  AR-036  GetOHLCData stagger 1.1s between pairs
  AR-037  API keys IP-whitelisted to VPS
  AR-038  Kraken Status API check at startup
  AR-044  ATR(14) and EMA warm-up via GetOHLCData
  AR-045  OHLC candle-close detection initialization
  AR-046  emergSL triggers.reference explicit
  AR-047  Price and quantity rounding initialized
  AR-048  Exit Controller bid price for MAE
  AR-055  DMS (cancel_all_orders_after) PROHIBITED
  AR-058  max_queue=None on all WS connections
  AR-059  ping_interval=None — disable library TCP ping
  AR-060  Use websockets.asyncio.client import connect

============================================================
4. PAIR STATES
============================================================

  WARM_UP   ATR or EMA cache not yet seeded. No entries
            permitted. Gates 4 and 8 block. Pair exits
            WARM_UP after seed + first candle-close event.

  READY     All caches seeded. Pair eligible for pipeline
            evaluation. Gates 4 and 8 can operate.

  BLOCKED   Pair excluded by instrument status check.
            reduce_only / work_in_progress / delisted /
            limit_only / cancel_only / maintenance.

  WARM_UP is the initial state for ALL pairs on startup.
  Transition to READY is defined in Section 7.

============================================================
5. PRE-CONDITIONS FOR STARTUP
============================================================

SS-PRE-002  API key pair DATA: valid, IP-whitelisted.
            API key pair TRADE: valid, IP-whitelisted.
SS-PRE-003  systemd service configured with:
            WatchdogSec=120, Type=notify.

============================================================
6. SECTION 1 — STARTUP SEQUENCE (10 STEPS)
============================================================

Steps execute in this order. No step is skipped.
Each step must complete successfully before proceeding
to the next (unless explicitly noted as non-blocking).

------------------------------------------------------------
STEP 1 — Kraken Status API Check (AR-038)
------------------------------------------------------------

SS-STARTUP-001  Query:
  GET https://status.kraken.com/api/v2/
      scheduled-maintenances/upcoming.json
  No authentication required.
  aiohttp ClientSession. ClientTimeout applies.

SS-STARTUP-002  If scheduled maintenance within 2 hours:
  Log: KRAKEN_MAINTENANCE_SCHEDULED (CRITICAL)
  Alert: alerts@tothbot.com with maintenance details. (OI-019)
  Action: Non-blocking. Continue startup.

SS-STARTUP-003  If request fails:
  Log: STATUS_API_UNAVAILABLE (INFO)
  Action: Non-blocking. Continue startup.

------------------------------------------------------------
STEP 2 — Acquire WebSocket Token (AR-004)
------------------------------------------------------------

SS-STARTUP-004  Call GetWebSocketsToken (REST, TRADE key).
  Token valid 15 minutes from creation.

SS-STARTUP-005  On failure: retry up to 3 times with 2s
  delay. If all fail: log FATAL_TOKEN_ACQUISITION_FAILED
  (CRITICAL), halt startup.

------------------------------------------------------------
STEP 3 — Connect Public WS and Subscribe (AR-029)
------------------------------------------------------------

SS-STARTUP-006  Connect: wss://ws.kraken.com/v2

  ★ MANDATORY (AR-058, AR-059, AR-060):
    from websockets.asyncio.client import connect

    conn = await connect(
        "wss://ws.kraken.com/v2",
        max_size=10 * 1024 * 1024,
        open_timeout=10,
        max_queue=None,
        ping_interval=None,
    )

  NOT the deprecated API:
    websockets.connect()  ← DEPRECATED, DO NOT USE

SS-STARTUP-007  Subscribe (single message, all channels):
  - instrument (snapshot=true)
  - status (snapshot=true)
  - ohlc (interval=5, snapshot=true, all monitored pairs)
  NOTE: Do NOT subscribe ohlc interval=60 via WS.
  Kraken WS v2 rejects a second ohlc interval subscription
  with "Already subscribed to one ohlc interval on this
  symbol." OI-NEW-001 confirmed. 1H HTF cache (htf_ema_20,
  htf_ema_50) is sourced from REST only (SS-WARMUP-003).
  NOTE: Do NOT subscribe ticker yet. Managed in Step 7.

SS-STARTUP-008  Parse all subscription ACK warnings[].
  Log any non-empty warnings (AR-031).

SS-STARTUP-009  Start ping task (30s interval — JSON ping,
  not library TCP ping). Start zombie detection task
  (90s threshold). Only real channel events reset timer.

------------------------------------------------------------
STEP 4 — Process Instrument Snapshot (AR-020)
------------------------------------------------------------

SS-STARTUP-010  Wait for instrument snapshot message.
  Timeout: 10 seconds. On timeout: reconnect + retry.

SS-STARTUP-011  For each pair in snapshot:
  Populate per-pair instrument cache:
    price_increment: Decimal(str(pair["price_increment"]))
    qty_increment:   Decimal(str(pair["qty_increment"]))
    qty_min:         Decimal(str(pair["qty_min"]))
    cost_min:        Decimal(str(pair["cost_min"]))
    status:          str
  Use price_increment (NOT deprecated tick_size). AR-028.
  All values converted to Decimal(str()) immediately.

SS-STARTUP-012  Set pair state:
  online / post_only → WARM_UP (eligible for seeding)
  All other statuses → BLOCKED

------------------------------------------------------------
STEP 5 — Connect Private WS and Subscribe (AR-003)
------------------------------------------------------------

SS-STARTUP-013  Connect: wss://ws-auth.kraken.com/v2

  ★ MANDATORY (AR-058, AR-059, AR-060):
    conn = await connect(
        "wss://ws-auth.kraken.com/v2",
        max_size=10 * 1024 * 1024,
        open_timeout=10,
        max_queue=None,
        ping_interval=None,
    )

SS-STARTUP-014  Subscribe executions:
  {
    "method": "subscribe",
    "params": {
      "channel": "executions",
      "token": <token>,
      "snap_orders": true,
      "snap_trades": true,
      "order_status": true,
      "ratecounter": true
    }
  }
  Extract maxratecount from ACK (AR-019).
  Parse ACK warnings[] and log.

SS-STARTUP-015  Subscribe balances:
  {
    "method": "subscribe",
    "params": {
      "channel": "balances",
      "token": <token>,
      "snapshot": true
    }
  }
  Parse initial snapshot: use wallets[type=spot][id=main].
  Set portfolio_baseline_USD = spot_usd_balance. AR-050.
  This is set ONCE here. Never reset during live operation.

SS-STARTUP-016  Start ping task on private WS connection.
  Start zombie detection on private WS connection.

------------------------------------------------------------
STEP 6 — Reconcile Open Positions (AR-003)
------------------------------------------------------------

SS-STARTUP-017  Process snap_orders snapshot from
  executions channel. Identify all open orders.

SS-STARTUP-018  Restore Position Mirror from snapshot:
  For each open position found:
    symbol, entry_fill_price (avg_price), qty,
    TP order_id, emergSL order_id, cl_ord_id
  If position has TP but no emergSL (or vice versa):
    Log INCOMPLETE_PROTECTION (CRITICAL). Alert operator.
    Do NOT auto-repair without operator confirmation.

SS-STARTUP-019  On reconciliation gap (executions seq gap):
  Fall back to REST GetOpenOrders. AR-021.
  GetAccountBalance for balance check.

------------------------------------------------------------
STEP 7 — Restore Ticker for Open Positions (AR-034)
------------------------------------------------------------

SS-STARTUP-020  For each pair with open position in
  Position Mirror:
  Subscribe ticker with event_trigger:bbo.
  Activates real-time MAE monitoring (bid price).

SS-STARTUP-021  For all other monitored pairs:
  Subscribe ticker with event_trigger:trades.
  Provides data for Gate 2 (24h volume) and
  pre-computation cache.

------------------------------------------------------------
STEP 8 — REST Warm-Up: GetOHLCData (AR-044)
------------------------------------------------------------

SS-WARMUP-001  REST warm-up is triggered from within
  _subscribe_ohlc_channels() immediately after the ohlc(5)
  subscription message is sent:
    asyncio.create_task(_warm_up_all_pairs())
  This fires concurrently with the running WS receive loop.
  Pairs remain in WARM_UP state until seeding completes.
  The pipeline gate (WARMUP_READY check) blocks any pair
  that has not yet completed seeding.

  Paper mode: identical warm-up path. No difference.
  The same _warm_up_all_pairs() call executes in both live
  and paper mode. Private WS absence does not affect
  REST warm-up.

  For all WARM_UP pairs, execute 2 GetOHLCData calls
  per pair (interval=5 and interval=60). Use
  asyncio.gather() to parallelize ACROSS pairs. Stagger
  1.1s WITHIN the same pair (Call A → sleep(1.1) → Call B).

SS-WARMUP-002  Per pair — Call A: interval=5 (ATR seed)
  GetOHLCData(pair, interval=5)
  Use response[:-1] (exclude uncommitted candle).
  Take last 14+ committed candles. All values: Decimal(str()).
  ATR seed (Wilder's method):
    prev_close = ohlc[-15].close
    TR = [max(h-l, |h-prev_c|, |l-prev_c|) for each candle]
    ATR_seed = sum(TR[-14:]) / 14

SS-WARMUP-003  Per pair — Call B: interval=60 (HTF EMA seed)
  GetOHLCData(pair, interval=60)
  1.1s AFTER Call A for the same pair.
  Use response[:-1]. Take last 100+ candles.
  All values: Decimal(str()).
  EMA(20) seed: SMA of first 20 closes, then forward compute
    alpha_20 = 2/21
    EMA_n = alpha_20 * close_n + (1-alpha_20) * EMA_n-1
  EMA(50) seed: SMA of first 50 closes, then forward compute
    alpha_50 = 2/51
  Store current EMA(20) and EMA(50) in 1H HTF cache.
  NOTE: No WS ohlc(60) subscription. This REST call is the
  sole source of 1H HTF data. htf_ema_20 and htf_ema_50
  are seeded here and updated incrementally on each 60m
  WS REST-derived candle via _update_htf_ema when
  _process_ohlc_60m fires — but ohlc(60) WS subscription
  is absent (OI-NEW-001). HTF EMAs are static after startup
  seed in this session. This is acceptable: EMAs change
  slowly (100+ candle lookback). CIATS will evaluate.
  Call C (interval=1440 regime) is not part of per-pair
  warm-up. Regime Engine runs independently at startup
  and at 00:00 UTC via daily refresh.

SS-WARMUP-004  On rate limit (HTTP 429) for any call:
  Backoff: 2s, 4s, 8s. Max 3 retries.
  ATR/EMA failure: pair stays WARM_UP (seeds via WS events).
  Log WARMUP_REST_FAILED for affected pair.

SS-WARMUP-005  Stagger enforcement:
  asyncio.sleep(1.1) between Call A→B for pair X.
  Calls for pair Y run concurrently with pair X.

SS-WARMUP-006  OHLC interval_begin initialization (AR-045):
  After Call A: last_interval_begin[pair] = response[-2].interval_begin
  After Call B: last_interval_begin_60[pair] = response[-2].interval_begin
  WS OHLC messages compared against these to detect candle-close.
  NOTE: last_interval_begin_60 is initialized here from REST even
  though no WS ohlc(60) subscription exists. Preserved for
  compatibility if WS 60m subscription is restored in future.

SS-WARMUP-007  Pair transitions WARM_UP → READY when:
  (a) ATR(14) seeded
  (b) EMA(20) and EMA(50) seeded
  (c) Regime available
  System does NOT wait for all pairs. READY pairs start
  trading immediately. WARM_UP pairs seed organically.

SS-WARMUP-008  After all asyncio.gather() tasks complete,
  _warm_up_all_pairs() logs SYSTEM_OPERATIONAL with
  ready_pairs count if at least one pair is READY.
  Pairs that failed (HTTP 429 exhausted or exception) remain
  in WARM_UP and seed organically from WS candle events.

------------------------------------------------------------
STEP 9 — At Least One READY Pair: Begin Pipeline
------------------------------------------------------------

SS-STARTUP-022  System enters OPERATIONAL state when
  at least one pair is in READY state.
  Log: SYSTEM_OPERATIONAL.

SS-STARTUP-023  WARM_UP pairs continue seeding via
  WS candle events. Enter READY organically.

SS-STARTUP-024  BLOCKED pairs re-evaluated on each
  instrument channel update. Status change to online/
  post_only → transition to WARM_UP.

SS-STARTUP-025  Pipeline is per-symbol. READY pairs
  proceed through full 8-gate pipeline.
  WARM_UP pairs skipped at per-pair status check (pre-Gate 1).

SS-STARTUP-026  Send sd_notify READY=1 to systemd.
  Log: VPS_STARTUP_COMPLETE.

------------------------------------------------------------
STEP 10 — Continuous Operation
------------------------------------------------------------

SS-STARTUP-027  At 00:00 UTC: Regime Engine re-runs
  GetOHLCData(interval=1440) for all pairs. 1.1s stagger.
  Refreshes daily regime classification.

SS-STARTUP-028  systemd watchdog: asyncio task sends
  sd_notify WATCHDOG=1 every 30 seconds.
  If event loop freezes → systemd restarts TothBot.
  On restart: full startup sequence from Step 1.

6A. PAPER MODE STARTUP BEHAVIOR (SS-PAPER) — NEW dv1_8
============================================================

This section specifies how the startup_sequence module
behaves in paper mode. Per TB00000 v2_20 §4.4 PA-001..010
PAPER-AS-MASTER and 0500000 dv1_24 §12 Paper-Mode Dispatch
Boundary Architecture, paper trading is the empirically-
validated master configuration; live trading is built to
MIMIC paper. Outside the four PA-004 divergence points
(private WS connection; order dispatch; capital ledger;
Position Mirror sourcing), paper and live operation MUST
be byte-identical (PA-005).

The Startup Sequence sits at the WIRE-UP layer of the
TothBot V2 architecture per 0500000 dv1_24 §12.8. It is
the FIRST consumer of the paper_trading_mode flag and the
sole module responsible for propagating the flag to
WSManager.__init__ as the FIRST consumer per 0500000
dv1_24 §12.2 LIFECYCLE. Startup Sequence does NOT make
mode-conditional behavioral decisions of its own. Apart
from the explicit Step 5 private-WS-connect gate
(SS-PAPER-002) and the Step 5 portfolio-baseline-source
divergence (SS-PAPER-003) and the Step 6 snap_orders
handling divergence (SS-PAPER-004), every startup step
executes byte-identically in paper and live (SS-PAPER-007
+ PA-005).

------------------------------------------------------------
6A.1 Architectural Principle
------------------------------------------------------------

SS-PAPER-001  paper_trading_mode FLAG READ-ONCE AT STARTUP
              + WSManager INJECTION (PA-004 #2 cascade).

           startup_sequence is the FIRST consumer of the
           paper_trading_mode flag per 0500000 dv1_24
           §12.2 LIFECYCLE. The flag is read EXACTLY ONCE
           at process boot from the configuration dict
           loaded from EnvironmentFile /root/.tothbot.env
           and injected into WSManager.__init__ as a
           constructor argument. WSManager stores the
           value as self.paper_mode (HR-WM-021). The flag
           is NEVER re-read by startup_sequence after
           process boot. The flag is NEVER mutated during
           operation. The flag is NEVER cached anywhere
           else in startup_sequence.

           Required implementation in _load_config():
             config["paper_trading_mode"] = (
                 os.environ.get(
                     "PAPER_TRADING_MODE", "false"
                 ).lower() == "true"
             )

           Required injection in _create_ws_manager():
             ws_manager = WSManager(
                 paper_mode=config["paper_trading_mode"],
                 ...
             )

           Default semantics: if PAPER_TRADING_MODE is
           absent from the environment, the flag
           resolves to False (live mode) per 0500000
           dv1_24 §12.2 CANONICAL VALUE.

           Per 0500000 dv1_24 §12.2: "Authoring: Bill
           manually sets the flag in the EnvironmentFile
           /root/.tothbot.env BEFORE invoking systemctl
           start. Read: startup_sequence loads the config
           dict at process boot. paper_trading_mode is
           extracted and passed to WSManager.__init__ as
           the first consumer."

SS-PAPER-002  STEP 5 PRIVATE WS CONNECTION GATE
              (PA-004 #1 PRIMARY DIVERGENCE).

           Step 5 (Connect Private WS and Subscribe;
           SS-STARTUP-013 through SS-STARTUP-016) is the
           PRIMARY paper-vs-live divergence point in the
           Startup Sequence. The full Step 5 block —
           private WS connect, executions subscribe,
           balances subscribe, ping task, zombie
           detection task — MUST gate on
           config["paper_trading_mode"] and execute
           ONLY when paper_trading_mode is False.

             PAPER MODE (paper_trading_mode == True):
               Step 5 is SKIPPED in full.
               WSManager.connect_private() is NEVER
               called. self._ws_private remains None
               for the entire session lifetime.
               No executions subscription. No balances
               subscription. No private-WS ping or
               zombie detection task started.

             LIVE MODE (paper_trading_mode == False):
               Step 5 executes per SS-STARTUP-013
               through SS-STARTUP-016.

           Required implementation pattern at the
           Step 5 entry point in startup_sequence:

             if not config["paper_trading_mode"]:
                 await _connect_private_ws_and_subscribe(
                     ws_manager, token, ...
                 )
             else:
                 # PA-004 #1 — paper does NOT connect
                 # private WS. self._ws_private stays
                 # None for session lifetime.
                 logger.info(
                     event="STEP_5_SKIPPED_PAPER",
                     reason="PA-004 #1 paper canonical "
                            "configuration: no private "
                            "WS connection",
                 )

           Per TB00000 v2_20 §4.4 PA-004 (1) and 0500000
           dv1_24 §12.1 DIVERGENCE POINT (1): "PAPER:
           Does NOT connect to Kraken private WS.
           self._ws_private remains None for the entire
           session lifetime. ... Why: Paper places no
           real orders. An authenticated session in
           paper mode would create an outbound Kraken-
           facing connection that exists for no
           operational purpose and was never validated
           in TB00141..144 testing."

           Bind: HR-WM-022 (0511001 dv1_5); PT-MODE-003
           (0211005 dv1_3).

SS-PAPER-003  STEP 5 PORTFOLIO BASELINE SOURCE
              (PA-004 #3 DIVERGENCE).

           SS-STARTUP-015 sets portfolio_baseline_USD =
           spot_usd_balance from the balances channel
           snapshot. This live-mode action is REPLACED
           in paper mode by an equivalent assignment
           sourced from the synthetic ledger initialized
           by WSManager per 1011002 dv1_26 §16A.1
           WM-PAPER-LEDGER-001.

             PAPER MODE: spot_usd_balance is initialized
               by WSManager at construction time from
               config["paper_starting_balance"] (default
               $1,000 per Ratified Decision D-05).
               portfolio_baseline_USD = spot_usd_balance
               is set by WSManager in the same
               initialization step (per
               WM-PAPER-LEDGER-001). startup_sequence
               does NOT separately read or write
               portfolio_baseline_USD in paper mode —
               WSManager owns the synthetic ledger
               initialization end-to-end.

             LIVE MODE: SS-STARTUP-015 executes as
               specified. WSManager populates
               spot_usd_balance from the balances
               channel snapshot wallets[type=spot]
               [id=main]. portfolio_baseline_USD =
               spot_usd_balance is set ONCE here.

           Capital ledger formula and threshold values
           (drawdown_pct = (spot_usd_balance -
           portfolio_baseline_USD) / portfolio_baseline_
           USD; 5% session_pause; 10% full_halt) are
           BYTE-IDENTICAL between modes per PA-005.
           Only the SOURCE of spot_usd_balance differs.

           Per TB00000 v2_20 §4.4 PA-004 (3) and 0500000
           dv1_24 §12.1 DIVERGENCE POINT (3): "PAPER:
           Synthetic spot_usd_balance starting at
           paper_starting_balance ($1,000 per D-05).
           Updated by simulated-fill P&L applied locally
           using the SAME fee schedule (FEE_MAKER_PCT,
           FEE_TAKER_PCT) Kraken applies in live."

           Bind: HR-WM-011, HR-WM-032 (0511001 dv1_5);
           WM-PAPER-LEDGER-001 (1011002 dv1_26 §16A.1);
           PT-MODE-004 (0211005 dv1_3); D-05.

SS-PAPER-004  STEP 6 SNAP_ORDERS / POSITION MIRROR
              HANDLING (PA-004 #4 DIVERGENCE).

           Step 6 (Reconcile Open Positions;
           SS-STARTUP-017 through SS-STARTUP-019) is a
           live-only action chain. Paper mode does NOT
           reconcile snap_orders against the Position
           Mirror because there are no real Kraken
           orders to reconcile against; the paper
           Position Mirror is populated EXCLUSIVELY by
           the local simulated-fill path inside
           WSManager (HR-WM-033; PA-004 #4).

             PAPER MODE: Step 6 is SKIPPED in full.
               No snap_orders processing. No
               snap_trades processing. No Position
               Mirror restoration. No Pending Order
               Registry population from snap_orders.
               If a snap_orders or snap_trades message
               were ever received in paper mode (it is
               not, because paper does not subscribe
               executions per SS-PAPER-002), it would
               be logged at INFO level
               (SNAP_ORDERS_RECEIVED_PAPER /
               SNAP_TRADES_RECEIVED_PAPER) and
               otherwise discarded — NOT applied to
               Position Mirror. Paper Position Mirror
               on startup is EMPTY; positions accrue
               solely through subsequent local
               simulated-fill events.

             LIVE MODE: Step 6 executes per
               SS-STARTUP-017 through SS-STARTUP-019.
               snap_orders restores Position Mirror.
               snap_trades back-fills recent fills for
               CIATS Trade Outcome Bus reconciliation.
               Pending Order Registry populated for
               new and pending_new orders.

           Required implementation pattern at the
           Step 6 entry point in startup_sequence:

             if not config["paper_trading_mode"]:
                 await _reconcile_open_positions(
                     ws_manager, position_mirror, ...
                 )
             else:
                 # PA-004 #4 — paper Position Mirror
                 # populated EXCLUSIVELY by local
                 # simulated-fill path. No snap_orders
                 # reconciliation in paper.
                 logger.info(
                     event="STEP_6_SKIPPED_PAPER",
                     reason="PA-004 #4 paper Position "
                            "Mirror sourced from local "
                            "simulated-fill path only",
                 )

           Per TB00000 v2_20 §4.4 PA-004 (4) and 0500000
           dv1_24 §12.1 DIVERGENCE POINT (4): "PAPER:
           Populated EXCLUSIVELY by the local simulated-
           fill path (HR-WM-033). No external Kraken
           event source."

           Bind: HR-WM-033 (0511001 dv1_5); PM-PAPER-001
           through PM-PAPER-005 (0511005 dv1_1 §6A);
           PT-MODE-001 (0211005 dv1_3).

SS-PAPER-005  STARTUP TELEMETRY: FIRST LOGGER MESSAGE
              (PA-004 #2 cascade telemetry).

           The FIRST log record emitted by Logger after
           startup_sequence completes is
           PAPER_TRADING_MODE_ON or PAPER_TRADING_MODE_OFF,
           depending on the value of
           config["paper_trading_mode"]. This is a
           STARTUP-TIME-IMMUTABLE assertion that
           establishes the unambiguous mode-tag for
           every subsequent log record in the session.

             PAPER MODE: First log record is
               PAPER_TRADING_MODE_ON with payload
               documenting paper-canonical state
               (private_ws_connected: false,
               paper_baseline_source:
               "paper_starting_balance",
               paper_baseline_value: <configured value>,
               steps_executed: list of completed
               startup steps, step_5_status:
               "SKIPPED_PAPER_NO_PRIVATE_WS",
               step_6_status:
               "SKIPPED_PAPER_NO_SNAP_ORDERS").

             LIVE MODE: First log record is
               PAPER_TRADING_MODE_OFF with payload
               documenting live-canonical state
               (private_ws_connected: true,
               portfolio_baseline_source:
               "kraken_balances_snapshot",
               portfolio_baseline_value:
               <spot_usd_balance from snapshot>).

           This log record is emitted by
           startup_sequence after Step 9
           (SS-STARTUP-022 SYSTEM_OPERATIONAL emission)
           but BEFORE any pipeline evaluation begins.
           The mode-tag is therefore visible to all
           downstream consumers (CIATS Trade Outcome
           Bus paper_trade: bool field; alert routing;
           audit log analysis) from the first
           pipeline-relevant log record onward.

           Per 0500000 dv1_24 §12.2: "Logging: First
           message emitted by Logger after startup is
           PAPER_TRADING_MODE_ON or
           PAPER_TRADING_MODE_OFF. Every subsequent log
           record carries the implicit mode-tag of the
           running process."

           Bind: 0500000 dv1_24 §12.6 Paper Telemetry
           Event Taxonomy; PT-MODE-002 (0211005 dv1_3).

SS-PAPER-006  SECTION 2 RECONNECT — PAPER BINDING.

           Section 2 (Mid-Session WS Reconnect Sequence;
           SS-RECON-001 through SS-RECON-016) governs
           reconnect behavior on WS disconnect during
           live operation. The Section 2 step set
           includes both private-WS reconnect actions
           (R3 fresh token, R4 private WS connect, R5
           executions resub, R6 Position Mirror
           reconciliation, R7 balances resub) and
           public-WS reconnect actions (R8 public
           channels resub, R9 ticker restore, R10 cache
           staleness, R11 resume). Paper mode binding
           differs by step class:

             PAPER MODE — PRIVATE-WS RECONNECT STEPS
               SKIPPED. Steps R3, R4, R5, R6, R7 do
               NOT execute in paper. self._ws_private
               is None throughout the session
               lifetime per SS-PAPER-002, so there is
               no private WS connection to reconnect.
               Position Mirror reconciliation does
               NOT execute (per SS-PAPER-004). Paper
               reconnect flow consists ONLY of public-
               WS-related actions.

             PAPER MODE — PUBLIC-WS RECONNECT STEPS
               BYTE-IDENTICAL TO LIVE. Steps R1
               (close broken connection), R2 (wait /
               retry pacing), R8 (re-subscribe public
               channels — instrument, status, ohlc(5m)),
               R9 (restore ticker subscriptions per
               position state), R10 (cache staleness
               check + REST re-warm if gap > 15min),
               R11 (resume operations) execute byte-
               identically in paper and live per PA-005.

             PAPER MODE — RECONNECT INVARIANTS
               PRESERVED. SS-RECON-002 invariants
               (portfolio_baseline_USD never reset;
               drawdown_pct preserved; ATR/EMA caches
               preserved unless stale; system_state
               preserved; regime_cache preserved)
               apply IDENTICALLY in paper. The paper
               synthetic ledger spot_usd_balance is
               preserved across reconnect — the
               local-simulated-fill path is unaffected
               by WS disconnect because it operates on
               in-process state.

             LIVE MODE: All Section 2 steps R1 through
               R11 execute as specified.

           Required implementation pattern at the
           private-WS reconnect entry point in
           startup_sequence reconnect handler:

             if not config["paper_trading_mode"]:
                 await _reconnect_private_ws(...)
             else:
                 # PA-004 #1 — paper has no private
                 # WS to reconnect. Public-WS
                 # reconnect proceeds independently.
                 logger.info(
                     event="PRIVATE_WS_RECONNECT_"
                           "SKIPPED_PAPER",
                     reason="PA-004 #1 paper canonical "
                            "configuration",
                 )

           Bind: SS-RECON-001 through SS-RECON-016
           (Section 2); HR-WM-022 (0511001 dv1_5);
           PT-MODE-003 (0211005 dv1_3); PA-005 byte-
           identical.

SS-PAPER-007  PA-005 BYTE-IDENTICAL EVERYWHERE ELSE.

           All non-PA-004 startup steps execute BYTE-
           IDENTICALLY in paper and live. Mode-conditional
           branching outside the explicitly enumerated
           SS-PAPER-002 / SS-PAPER-003 / SS-PAPER-004
           gates is PROHIBITED. The complete enumeration
           of byte-identical startup steps:

             Step 1   Kraken Status API Check
                      (SS-STARTUP-001..003).
             Step 2   Acquire WebSocket Token
                      (SS-STARTUP-004..005).
                      NOTE: Token is acquired in BOTH
                      modes. In paper mode, the token
                      is acquired and discarded — no
                      private WS connection consumes
                      it. The token acquisition itself
                      is mode-agnostic and the REST
                      call cost is acceptable.
             Step 3   Connect Public WS and Subscribe
                      (SS-STARTUP-006..009). Public WS
                      is ALWAYS connected in both modes.
             Step 4   Process Instrument Snapshot
                      (SS-STARTUP-010..012).
             Step 7   Restore Ticker for Open Positions
                      (SS-STARTUP-020..021). In paper
                      mode, the open-position list is
                      EMPTY at startup (per
                      SS-PAPER-004) so all monitored
                      pairs subscribe ticker with
                      event_trigger:trades.
             Step 8   REST Warm-Up: GetOHLCData
                      (SS-WARMUP-001..008). Already
                      pre-existing paper-aware text in
                      SS-WARMUP-001 ("Paper mode:
                      identical warm-up path. No
                      difference.") — preserved by
                      SS-PAPER-007.
             Step 9   At Least One READY Pair: Begin
                      Pipeline (SS-STARTUP-022..026).
             Step 10  Continuous Operation
                      (SS-STARTUP-027..028).

           Pre-emit guard: any future startup-step
           amendment that introduces a mode-conditional
           branch outside the SS-PAPER-002 /
           SS-PAPER-003 / SS-PAPER-004 / SS-PAPER-006
           gates is a PA-005 violation per TB00000 v2_20
           §4.4 PA-005 + PA-006 (new divergence points
           require Bill written authorization).
           PA-008 self-catch ("PA-MASTER self-caught —
           redrafting") fires on detection.

           Per TB00000 v2_20 §4.4 PA-005: "Outside the
           four PA-004 divergence points, paper and
           live MUST be byte-identical."

7. SECTION 1 — ERROR HANDLING MATRIX
============================================================

  FAILURE                  ACTION
  ──────────────────────────────────────────────────────────
  Token failure            Retry 3x. FATAL halt if all fail.
  WS connect fail          Retry 5x. FATAL halt if all fail.
  Instrument timeout       Reconnect + resubscribe.
  snap_orders gap          Fall back REST GetOpenOrders.
  GetOHLCData 429          Backoff 3x. Pair stays WARM_UP.
  GetOHLCData fail         Log. Pair stays WARM_UP. Continue.
  Incomplete position      Log + Alert. No auto-repair.
  Status API fail          Log. Non-blocking. Continue.
  Private WS connect fail  Retry 5x. FATAL halt if all fail.

9. SECTION 2 — MID-SESSION WS RECONNECT (AR-056)
============================================================

------------------------------------------------------------
9.1 PURPOSE AND DISTINCTION FROM STARTUP
------------------------------------------------------------

SS-RECON-001  Mid-session reconnect is DISTINCT from startup.
              Do NOT execute Section 1 on a mid-session
              reconnect.

              TRIGGER: WS connection drops during live operation.
              WS Manager detects via asyncio exception or timeout.

              KEY DISTINCTIONS FROM STARTUP:
              (a) portfolio_baseline_USD: NEVER reset.
              (b) ATR/EMA caches: PRESERVED unless stale (>15min gap).
              (c) Positions may have closed during gap.
              (d) Pending Order Registry: reconcile.
              (e) system_state (halt/pause): PRESERVED.

SS-RECON-002  INVARIANTS — preserved across all reconnects:
                portfolio_baseline_USD:    NEVER reset
                drawdown_pct:              PRESERVED
                ATR cache per pair:        PRESERVED (unless stale)
                EMA cache per pair:        PRESERVED (unless stale)
                Position Mirror:           Updated by reconciliation
                system_state (halt/pause): PRESERVED
                regime_cache:              PRESERVED

------------------------------------------------------------
9.2 RECONNECT STEPS (11 STEPS)
------------------------------------------------------------

SS-RECON-003  STEP R1: Close broken connection.
              Close WS cleanly (suppress errors).
              Cancel all pending asyncio tasks for connection.
              Reset per-connection sequence numbers.
              Log WS_DISCONNECT_DETECTED with timestamp.

SS-RECON-004  STEP R2: Wait.
              Normal: retry instantly up to 5 attempts.
              After 5 failures or confirmed maintenance:
                Wait 5 seconds between attempts.

SS-RECON-005  STEP R3: Fetch fresh WebSocket token.
              Call GetWebSocketsToken (REST, TRADE key).
              Retry 3x with 2s delay.
              Failure: log FATAL_TOKEN_RECONNECT_FAILED.
              Systemd watchdog handles restart.

SS-RECON-006  STEP R4: Reconnect private WS.

  ★ MANDATORY (AR-058, AR-059, AR-060):
    conn = await connect(
        "wss://ws-auth.kraken.com/v2",
        max_size=10 * 1024 * 1024,
        open_timeout=10,
        max_queue=None,
        ping_interval=None,
    )

SS-RECON-007  STEP R5: Re-subscribe executions.
              {
                "method": "subscribe",
                "params": {
                  "channel": "executions",
                  "token": <fresh_token>,
                  "snap_orders": true,
                  "snap_trades": true,
                  "order_status": true,
                  "ratecounter": true
                }
              }
              Extract maxratecount from ACK.
              Parse ACK warnings[] and log.

SS-RECON-008  STEP R6: Position Mirror reconciliation.
              Compare pre-disconnect Position Mirror vs
              snap_orders from new subscription.

              For each symbol in Mirror but NOT in snap_orders:
                Position closed during gap (TP or emergSL fired).
                Find in snap_trades (last 50 fills).
                Fire CIATS Trade Outcome Bus with trade data.
                Remove from Position Mirror.
                Log POSITION_CLOSED_DURING_GAP (HIGH).

              For each order in snap_orders but NOT in Mirror:
                Alert operator only. Do not auto-trade.
                Log UNEXPECTED_ORDER_FOUND (HIGH).

              Pending Order Registry reconciliation:
                cl_ord_id in pending_orders but NOT in snap_orders:
                  Clear from registry.
                  Log PENDING_ORDER_LOST.
                cl_ord_id in pending_orders AND in snap_orders:
                  Keep in registry (order confirmed live).

SS-RECON-009  STEP R7: Re-subscribe balances.
              {
                "method": "subscribe",
                "params": {
                  "channel": "balances",
                  "token": <fresh_token>,
                  "snapshot": true
                }
              }
              Update spot_asset_balances from spot/main wallet.
              AR-050. Do NOT reset portfolio_baseline_USD.
              Log BALANCES_RESYNCED.

SS-RECON-010  STEP R8: Re-subscribe public channels.
              Re-subscribe: instrument, status, ohlc(5m), ohlc(60m).
              Update pair cache from new instrument snapshot.
              If pair status changed during gap: update state.
              Log PUBLIC_CHANNELS_RESUBSCRIBED.

SS-RECON-011  STEP R9: Restore ticker subscriptions.
              For each pair with open position in (updated) Mirror:
                Subscribe ticker with event_trigger:bbo.
              For all other monitored pairs:
                Subscribe ticker with event_trigger:trades.
              Log TICKER_RESTORED.

SS-RECON-012  STEP R10: Cache staleness check.
              gap_duration = reconnect_time - disconnect_time.

              If gap_duration <= 15 minutes:
                ATR/EMA caches valid. Skip REST warm-up.
                Regime cache valid (daily — not stale intraday).
                Log CACHE_VALID_NO_WARMUP.

              If gap_duration > 15 minutes:
                Re-run GetOHLCData(interval=5) and (interval=60)
                for affected pairs.
                Do NOT re-run GetOHLCData(interval=1440) unless
                date has changed.
                asyncio.gather() across pairs. 1.1s stagger
                within pair. AR-036.
                Log CACHE_REWARM_STARTED.

SS-RECON-013  STEP R11: Resume operations.
              Pairs with fresh caches: remain READY.
              Pairs with stale caches (rewarm in progress):
                Set to WARM_UP until rewarm completes.
              BLOCKED pairs: unchanged.
              Log RECONNECT_COMPLETE with gap_duration.
              Resume pipeline at next candle-close.
              Discard candle-close events that fired during
              Steps R1-R11. Log CANDLE_DISCARDED_DURING_RECONNECT.

------------------------------------------------------------
9.3 PIPELINE DURING RECONNECT
------------------------------------------------------------

SS-RECON-014  No pipeline evaluations during Steps R1-R11.
              Any candle-close events during reconnect:
              DISCARDED after reconnect completes.
              A missed evaluation is safer than a mis-fired entry.
              Log CANDLE_DISCARDED_DURING_RECONNECT for each.

------------------------------------------------------------
9.4 FATAL RECONNECT FAILURE
------------------------------------------------------------

SS-RECON-015  If reconnect fails after 20 total attempts
              spanning ~481 seconds (~8 minutes) (OI-020):
              Log FATAL_RECONNECT_FAILED (CRITICAL).
              Alert operator at alerts@tothbot.com (OI-019).
              Stop retrying.
              Systemd WatchdogSec=120 detects watchdog ping
              has stopped → restarts TothBot automatically.
              On restart: full startup sequence (Section 1).
              Open positions protected by resting emergSL orders.
              Attempt count and window harmonized with 1011002
              dv1_20 WM-RECONNECT-002 / WM-RECONNECT-017.

------------------------------------------------------------
9.5 RECONNECT INVARIANT VERIFICATION
------------------------------------------------------------

SS-RECON-016  After RECONNECT_COMPLETE, verify:
              portfolio_baseline_USD unchanged (log value).
              drawdown_pct unchanged (log value).
              system_state (halt/pause/normal) unchanged.
              If any invariant violated: log INVARIANT_BREACH,
              alert operator CRITICAL. Do not resume pipeline.

SS-WIRE-001  The _regime_wrapper closure in startup_sequence.py
             MUST pass wm.monitored_universe to
             rge.run_daily_computation().

             DEFECT-SS-009 root cause: _regime_wrapper called
             rge.run_daily_computation() with no universe
             argument. rge._universe is set at construction
             from _load_universe(config) which returns
             ["BTC/USD"] only. The full 50-pair universe is
             built later by WSManager from the Kraken
             instrument snapshot and is not known at
             construction time. Result: regime computed for
             BTC/USD only. All 49 other monitored pairs had
             NO_REGIME_DATA. Gate 3 blocked all non-BTC
             entries for the entire session until 00:00 UTC.

             Required implementation:

               async def _regime_wrapper(candles, symbol):
                 universe = (
                     list(wm.monitored_universe)
                     if wm.monitored_universe else None
                 )
                 await rge.run_daily_computation(
                     universe=universe
                 )

             Python closures capture variables by reference.
             At call time (from _warm_up_all_pairs via
             _trigger_daily_regime_refresh, or from the
             00:00 UTC midnight loop), wm.monitored_universe
             contains the fully ranked 50-pair universe.

             This applies to BOTH call sites:
               (a) Startup seed: WM-WARMUP-004 in ws_manager
               (b) Daily 00:00 UTC refresh: midnight loop

             Guard: if wm.monitored_universe else None.
             When None, run_daily_computation() falls back to
             rge._universe (["BTC/USD"]) — safe default.
