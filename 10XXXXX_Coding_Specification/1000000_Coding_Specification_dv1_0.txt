============================================================
1. PURPOSE
============================================================

This document is the AA=10 Domain Document for the
Coding Specification domain of TothBot V2. It defines
the purpose, scope, structure, and governing rules of
all AA=10 Coding Specification documents.

The Coding Specification domain contains the complete,
unambiguous coding contracts from which all TothBot V2
code is written. No code is written from any other
document. AA=10 is the sole direct input to code.

============================================================
2. DOMAIN SCOPE
============================================================

AA=10 Coding Specification contains two independent
coding pathways and one testing sub-domain:

  PATHWAY 1 — GitHub Document Control Automation
    Repository: github.com/TothBot/TothBot_V2-Docs
    Runtime: GitHub Actions (Python 3.11+)
    Anchored by: 1030000 GitHub_Automation_Coding_Anchor

  PATHWAY 2 — TothBot V2 Trading System
    Repository: github.com/TothBot/TothBot_V2-Code
    Runtime: Hetzner VPS, Python 3.12.3
    Anchored by: 1010000 Trading_System_Coding_Anchor

  TESTING — All test specifications
    Anchored by: 1020000 Testing_Coding_Anchor

The two pathways are permanently independent. No code,
configuration, or dependency is shared between them.
This is a hard architectural constraint. See TB00000
Section 3.4.3 for full pathway separation rules.

============================================================
3. CODING READINESS STANDARD
============================================================

Every AA=10 document must satisfy the five-question
coding-readiness test (TB00000 Section 3.2):

  (1) What does this component DO? (inputs → outputs)
  (2) What are its interfaces to other components?
  (3) What are its hard rules? (must / must not)
  (4) What triggers it and what does it trigger?
  (5) What does it log?

A document that cannot answer all five questions for
every component it defines is not coding-ready and is
not complete. No exceptions.

No vague terms are permitted in any AA=10 document:
approximately, generally, as needed, usually, typically.
All values are explicit. All conditions are deterministic.
All behaviors are unambiguous.

============================================================
4. WORKING DRAFT EXCEPTION
============================================================

Working Draft (dv) AA=10 documents may be created before
their parent specifications reach approved (v) state.
WD documents carry a "Must be Included From Previous
Analysis" section capturing requirements from FP/DP
and validation sessions. WD documents are completed and
elevated only after parent specifications are in approved
(v) state. This prevents requirement loss.

All WD AA=10 documents active at Phase 8 start are
listed in 1010000 Trading_System_Coding_Anchor and
1030000 GitHub_Automation_Coding_Anchor.

============================================================
5. PARENT CHAIN RULE
============================================================

Every AA=10 instance document must chain to this
Domain Document through its Sub-Domain Anchor:

  Instance Document → Sub-Domain Anchor → 1000000

No AA=10 instance document may be approved or committed
without both 1000000 and its Anchor existing in
approved (v) state on GitHub.
