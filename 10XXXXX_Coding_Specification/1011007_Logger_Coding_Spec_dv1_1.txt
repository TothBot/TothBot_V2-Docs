LOGGER CODING SPECIFICATION
============================================================

STATUS: Working Draft — Placeholder
Created 03-26-2026 under WD Exception (0311002 Section 1).

FP/DP validation (TB00019 NEW-06 / AR-063).

The Logger is the sole data source for CIATS. Its
correctness and reliability are critical to system-wide
observability and continuous improvement.

============================================================
1. PURPOSE
============================================================

The Logger provides non-blocking, structured JSON logging
for all TothBot V2 events. It is the sole data interface
between TothBot's trading operations and CIATS.

Core requirements:
  - NEVER block the trading hot path
  - Structured JSON format (orjson)
  - Bounded queue with defined overflow behavior
  - Thread-safe async logging (QueueHandler pattern)
  - CIATS reads Logger output; Logger does not know CIATS

3.1 LOGGER ARCHITECTURE (AR-014, AR-063)
------------------------------------------------------------

LG-ARCH-001  ★ Logger is the sole CIATS data interface.
             CIATS reads only from the Logger output files.
             CIATS writes only to the Parameter Store.
             No direct in-memory data transfer between
             TothBot hot path and CIATS. All data flows
             via Logger on-disk records.

LG-ARCH-002  ★ Logger MUST NEVER block the trading hot path.
             No synchronous file I/O on the asyncio event
             loop thread. No synchronous network I/O.
             All blocking I/O delegated to a separate thread.

LG-ARCH-003  ★ Logger produces structured JSON only.
             All log records are JSON objects with:
               timestamp: RFC3339 UTC string
               event: string (event name / log level code)
               level: "DEBUG"|"INFO"|"HIGH"|"CRITICAL"
               [event-specific fields...]
             Serialization: orjson.dumps() per BP-JSON-002.
             Decimal values: orjson Decimal callback mandatory
             per BP-JSON-005.

3.2 QUEUE IMPLEMENTATION (AR-014, AR-063)
------------------------------------------------------------

LG-QUEUE-001  ★ NEW dv1_0 CRITICAL (AR-063):
              Logger uses Python standard library queue,
              NOT asyncio.Queue.

              CORRECT IMPLEMENTATION:
                import queue
                import logging
                import logging.handlers

                # Bounded queue for log records
                log_queue = queue.Queue(maxsize=10000)

              NOT:
                log_queue = asyncio.Queue(maxsize=10000)
                # asyncio.Queue is NOT safe with QueueListener
                # which runs in a separate non-asyncio thread

LG-QUEUE-002  ★ QUEUE SIZE RATIONALE (FP/DP validated
              dv1_6, AR-014):
              10,000 entries provides:
                20 positions × 10 events/candle ×
                50-candle buffer = 10,000 entries
              This is the burst capacity buffer during
              high-activity periods.

LG-QUEUE-003  ★ QUEUEHANDLER ON HOT PATH:
              Attach logging.handlers.QueueHandler to all
              TothBot loggers. QueueHandler.emit() calls
              put_nowait() on the queue — very fast,
              returns immediately.

              CORRECT USAGE:
                queue_handler = logging.handlers.QueueHandler(
                    log_queue)
                tothbot_logger = logging.getLogger("tothbot")
                tothbot_logger.addHandler(queue_handler)
                tothbot_logger.setLevel(logging.DEBUG)
                # Remove all other handlers from tothbot logger
                # to ensure no blocking I/O on hot path

LG-QUEUE-004  ★ QUEUELISTENER IN SEPARATE THREAD:
              Create a QueueListener that runs in its own
              non-asyncio thread. Listener reads from the
              queue and writes to file handlers.

              CORRECT USAGE:
                file_handler = logging.handlers.RotatingFileHandler(
                    filename="logs/tothbot.log",
                    maxBytes=50 * 1024 * 1024,   # 50MB per file
                    backupCount=90,               # 90 files = 90 days
                    encoding="utf-8"
                )
                file_handler.setFormatter(
                    logging.Formatter('%(message)s'))
                # One log record = one orjson JSON line

                log_listener = logging.handlers.QueueListener(
                    log_queue,
                    file_handler,
                    respect_handler_level=True
                )
                log_listener.start()
                # QueueListener creates its own thread internally

LG-QUEUE-005  ★ LISTENER THREAD IS DAEMON:
              The QueueListener's internal thread is NOT a
              daemon thread by default in Python standard
              library. This means it will block program
              shutdown until empty.

              REQUIREMENT: On TothBot shutdown, explicitly
              stop the listener BEFORE asyncio event loop
              closes:
                log_listener.stop()
                # stop() drains the queue and joins the thread
                # Call this in the cleanup/shutdown sequence

LG-QUEUE-006  ★ QUEUE FULL BEHAVIOR — NEVER BLOCK:
              QueueHandler.emit() calls put_nowait().
              If queue is full (10,000 entries), put_nowait()
              raises queue.Full.

              QueueHandler's default behavior on queue.Full:
              It calls self.handleError(record) which logs
              the error to sys.stderr. This is the CORRECT
              behavior — the trading hot path is NOT blocked.

              ADDITIONAL REQUIREMENT: Override QueueHandler
              to also alert operator when queue overflows:

                class TothBotQueueHandler(
                        logging.handlers.QueueHandler):
                    def enqueue(self, record):
                        try:
                            self.queue.put_nowait(record)
                        except queue.Full:
                            # Log to stderr (non-blocking)
                            import sys
                            print(
                                "LOGGER QUEUE FULL — record dropped",
                                file=sys.stderr
                            )
                            # Alert operator via email
                            # (alert mechanism must be separate
                            #  from Logger to avoid circularity)
                            alert_operator_direct(
                                "CRITICAL: Logger queue full. "
                                "Disk writer may be backed up.")

LG-QUEUE-007  ★ QUEUE HEALTH MONITORING:
              WS Manager or a dedicated asyncio task MUST
              periodically check queue depth:
                every 60 seconds: check log_queue.qsize()
                if log_queue.qsize() > 8000:  # 80% full
                    alert(HIGH, "Logger queue approaching full")
                if log_queue.qsize() == 10000:  # Full
                    alert(CRITICAL, "Logger queue full")
              Provide early warning before drops occur.

LG-QUEUE-008  ★ STARTUP AND SHUTDOWN SEQUENCE:
              Startup order:
                1. Create log_queue (queue.Queue)
                2. Create file_handler with RotatingFileHandler
                3. Create log_listener (QueueListener)
                4. log_listener.start() — starts thread
                5. Create TothBotQueueHandler
                6. Attach to tothbot_logger
                7. Proceed with TothBot startup

              Shutdown order (reverse):
                1. Stop asyncio event loop tasks
                2. log_listener.stop() — drains queue, joins
                3. Close file_handler
                4. Shutdown asyncio

3.3 STRUCTURED LOG FORMAT
------------------------------------------------------------

LG-FMT-001  ★ Every log record MUST be a valid JSON object
            on a single line (NDJSON format — newline-
            delimited JSON). CIATS reads line by line.

LG-FMT-002  ★ Mandatory fields on every record:
              {
                "ts":    "2026-03-26T14:30:00.000000Z",
                "event": "CANDLE_CLOSE",
                "level": "INFO",
                ...event-specific fields...
              }

              ts:    ISO 8601 UTC with microseconds
              event: unique event code (SCREAMING_SNAKE)
              level: INFO | HIGH | CRITICAL | DEBUG

LG-FMT-003  ★ Decimal values: serialize via orjson callback
            per BP-JSON-005. Decimals appear as JSON strings
            in log output (e.g., "1.50000000") to preserve
            precision. CIATS reads and parses them back
            to Decimal.

LG-FMT-004  ★ CIATS Trade Outcome Bus records: serialized
            as a single JSON record with event="TRADE_CLOSE".
            Must include ALL fields from 1011005 Section 6.
            This is the primary CIATS data record.

------------------------------------------------------------
3.4 CIATS DATA INTERFACE
------------------------------------------------------------

LG-CIATS-001  ★ CIATS reads ONLY from log files. Never from
              in-memory state, queues, or direct function calls.

LG-CIATS-002  ★ CIATS EWMA Monitor (Stream 1) reads from:
              event codes: CANDLE_EVAL, PIPELINE_GATE_*,
              ENTRY_REJECTED, WS_ROUNDTRIP_*,
              RATE_COUNTER_UPDATE

LG-CIATS-003  ★ CIATS Trade Outcome Bus (Stream 2) reads from:
              event code: TRADE_CLOSE
              This record fires on every position close and
              contains all fields from 1011005 Section 6.

LG-CIATS-004  ★ Logger does not know CIATS exists. Logger
              writes all events. CIATS selects the events
              it needs by filtering event codes.

5. FIVE CODING-READINESS QUESTIONS (PARTIAL)
============================================================

  (1) What does Logger DO?
      Receives log records from all TothBot components.
      Enqueues without blocking. Writes to disk via
      QueueListener in a separate thread. Provides CIATS
      its sole data source. Handles queue overflow without
      blocking hot path.

  (2) Interfaces:
      IN:  All TothBot components via logging.getLogger()
      OUT: Disk log files (RotatingFileHandler)
           CIATS reads these files

  (3) Hard rules:
      NEVER block hot path.
      queue.Queue (not asyncio.Queue).
      QueueListener in separate thread.
      orjson for ALL serialization. Decimal callback mandatory.
      On queue.Full: stderr + alert, do NOT block.
      Stop listener on shutdown to drain queue.
      One JSON object per log line (NDJSON).

  (4) Triggers: Logging calls from all TothBot components.
      Queue listener runs continuously in background thread.

  (5) Logs: This IS the logging component. It logs to itself
      on error conditions (queue.Full → stderr). Logger
      does not use the Logger for its own error reporting.
