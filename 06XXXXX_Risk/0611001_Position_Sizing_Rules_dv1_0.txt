============================================================
POSITION SIZING RULES
============================================================

All content derived from FP/DP validated sources.
Primary ARs: AR-011, AR-051, AR-065. Validated across
430+ unique sources over 10 validation sessions
(TB00006 through TB00019). All rules are locked
architectural decisions unless explicitly noted as
a CIATS-owned starting value.

============================================================
1. PURPOSE
============================================================

This document is the complete, coding-ready specification
for all position sizing rules in TothBot V2. It defines
exactly how the size of every position is calculated,
how the 1:1.5 R:R constraint is enforced in every trade,
how Half-Kelly replaces fixed sizing after the 200-trade
floor, and all Decimal rounding rules that govern every
financial computation in the Risk Engine.

A coder reading this document must be able to implement
Gate 8 (Position Sizer) completely without asking any
questions.

4. PORTFOLIO USD DEFINITION — SIZING ONLY
============================================================

  PS-PORT-001  portfolio_USD for ALL sizing computations:
               portfolio_USD = spot_usd_balance
               Source: spot wallet, main sub-wallet, USD only.
               Provided by WS Manager balances channel
               (WM-BAL-002 in 1011002).

  PS-PORT-002  portfolio_USD is REALIZED CAPITAL ONLY.
               Mark-to-market value of open positions is
               NEVER included in portfolio_USD for sizing.
               RATIONALE: Including MTM creates a feedback
               loop — rising positions inflate sizing of
               new positions, increasing total risk beyond
               intent. Cash-in-hand is the only correct
               basis for new position sizing.

  PS-PORT-003  portfolio_USD for SIZING is NOT the same
               as current_portfolio_USD for DRAWDOWN.
               These are two separate computations. They
               must never be conflated. See 0611002 for
               the drawdown portfolio definition.

============================================================
5. TRADEABLE CAPITAL
============================================================

  PS-TRADE-001  tradeable_USD = portfolio_USD * tradeable_pct
                tradeable_pct: CIATS-owned starting value = 0.50
                (50% of portfolio_USD committed to trading).
                The remaining 50% is held in reserve.

  PS-TRADE-002  tradeable_pct is computed once per pipeline
                evaluation from the frozen Parameter Store
                snapshot (I-4). It does not change during
                a pipeline evaluation.

============================================================
6. PER-TRADE ALLOCATION
============================================================

------------------------------------------------------------
6.1 Phase 1 — Fixed Allocation (below 200 closed trades)
------------------------------------------------------------

  PS-PTA-001  per_trade_USD = tradeable_USD * per_trade_pct
              per_trade_pct: CIATS-owned starting value = 0.05
              (5% of tradeable_USD per trade).

  PS-PTA-002  per_trade_pct is read from the frozen
              Parameter Store snapshot. It does not change
              during a pipeline evaluation.

------------------------------------------------------------
6.2 Phase 2 — Half-Kelly (at 200+ closed trades)
------------------------------------------------------------

  PS-HK-001   At 200 closed trades, CIATS activates
              Half-Kelly. per_trade_pct is replaced by
              a dynamically computed Kelly fraction.
              The fixed per_trade_pct parameter becomes
              inactive. CIATS writes the Kelly-derived
              effective fraction to the Parameter Store.

  PS-HK-002   Half-Kelly formula:
                K_full = W - ((1 - W) / R)
                K_half = K_full * Decimal("0.5")
                per_trade_USD = min(
                    K_half * tradeable_USD,
                    tradeable_USD / max_concurrent
                )

  PS-HK-003   W — WIN RATE (net):
                W = count(closed_trades where
                          net_gain_usd > 0)
                    / count(total_closed_trades)
              "Win" = position closed with POSITIVE NET
              P/L after all fees (entry maker + exit fees).
              A TP fill that results in negative net P/L
              counts as a loss for Kelly purposes.
              Source: Trade Outcome Bus net_gain_usd field
              via Logger (sole CIATS data interface).

  PS-HK-004   R — NET REWARD:RISK RATIO:
                R = mean(net_gain_usd for winning trades)
                    / mean(|net_loss_usd| for losing trades)
              Both values are actual realized net P/L from
              Trade Outcome Bus — not theoretical R:R targets.
              Fees are already included in both figures.
              RATIONALE: Realized R clusters near 1.5 for
              TP exits but deviates due to slippage on
              market sells, partial fills, and fee
              accumulation. Kelly must use realized, not
              theoretical, to correctly size positions.

  PS-HK-005   The cap (tradeable_USD / max_concurrent)
              prevents any single trade from exceeding its
              proportional share even at a high Kelly
              fraction. This is a loss-prevention constraint.

  PS-HK-006   Half-Kelly update cadence: CIATS recomputes
              W and R and updates the Parameter Store every
              50 trades after the 200-trade activation.
              Minimum 50-trade interval between any two
              CIATS parameter changes (CIATS-PDCA-001).

  PS-HK-007   If K_full <= 0 (negative Kelly — edge is
              negative), per_trade_USD = 0. TothBot stops
              sizing new entries. CIATS alerts Bill.
              This condition must never persist. It
              indicates the strategy is losing edge and
              requires immediate operator review.

------------------------------------------------------------
6.3 NON_DIR Regime 50% Size Modifier
------------------------------------------------------------

  PS-MOD-001  When Gate 6 (Regime Gate) assigns a 50%
              modifier (NON_DIRECTIONAL + NORMAL_VOL
              regime), per_trade_USD is halved:
                per_trade_USD = per_trade_USD * Decimal("0.5")
              This modifier applies in both Phase 1 and
              Phase 2 (after Half-Kelly computation).

  PS-MOD-002  The 50% modifier reflects reduced conviction
              in non-directional regimes. Full size is
              reserved for TRENDING_POS regimes where
              directional edge is confirmed by ADX and EMA.

7. GATE 8 — R:R FORMULA (SACRED — AR-011)
============================================================

Gate 8 never blocks. It only sizes. All five values below
are computed on every Gate 8 execution.

All computations use ACTUAL entry fill price, not the
limit price submitted at dispatch. The entry fill price
is received from the executions channel (exec_type=trade
or exec_type=filled on the entry order). This is why OTO
conditional orders were rejected (AR-008) — OTO uses
limit price, which violates the R:R integrity requirement.

------------------------------------------------------------
7.1 MAE Threshold (Layer 2 Exit Trigger Price)
------------------------------------------------------------

  PS-RR-001   mae_pct = (ATR(14) * mae_mult) / entry_fill_price
              mae_mult: CIATS-owned starting value = 1.5
              ATR(14): incremental Wilder ATR from 5-minute
              candle cache. O(1) lookup — never recomputed
              at dispatch. Provided by WS Manager cache.

  PS-RR-002   mae_pct defines the percentage distance from
              entry fill price at which Layer 2 MAE exit
              fires. It is the loss side of the R:R equation.

------------------------------------------------------------
7.2 Net Loss
------------------------------------------------------------

  PS-RR-003   net_loss = mae_pct + Decimal("0.0016")
                                  + Decimal("0.0026")
              0.0016 = entry maker fee (0.16%)
              0.0026 = MAE exit taker fee (0.26%)
              net_loss is the total realized cost of a
              maximum adverse excursion exit including fees.

------------------------------------------------------------
7.3 Net Gain (SACRED — HARDCODED — NEVER CHANGES)
------------------------------------------------------------

  PS-RR-004   net_gain = net_loss * Decimal("1.5")
              This is the sacred 1:1.5 R:R constraint.
              CIATS does not own this multiplier.
              Bill does not change this multiplier.
              It never changes. No exception. No override.

------------------------------------------------------------
7.4 Gross Target (TP Distance)
------------------------------------------------------------

  PS-RR-005   gross_target = net_gain + Decimal("0.0016")
              0.0016 = TP maker fill fee (0.16%).
              gross_target is the total percentage gain
              required at the TP fill price to achieve
              net_gain after the TP maker fee.

------------------------------------------------------------
7.5 Emergency SL Distance (Layer 3 — Off-Book)
------------------------------------------------------------

  PS-RR-006   emergSL_dist = (ATR(14) * emergency_sl_mult)
                              / entry_fill_price
              emergency_sl_mult: CIATS-owned starting
              value = 3.0
              emergSL_dist is the percentage distance from
              entry fill price at which the off-book
              emergency stop-market is placed on Kraken.

  PS-RR-007   emergSL_dist is NEVER part of the R:R formula.
              It does not affect net_loss, net_gain, or
              gross_target. It is computed separately for
              order placement only.

  PS-RR-008   The emergSL is crash protection only.
              It fires ONLY on VPS/TothBot/internet failure.
              It must NEVER fire in normal operation.
              If it fires, it is a system failure event
              requiring immediate investigation.

============================================================
8. ORDER PARAMETER COMPUTATION WITH DECIMAL ROUNDING
============================================================

All financial computations use Python Decimal arithmetic.
float arithmetic is PROHIBITED. math.floor() and
math.ceil() are PROHIBITED for any rounding operation.
All rounding uses Decimal.quantize() only.
(BP-DEC-001 through BP-DEC-008 in 1011001)

All prices and quantities received from Kraken API
responses must be converted to Decimal on receipt:
  value = Decimal(str(api_response_value))
Never: Decimal(float_value) — binary precision errors.

------------------------------------------------------------
8.1 Order Quantity
------------------------------------------------------------

  PS-QTY-001  raw_qty = per_trade_USD / entry_limit_price
              entry_limit_price used for SIZING (pre-fill).
              entry_fill_price used for R:R (post-fill).
              These are different values. Do not conflate.

  PS-QTY-002  order_qty = raw_qty.quantize(
                  pair_cache[sym]["qty_increment"],
                  rounding=ROUND_DOWN
              )
              ROUND_DOWN: never commit more base currency
              than the USD allocation allows. Erring toward
              smaller size is the loss-prevention choice.

------------------------------------------------------------
8.2 TP Price
------------------------------------------------------------

  PS-TP-001   raw_tp = entry_fill_price * (
                  Decimal("1") + gross_target
              )

  PS-TP-002   tp_price = raw_tp.quantize(
                  pair_cache[sym]["price_increment"],
                  rounding=ROUND_UP
              )
              ROUND_UP: ensures the TP limit is at or
              above the minimum required price to achieve
              net_gain. Rounding down would place the TP
              below the required threshold, violating R:R.

------------------------------------------------------------
8.3 Emergency SL Price (Layer 3 — Off-Book)
------------------------------------------------------------

  PS-SL-001   raw_sl = entry_fill_price * (
                  Decimal("1") - emergSL_dist
              )

  PS-SL-002   emergSL_price = raw_sl.quantize(
                  pair_cache[sym]["price_increment"],
                  rounding=ROUND_DOWN
              )
              ROUND_DOWN: places the stop below the
              computed threshold, ensuring it does not
              trigger prematurely on noise at the boundary.

------------------------------------------------------------
8.4 MAE Threshold Price (Layer 2 — for Exit Controller)
------------------------------------------------------------

  PS-MAE-001  mae_price = entry_fill_price * (
                  Decimal("1") - mae_pct
              )

  PS-MAE-002  mae_price = mae_price.quantize(
                  pair_cache[sym]["price_increment"],
                  rounding=ROUND_DOWN
              )
              mae_price is passed to the Exit Controller
              for continuous bbo monitoring (Layer 2 trigger).

============================================================
9. MINIMUM VIABLE POSITION VALIDATION
============================================================

  PS-MIN-001  After order_qty is computed, validate:
                order_qty >= pair_cache[sym]["qty_min"]
              If fails: log POSITION_TOO_SMALL with full
              sizing detail. Skip this pair. Do not dispatch.

  PS-MIN-002  Validate notional value:
                order_qty * entry_limit_price >=
                pair_cache[sym]["cost_min"]
              If fails: log POSITION_TOO_SMALL. Skip.

  PS-MIN-003  Both validations must pass before dispatch.
              Either failure is a SKIP, not a HALT.
              The pipeline continues to the next pair.
              This condition is expected occasionally
              (small portfolio, low-priced pairs).

  PS-MIN-004  CIATS monitors POSITION_TOO_SMALL frequency.
              If frequency is high, CIATS may propose a
              per_trade_pct increase or a universe filter
              adjustment. This is a CIATS Proposal Engine
              function — not an automatic system action.

============================================================
10. GATE 8 OUTPUT
============================================================

  PS-OUT-001  Gate 8 produces the following values for
              every successfully sized position:
                symbol            (trading pair)
                order_qty         (Decimal, base currency)
                entry_limit_price (Decimal, for dispatch)
                tp_price          (Decimal, resting limit)
                emergSL_price     (Decimal, stop-market)
                mae_price         (Decimal, Layer 2 trigger)
                per_trade_USD     (Decimal, for POR entry)
                net_loss          (Decimal, for Logger)
                net_gain          (Decimal, for Logger)
                gross_target      (Decimal, for Logger)

  PS-OUT-002  Gate 8 output is passed to the Execution
              Engine (0511003) for order dispatch.
              Gate 8 never dispatches orders directly.

11. INTERFACES
============================================================

  11.1  FROM WS Manager (0511001)
        spot_usd_balance      — current cash balance
        pair_cache[sym]       — qty_increment, price_increment,
                                qty_min, cost_min
        atr_cache[sym]        — ATR(14) running value
        pending_orders        — for available_USD (Gate 7,
                                see 0611003)

  11.2  FROM Parameter Store (frozen snapshot)
        tradeable_pct         — sizing parameter
        per_trade_pct         — sizing parameter (Phase 1)
        mae_mult              — R:R parameter (1.5 starting)
        emergency_sl_mult     — emergSL parameter (3.0 starting)
        max_concurrent        — for Half-Kelly cap

  11.3  FROM Executions Channel (post-fill)
        entry_fill_price      — ACTUAL fill price for R:R
        Provided via WS Manager executions channel handler.

  11.4  TO Execution Engine (0511003)
        Complete Gate 8 output dict (PS-OUT-001).

  11.5  TO Position Mirror (0511005)
        tp_price, emergSL_price, mae_price recorded
        at dispatch for Exit Controller use.

  11.6  TO Logger (0511006)
        Every Gate 8 calculation logged in full
        (see Section 12).

  11.7  TO CIATS (via Logger)
        per_trade_USD, net_loss, net_gain, gross_target
        logged per trade — feeds Trade Outcome Bus
        for Half-Kelly W and R computation.

============================================================
12. LOGGING REQUIREMENTS
============================================================

  PS-LOG-001  Every Gate 8 execution logs:
                symbol
                portfolio_USD
                tradeable_USD
                per_trade_USD (and modifier if 50% applied)
                order_qty (raw and quantized)
                entry_limit_price
                atr_14 (value used)
                mae_mult (value used)
                mae_pct, net_loss, net_gain, gross_target
                emergSL_dist, emergSL_price
                tp_price
                mae_price
                Kelly phase (FIXED or HALF_KELLY)
                W and R values (if Half-Kelly active)

  PS-LOG-002  Every POSITION_TOO_SMALL event logs:
                symbol
                order_qty (computed)
                qty_min (required)
                notional (computed)
                cost_min (required)
                failure reason (qty or notional)

  PS-LOG-003  Every K_full <= 0 event logs:
                W (win rate)
                R (reward:risk ratio)
                K_full (negative value)
                trade count (at time of detection)
              Alert sent to alert@tothbot.com immediately.

13. HARD RULES
============================================================

  HR-PS-001   Net 1:1.5 R:R is HARDCODED and SACRED.
              net_gain = net_loss * 1.5. NEVER changes.
              CIATS does not own this multiplier.

  HR-PS-002   R:R uses ACTUAL fill price, not limit price.
              entry_fill_price from executions channel.
              entry_limit_price is for sizing only.

  HR-PS-003   All financial computations use Python Decimal.
              float is PROHIBITED. math.floor/ceil is
              PROHIBITED for any rounding operation.

  HR-PS-004   API values converted to Decimal via str():
              Decimal(str(value)) — NEVER Decimal(float).

  HR-PS-005   order_qty rounds DOWN (ROUND_DOWN).
              tp_price rounds UP (ROUND_UP).
              emergSL_price rounds DOWN (ROUND_DOWN).
              mae_price rounds DOWN (ROUND_DOWN).

  HR-PS-006   emergSL_dist is NEVER in the R:R formula.
              It is computed separately for order placement.

  HR-PS-007   Gate 8 NEVER blocks. If sizing is possible,
              Gate 8 always produces output.
              Minimum validation failures (PS-MIN-001,
              PS-MIN-002) are SKIP events, not blocks.

  HR-PS-008   Half-Kelly activates at exactly 200 closed
              trades. Below 200: fixed per_trade_pct only.
              At and above 200: Half-Kelly governs.

  HR-PS-009   If K_full <= 0: per_trade_USD = 0.
              Alert immediately. Do not dispatch entries.

  HR-PS-010   NON_DIR 50% modifier applies after
              per_trade_USD is computed — whether by
              fixed allocation or Half-Kelly.

  HR-PS-011   Gate 8 reads ATR from cache (O(1) lookup).
              It never recomputes ATR at dispatch time.

============================================================
14. FIVE CODING-READINESS QUESTIONS
============================================================

  (1) What does Gate 8 DO?
      Computes five R:R values (mae_pct, net_loss,
      net_gain, gross_target, emergSL_dist) from
      ATR(14) and actual fill price. Computes order_qty,
      tp_price, emergSL_price, mae_price using Decimal
      arithmetic and Decimal.quantize() rounding. Validates
      minimum viable position. Applies NON_DIR 50% modifier
      if Gate 6 signaled it. Passes complete output to
      Execution Engine. Never blocks.

  (2) What are its interfaces?
      Inputs: spot_usd_balance, pair_cache, atr_cache
      (from WS Manager), Parameter Store frozen snapshot,
      entry_fill_price (from executions channel post-fill).
      Outputs: order_qty, tp_price, emergSL_price,
      mae_price, per_trade_USD to Execution Engine,
      Position Mirror, and Logger.

  (3) What are its hard rules?
      HR-PS-001 through HR-PS-011 above.
      Critically: 1:1.5 R:R is sacred. float is prohibited.
      Fill price drives R:R. Gate 8 never blocks.

  (4) What triggers it and what does it trigger?
      Triggered by: Gate 7 pass on every 5-minute OHLC
      candle close pipeline evaluation.
      Triggers: Execution Engine order dispatch (0511003),
      Position Mirror update (0511005), Logger record
      (0511006), CIATS Trade Outcome Bus (via Logger).

  (5) What does it log?
      Every Gate 8 execution: full sizing detail
      (PS-LOG-001). Every POSITION_TOO_SMALL skip
      (PS-LOG-002). Every K_full <= 0 alert (PS-LOG-003).
