============================================================
2. SYSTEM IDENTITY
============================================================

TothBot V2 is an automated cryptocurrency spot trading
system running on Kraken using Python 3.12.3 on a
Hetzner VPS (Ubuntu 24.04.4 LTS).

TothBot V2 is a three-system organism:

  Zone 1 — Kraken:  Event source.
  Zone 2 — TothBot: Event processor. Executes trades.
  Zone 3 — CIATS:   Continuous improvement engine.
                    Owns all operating parameters.

Operator: Bill (sole operator).
Sole hardcoded constraint: Net 1:1.5 R:R — never changes.
Everything else: CIATS-owned starting values.

Primary mission: Maximize profit. Minimize loss.
Emphasis: Minimize loss. Loss prevention takes priority.

4.3 MODULE CODING SEQUENCE
------------------------------------------------------------

Coding proceeds bottom-of-stack first, following the
5-minute Kraken OHLC candle-close event flow. Each
module is one session per DEC-003 Path A cadence
(one diagram per session) and per RR-SCOPE-011 (one
primary mission per session).

  STEP 1.  WS_Manager (D1)
           System clock. Receives Kraken WS v2 candle-
           close events. Everything downstream depends
           on its events. Heavily specced (D1 + 0511001
           dv1_9 + 0411001 dv1_12). Empirically
           validated against Kraken in paper testing
           (TB00141 + TB00142 message-limit testing).
           Target session: TB00386.

  STEP 2.  Logger (cross-cutting; references D6 +
           0511006 dv1_4)
           Must exist before anything else can emit
           events. CIATS sole data source per TB00000
           §3.4.2 Pathway 2 functions.

  STEP 3.  Regime_Engine (D4 + 0711002 dv1_2)
           Daily-cadence regime taxonomy computation
           (6 regimes; BTC/USD anchor).

  STEP 4.  Signal_Pipeline (D2 + 0511002 dv1_1 +
           0711001 dv1_2)
           8-gate evaluation pipeline triggered by
           candle close.

  STEP 5.  Position_Mirror + Execution_Engine (D6 +
           0511005 dv1_1 + 0511003 dv1_1)
           Order dispatch and position-state tracking.
           Per TB00000 §4.4 PA-001..010, Position Mirror
           sourcing is one of the four permitted
           divergence points between paper and live —
           paper-mode population is local-simulation
           only; live-mode population is Kraken
           executions-event sourced.

  STEP 6.  Long_Module + Short_Module (D3 + D4 + 0811005
           dv1_3)
           Per-module entry orchestration. Each module
           is a parallel, independent sibling per
           TB00000 §9.3 PARALLEL-MODULE FRAMEWORK.
           Each gets its own universe scope, gate
           thresholds, sizing function, CIATS instance,
           drawdown halts. Shared WS Manager at data-
           acquisition layer only.

  STEP 7.  Exit_Controller (D3 + 0511004 dv1_6)
           Three-layer exit architecture (Layer 1
           signal/TP; Layer 2 MAE threshold; Layer 3
           emergency SL crash protection only).
           Triggered by candle close + fill events.

  STEP 8.  Risk_Engine (D5 + D8)
           G7 risk-guard checks (drawdown halts,
           concentration cap, exposure cap).

  STEP 9.  CIATS (D5 + 1011010 dv1_8)
           Inter-trade boundary. Per-module CIATS
           instances per TB00000 §9.6. Operates last
           in startup sequence.

Subsequent integration sessions glue the modules per
0211003 Startup_Shutdown_Procedure dv1_1 and run
integration tests per 1021002 Integration_Test_
Specification.
