KRAKEN REST API SPECIFICATION
============================================================

All content derived from FP/DP validated sources (430+
unique sources across 10 validation sessions, TB00006
through TB00019). All rules are verified unless explicitly
noted as a starting value.

============================================================
1. PURPOSE AND SCOPE
============================================================

This document is the complete, coding-ready specification
for all Kraken REST API endpoints used by TothBot V2. It
defines every endpoint, every request format, every
response format, every error handling behavior, and every
hard constraint that governs REST communication between
TothBot and Kraken.

TothBot V2 uses REST for a minimal, specific set of
functions. All normal trading operations use WebSocket v2.
REST is used only where WebSocket cannot serve the need.

REST endpoints used by TothBot V2 (all six):
  1. GetWebSocketsToken    — WS private connection auth
  2. GetOHLCData           — daily regime computation
  3. GetOpenOrders         — reconciliation fallback
  4. GetAccountBalance     — reconciliation fallback
  5. CancelAllOrders       — emergency kill switch only
  6. Status API            — proactive maintenance check
  7. QueryOrdersInfo       — targeted single-order recon

This document does NOT cover:
  - WebSocket v2 interface (see 0411001)
  - Fee structure and rate limits detail (see 0411003)
  - REST implementation architecture (see 1011002)

3. AUTHENTICATION
============================================================

------------------------------------------------------------
3.1 REST Authentication Model
------------------------------------------------------------

REST-AUTH-001  Kraken Spot REST private calls use
               HMAC-SHA512 authentication.

               Signature formula:
                 message = URI_path + SHA256(nonce +
                           POST_data_string)
                 signature = HMAC-SHA512(message,
                             base64_decode(api_secret))
                 API-Sign header = base64_encode(signature)

REST-AUTH-002  The October 1, 2025 Kraken authentication
               breaking change applied to Kraken FUTURES
               REST ONLY. Kraken Spot REST authentication
               is UNCHANGED. No code changes required
               for Spot. (A-14 / PL-014 RESOLVED)

REST-AUTH-003  Required headers for all private REST calls:
                 API-Key:  TRADE API key value
                 API-Sign: HMAC-SHA512 signature (above)
               Content-Type: application/x-www-form-urlencoded

------------------------------------------------------------
3.2 Nonce
------------------------------------------------------------

REST-AUTH-004  Every private REST call MUST include a
               nonce: a strictly increasing integer.
               Standard implementation: current Unix
               timestamp in milliseconds.
                 nonce = int(time.time() * 1000)

REST-AUTH-005  Kraken nonce window: 10,000ms. Calls with
               nonce more than 10,000ms behind the current
               time are rejected. Clock drift on the VPS
               must be managed. Use NTP-synchronized
               system clock.

------------------------------------------------------------
3.3 HTTP Client Configuration
------------------------------------------------------------

REST-HTTP-001  All REST calls MUST use aiohttp.ClientSession.
               Never use requests (synchronous — blocks
               asyncio event loop). (AR-025 / IMP-06)

REST-HTTP-002  MANDATORY aiohttp ClientSession configuration:
                 timeout = aiohttp.ClientTimeout(
                     total=10,
                     connect=5,
                     sock_read=8
                 )
                 connector = aiohttp.TCPConnector(
                     limit=10,
                     limit_per_host=5,
                     force_close=False
                 )
                 session = aiohttp.ClientSession(
                     timeout=timeout,
                     connector=connector
                 )
               (AR-035 / A-22)

REST-HTTP-003  Timeout rationale:
                 total=10:     10s max for complete request
                 connect=5:    5s max to establish TCP conn
                 sock_read=8:  8s max waiting for response
               Without explicit timeout, REST calls hang
               indefinitely on degraded networks, blocking
               the asyncio event loop and starving all
               other tasks.

REST-HTTP-004  force_close=False enables HTTP keepalive.
               Connection reused across calls. Reduces
               per-call TCP handshake overhead.

REST-HTTP-005  One shared ClientSession for the lifetime
               of the TothBot process. Do NOT create a
               new session per call. Session creation is
               expensive and defeats keepalive.

REST-HTTP-006  REST base URL (private endpoints):
                 https://api.kraken.com
               All private endpoint paths are POST to
               /0/private/[EndpointName].

REST-HTTP-007  REST base URL (public endpoints):
                 https://api.kraken.com
               Public endpoint paths are GET or POST to
               /0/public/[EndpointName].

------------------------------------------------------------
3.4 API Key Pairs
------------------------------------------------------------

REST-KEY-001   TothBot V2 requires two separate API key pairs:
                 DATA key:  public market data access only
                 TRADE key: private order management access

REST-KEY-002   MANDATORY: Both API keys MUST be IP-whitelisted
               to the VPS IP address: 87.99.141.44.
               IP whitelisting is configured separately in
               Kraken API key settings for each key.
               Update whitelist on any VPS migration.
               (AR-037)

REST-KEY-003   API key permissions required:
                 DATA key:   Query Funds, Query Open Orders
                             and Trades, Query Closed Orders
                 TRADE key:  Query Funds, Query Open Orders
                             and Trades, Create and Modify
                             Orders, Cancel and Close Orders

REST-KEY-004   API keys are stored securely on the VPS.
               Never hardcoded in source code. Loaded
               from environment variables or encrypted
               config file at startup.

4. ENDPOINT SPECIFICATIONS
============================================================

------------------------------------------------------------
4.1 GetWebSocketsToken
------------------------------------------------------------

REST-WST-001   Purpose: Obtain a WebSocket authentication
               token for use in private WS v2 connections.

REST-WST-002   Endpoint:
                 POST https://api.kraken.com/0/private/
                      GetWebSocketsToken
               Authentication: Required (TRADE key).
               Request body: nonce=[nonce]

REST-WST-003   Response format (success):
                 {
                   "error": [],
                   "result": {
                     "token": "string (WebSocket token)",
                     "expires": integer (seconds)
                   }
                 }

REST-WST-004   Token validity: approximately 15 minutes
               (900 seconds). A fresh token MUST be
               obtained on every reconnect. Do NOT
               cache and reuse across reconnects.

REST-WST-005   Call timing: At startup (Step 2 of startup
               sequence) and immediately before every
               private WS reconnect.

REST-WST-006   On error response (error[] non-empty):
               Log REST_ERROR(endpoint=GetWebSocketsToken,
               errors=error[]). Retry up to 3 times with
               1-second delay between attempts. If all
               3 attempts fail: halt startup, alert
               operator.

------------------------------------------------------------
4.2 GetOHLCData
------------------------------------------------------------

REST-OHLC-001  Purpose: Retrieve historical OHLC candle
               data for daily regime computation.

REST-OHLC-002  Endpoint:
                 GET https://api.kraken.com/0/public/OHLC
               Authentication: None (public endpoint).
               Parameters:
                 pair:     [Kraken pair symbol]
                 interval: 1440 (daily candles, minutes)
                 since:    [optional — Unix timestamp]

REST-OHLC-003  Response format (success):
                 {
                   "error": [],
                   "result": {
                     "[pair]": [
                       [time, open, high, low, close,
                        vwap, volume, count],
                       ...
                     ],
                     "last": integer (last candle time)
                   }
                 }
               Each candle field is a string. All values
               MUST be converted to Decimal(str(value))
               immediately on parse. No float arithmetic
               on financial values.

REST-OHLC-004  CRITICAL — response[-1] MUST be excluded:
               GetOHLCData ALWAYS returns the current
               not-yet-committed candle as the LAST entry
               (response[-1]). Kraken documentation:
               "The last entry in the OHLC array is for
               the current, not-yet-committed timeframe,
               and will always be present, regardless of
               the value of since."

               Use ONLY response[:-1] (all committed
               candles). INCLUDING response[-1] corrupts
               ALL regime indicators (ADX, EMA, ATR) and
               produces incorrect regime classification.
               (GAP-03 / AR-017 / HR-EI-004 — CRITICAL)

REST-OHLC-005  Returns up to 720 OHLC entries (including
               the uncommitted current candle). After
               excluding response[-1]: up to 719 committed
               daily candles — approximately 2 years of
               history. More than sufficient for all regime
               computations.

REST-OHLC-006  Call schedule: Once per monitored pair at
               00:00 UTC daily. Staggered at 1.1-second
               intervals across all pairs.
               (FLAG 2 / AR-017 / AR-036)

REST-OHLC-007  Call staggering rule:
               REST public GetOHLCData rate limit:
               1 call per second per IP+pair.
               50 pairs × 1.1s = 55 seconds total.
               This completes before the first 5-minute
               candle close of the new day.
               Implementation: asyncio.sleep(1.1) between
               each successive GetOHLCData call. Calls
               across DIFFERENT pairs may use
               asyncio.gather() for parallelism.
               (AR-036)

REST-OHLC-008  Also used at startup for warm-up seeding:
               Three calls per monitored pair at startup
               (per 1011014 startup sequence):
                 Call A: interval=5  (ATR(14) seed)
                 Call B: interval=60 (EMA(20)/EMA(50) seed)
                 Call C: interval=1440 (initial regime)
               Startup calls follow the same response[-1]
               exclusion rule and same staggering rule.

REST-OHLC-009  On error response:
               Log REST_ERROR(endpoint=GetOHLCData,
               pair=pair, errors=error[]). Retry once
               after 2 seconds. If retry fails: log
               OHLC_FETCH_FAILED, use prior regime
               classification for this pair until next
               00:00 UTC cycle. Do NOT halt trading.

------------------------------------------------------------
4.3 GetOpenOrders
------------------------------------------------------------

REST-OO-001    Purpose: Retrieve all currently open orders.
               Used as reconciliation fallback when
               executions channel sequence gap is detected
               or on restart. (AR-021)

REST-OO-002    Endpoint:
                 POST https://api.kraken.com/0/private/
                      OpenOrders
               Authentication: Required (TRADE key).
               Request body: nonce=[nonce]
               Optional: trades=true (include trade info)

REST-OO-003    Response format (success):
                 {
                   "error": [],
                   "result": {
                     "open": {
                       "[order_id]": {
                         "refid": ...,
                         "userref": integer,
                         "status": "open",
                         "opentm": float,
                         "starttm": float,
                         "expiretm": float,
                         "descr": { order description },
                         "vol": "string (order qty)",
                         "vol_exec": "string (filled qty)",
                         "cost": "string",
                         "fee": "string",
                         "price": "string (avg fill price)",
                         "stopprice": "string",
                         "limitprice": "string",
                         "misc": "string",
                         "oflags": "string"
                       },
                       ...
                     }
                   }
                 }

REST-OO-004    On executions sequence gap:
               Call GetOpenOrders immediately on gap
               detection. Reconcile Position Mirror
               against returned open orders. Log
               EXECUTIONS_GAP_RECONCILED with before/after
               Position Mirror state. (AR-021)

REST-OO-005    On restart:
               Call GetOpenOrders as fallback if the
               snap_orders snapshot from the executions
               channel subscription is unavailable or
               incomplete. See startup sequence (1011014).

REST-OO-006    On error response:
               Log REST_ERROR(endpoint=GetOpenOrders,
               errors=error[]). Retry once after 2 seconds.
               If retry fails: log RECONCILIATION_FAILED,
               alert operator. TothBot enters DEGRADED
               state — monitor only, no new entries.

------------------------------------------------------------
4.4 GetAccountBalance
------------------------------------------------------------

REST-BAL-001   Purpose: Retrieve current account balances.
               Used as reconciliation fallback when
               balances channel sequence gap is detected
               or on restart. (AR-009)

REST-BAL-002   Endpoint:
                 POST https://api.kraken.com/0/private/
                      Balance
               Authentication: Required (TRADE key).
               Request body: nonce=[nonce]

REST-BAL-003   Response format (success):
                 {
                   "error": [],
                   "result": {
                     "ZUSD": "string (USD balance)",
                     "XXBT": "string (BTC balance)",
                     ...
                   }
                 }
               All balance values are strings. Convert to
               Decimal(str(value)) immediately on parse.

REST-BAL-004   CRITICAL: Extract USD balance from result
               field ONLY for the spot/main wallet.
               The REST GetAccountBalance endpoint returns
               the spot wallet balances only (no futures,
               no staking). This is consistent with the
               balances WS channel rule (WS-BAL-002 in
               0411001). Use the returned USD balance
               directly as portfolio_baseline_USD.

REST-BAL-005   On balances sequence gap:
               Call GetAccountBalance immediately on gap
               detection. Update portfolio_baseline_USD
               from returned USD balance. Log
               BALANCES_GAP_RECONCILED with before/after
               balance values.

REST-BAL-006   On restart:
               Call GetAccountBalance as fallback if the
               balances channel snapshot is unavailable
               or incomplete on reconnect.

REST-BAL-007   On error response:
               Log REST_ERROR(endpoint=GetAccountBalance,
               errors=error[]). Retry once after 2 seconds.
               If retry fails: log BALANCE_RECONCILIATION_
               FAILED, alert operator. TothBot enters
               DEGRADED state.

------------------------------------------------------------
4.5 CancelAllOrders
------------------------------------------------------------

REST-CAO-001   Purpose: Emergency kill switch only.
               Cancels ALL open orders on the account.

REST-CAO-002   Endpoint:
                 POST https://api.kraken.com/0/private/
                      CancelAll
               Authentication: Required (TRADE key).
               Request body: nonce=[nonce]

REST-CAO-003   Response format (success):
                 {
                   "error": [],
                   "result": {
                     "count": integer (orders canceled)
                   }
                 }

REST-CAO-004   USE RESTRICTION — EMERGENCY ONLY:
               CancelAllOrders cancels ALL open orders
               including resting TP limit orders and
               emergSL stop orders. Calling this in normal
               operation destroys crash protection.
               This endpoint MUST ONLY be called by:
               (a) Manual operator emergency action
               (b) An explicit EMERGENCY_HALT code path
                   triggered by Bill, not by automation

REST-CAO-005   CancelAllOrders is NOT used for:
               - Normal MAE Layer 2 exits (use cancel_order)
               - Full Halt drawdown circuit breaker
                 (use WS batch_cancel — preserves TP+emergSL
                  on individual positions being managed)
               - Any automated routine operation

REST-CAO-006   After calling CancelAllOrders:
               Log EMERGENCY_KILL_SWITCH_ACTIVATED(count=n).
               Alert operator PRIORITY_CRITICAL.
               TothBot enters HALT state.
               Position state is unknown — manual review
               required before restarting.

------------------------------------------------------------
4.6 Status API (Kraken System Status)
------------------------------------------------------------

REST-STAT-001  Purpose: Proactive detection of scheduled
               Kraken maintenance before it affects
               TothBot operation. Called at startup only.

REST-STAT-002  Endpoint (public, no authentication):
                 GET https://status.kraken.com/api/v2/
                     scheduled-maintenances/upcoming.json

REST-STAT-003  Response format (success): JSON object
               with an array of scheduled maintenance
               windows, each containing:
                 name:           maintenance description
                 scheduled_for:  ISO 8601 start time
                 scheduled_until: ISO 8601 end time
                 status:         "scheduled" | "in_progress"
                                 | "verifying" | "completed"

REST-STAT-004  Processing rule:
               For each upcoming maintenance window:
                 If scheduled_for is within 2 hours of
                 startup time:
                   Log KRAKEN_MAINTENANCE_SCHEDULED(
                       name, scheduled_for, scheduled_until)
                   Alert operator (PRIORITY_HIGH)
               Informational only. Does NOT block startup.
               TothBot continues normal startup regardless.
               (AR-038)

REST-STAT-005  This endpoint uses the Kraken Status page
               API, not the trading API base URL. No
               API key required. No nonce required.
               Uses standard aiohttp GET request with
               the same ClientSession and timeout config.

REST-STAT-006  On error or timeout:
               Log MAINTENANCE_CHECK_FAILED. Do not retry.
               Continue startup normally. The maintenance
               check is informational — failure does not
               block trading.

------------------------------------------------------------
4.7 QueryOrdersInfo
------------------------------------------------------------

REST-QOI-001   Purpose: Targeted single-order reconciliation.
               Used when Position Mirror has a specific
               order_id that needs current status without
               fetching all open orders. (AR-031)

REST-QOI-002   Endpoint:
                 POST https://api.kraken.com/0/private/
                      QueryOrders
               Authentication: Required (TRADE key).
               Request body:
                 nonce=[nonce]
                 txid=[order_id_1,order_id_2,...]
                 trades=true

REST-QOI-003   Response format (success):
               Same structure as GetOpenOrders result,
               containing only the queried order_ids.

REST-QOI-004   Use cases:
               (a) When a specific order_id is in ambiguous
                   state in Position Mirror and a full
                   GetOpenOrders would be excessive
               (b) During manual reconciliation if WS
                   execution events were missed for a
                   specific order
               (c) Verifying TP or emergSL order status
                   after a restated exec_type event

REST-QOI-005   On error response:
               Log REST_ERROR(endpoint=QueryOrdersInfo,
               txid=order_ids, errors=error[]).
               Fall back to GetOpenOrders for full
               reconciliation.

5. ERROR HANDLING — GENERAL RULES
============================================================

REST-ERR-001   All REST responses include an error[] array.
               A non-empty error[] indicates a failed call.
               An empty error[] with a result field
               indicates success.

REST-ERR-002   Known Kraken error prefixes:
                 EGeneral:    General errors
                 EAPI:        API key / auth errors
                 EOrder:      Order-related errors
                 ETrade:      Trade-related errors
                 EQuery:      Query errors
                 EService:    Service unavailable

REST-ERR-003   EAPI:Invalid key — API key error.
               Log CRITICAL. Alert operator immediately.
               Do not retry. TothBot cannot operate
               without valid API keys.

REST-ERR-004   EService:Unavailable — Kraken service down.
               Log WARN. Retry after 5 seconds, up to
               3 attempts. If all fail: treat as maintenance
               condition, alert operator.

REST-ERR-005   Rate limit errors (EAPI:Rate limit exceeded):
               Log WARN with endpoint and timestamp.
               Back off 5 seconds before retry.
               Escalate alert if rate limit hit more than
               3 times in one session — indicates systematic
               over-use requiring CIATS review.

REST-ERR-006   All REST errors are logged with:
                 endpoint name
                 request parameters (nonce, pair, etc.)
                 full error[] array
                 timestamp (UTC)
               Never swallow REST errors silently.

6. FIVE CODING-READINESS QUESTIONS
============================================================

(1) WHAT DOES THIS COMPONENT DO?
    Specifies all Kraken REST API endpoints used by
    TothBot V2. Defines request formats, authentication,
    response parsing, error handling, and behavioral rules
    for all 7 REST endpoints. Is the authoritative REST
    wire contract consumed by WS Manager (1011002) and
    Startup Sequence (1011014) implementations.

(2) INTERFACES:
    Caller: WS Manager (1011002) via shared aiohttp
            ClientSession
    Caller: Startup Sequence (1011014) for warmup and
            initial reconciliation
    Caller: Regime Engine (1011012) for GetOHLCData
            daily computation
    Outputs to:
      Position Mirror (via GetOpenOrders reconciliation)
      Portfolio balance state (via GetAccountBalance)
      Regime Engine input (via GetOHLCData OHLC data)
      WS Manager token store (via GetWebSocketsToken)
      Logger (all calls and errors logged)

(3) HARD RULES:
    REST-AUTH-002: Spot REST auth unchanged (HMAC-SHA512)
    REST-HTTP-001: aiohttp only — no synchronous requests
    REST-HTTP-002: Explicit timeout and connector MANDATORY
    REST-OHLC-004: response[-1] EXCLUDED always (CRITICAL)
    REST-OHLC-007: 1.1s stagger between OHLC calls
    REST-KEY-002:  Both API keys IP-whitelisted to VPS
    REST-CAO-004:  CancelAllOrders EMERGENCY ONLY
    REST-BAL-004:  Spot wallet only (no futures/staking)
    REST-WST-004:  Fresh token on every reconnect
    REST-ERR-006:  All REST errors logged — no silent drops

(4) TRIGGERS AND TRIGGER CHAIN:
    GetWebSocketsToken: triggered at startup and on every
      private WS reconnect.
    GetOHLCData: triggered at 00:00 UTC (daily regime)
      and at startup (warm-up seeding).
    GetOpenOrders: triggered on executions sequence gap
      or startup reconciliation fallback.
    GetAccountBalance: triggered on balances sequence gap
      or startup reconciliation fallback.
    CancelAllOrders: triggered only by explicit operator
      emergency action.
    Status API: triggered once at startup.
    QueryOrdersInfo: triggered on specific order
      ambiguity in Position Mirror.

(5) WHAT DOES IT LOG?
    Every REST call (endpoint, params, timestamp)
    Every REST response error[] (CRITICAL if EAPI auth)
    GetWebSocketsToken success/failure + token expiry
    GetOHLCData fetch per pair (pair, interval, count)
    GetOHLCData failure (pair, retry outcome)
    GetOpenOrders reconciliation (before/after PM state)
    GetAccountBalance reconciliation (before/after balance)
    CancelAllOrders activation (CRITICAL + count)
    Status API maintenance windows detected
    QueryOrdersInfo calls and results
    All rate limit hits (endpoint, timestamp)
    All retry attempts (endpoint, attempt number)
