1. PURPOSE
============================================================

This document is the Sub-Domain Anchor for AA=08 Sub-Domain
1 — Trading_System_Modules. It anchors the instance
documents that specify TothBot V2 trading module rules to
the Trading System Domain Document (0800000).

This document defines the governance chain, the scope
boundary of Sub-Domain 1, and the mandatory reading and
dependency order for all instance documents in this
sub-domain.

3. SUB-DOMAIN 1 SCOPE
============================================================

Sub-Domain 1 (Trading_System_Modules) governs:

  - Long Module entry dispatch rules and order lifecycle
  - Short Module entry dispatch rules and order lifecycle
  - Selection Controller 6-gate quality filtering rules
  - Exit Controller 3-layer exit architecture and rules
  - Entry Limit Placement price computation rules
  - Position protection (TP + emergSL) placement rules
  - Cancel timeout fallback rules
  - MPP IOC retry rules
  - CIATS Trade Outcome Bus reporting rules

Sub-Domain 1 does NOT govern:

  - WS connection management (AA=05, 0511001)
  - SSS signal computation (AA=07, 0711001)
  - Regime classification (AA=07, 0711002)
  - Asset universe selection (AA=07, 0711003)
  - Risk sizing formulas (AA=06, 0611001)
  - Drawdown circuit breaker thresholds (AA=06, 0611002)
  - Kraken WS v2 wire protocol formats (AA=04, 0411001)

NOTE: Exit Controller 3-layer exit architecture and rules,
Cancel timeout fallback rules, and MPP IOC retry rules are
canonically encoded in 0500000 System_Architecture_Overview
§8 (AR-077 cancel_timeout_window FP/DP derivation; AR-078
mpp_retry_count FP/DP derivation; AR-079 Full Halt
batch_cancel architectural decision) and Diagram body per
DD-001/DD-002 diagrams-as-canonical-design-documents and
DD-012 v2_38 AMENDMENT A 0500000-canonical-all-docs scope.
The retired 0811003 Exit_Controller_Specification dv1_0
previously held the AA=08 spec for these rules; per DEC-012
retirement-campaign methodology, 0500000 is now the
canonical source. The Sub-Domain 1 scope statement above
identifies these as Sub-Domain 1 governance topics; the
authoritative spec source for each is 0500000.

NOTE: Entry Limit Placement price computation rules are
canonically encoded in 0500000 System_Architecture_Overview
§8 (AR-069 entry_limit_price = candle close quantized DOWN
to price_increment) and Diagram body per DD-001/DD-002 +
DD-012 v2_38 AMENDMENT A. The retired 0811004 Entry_Limit_
Placement_Specification dv1_1 previously held the AA=08
spec for these rules; per DEC-012 retirement-campaign
methodology, 0500000 is now the canonical source. The
Sub-Domain 1 scope statement above identifies Entry Limit
Placement as a Sub-Domain 1 governance topic; the

NOTE: Long Module entry dispatch rules and order lifecycle
are canonically encoded in 0500000 System_Architecture_
Overview Tier 1 Context (mod:Long_Module structured tag
line 2332-2352 with canonical / tier / parent_diagram /
drill_targets / constraints / consumes / produces fields),
D2 Trading Pipeline (mod:Long_Module dispatch context),
and D7 Dispatch Seam (mod:Long_Module labeled group
lm_above_seam with emergency-IOC arrow through seam) per
DD-001/DD-002 diagrams-as-canonical-design-documents and

AR-006 add_order construction, AR-007 batch_add TP+emergSL
on fill, AR-008 R:R from actual fill price, AR-002 cl_ord_id
at dispatch, AR-053 Pending Order Registry, and AR-054
Partial Fill Protection are all canonical AR identifiers

retirement-campaign methodology, 0500000 is now the

identifies Long Module entry dispatch as a Sub-Domain 1
governance topic; the authoritative spec source is
