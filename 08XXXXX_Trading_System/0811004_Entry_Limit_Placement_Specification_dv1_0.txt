ENTRY LIMIT PLACEMENT SPECIFICATION
============================================================

============================================================
1. PURPOSE
============================================================

This document is the complete specification for entry limit
price placement in TothBot V2. It defines how the
entry_limit_price is computed from the 5-minute candle
close price, how it is quantized to Kraken's
price_increment, and the rationale for these rules.

The entry_limit_price computation is one of the last steps
before Long Module dispatch. It runs after Gate 8 Position
Sizer authorization and before add_order construction.

This document is the authoritative parent for entry limit
placement in AA=10 coding specifications.

4. WHAT ENTRY LIMIT PLACEMENT DOES
============================================================

Input:  candle_close (Decimal) from the triggering 5-minute
        ohlc(5m) close event.
        price_increment (Decimal) for this symbol from the
        instrument channel snapshot (per-symbol, per-pair).
Output: entry_limit_price (Decimal) — the limit_price field
        value submitted in the add_order message.

Computation: entry_limit_price = candle_close quantized
DOWN to the nearest price_increment.

============================================================
5. ENTRY LIMIT PRICE RULE (AR-069)
============================================================

ELP-001  entry_limit_price basis: candle_close price from
         the triggering ohlc(5m) close event.

ELP-002  Quantization direction: ROUND_DOWN to nearest
         price_increment.
           entry_limit_price = Decimal(str(candle_close)
             ).quantize(price_increment, rounding=ROUND_DOWN)

ELP-003  price_increment source: instrument channel snapshot.
         Stored in per-symbol instrument cache by WS Manager.
         Retrieved at pipeline start (pre-computation cache
         read, I-2). Never re-fetched mid-pipeline.

ELP-004  price_increment is Kraken's tick size for the pair.
         Varies by pair (e.g., BTC/USD: 0.1, SOL/USD: 0.01).
         Referred to as tick_size in some Kraken documentation.
         In instrument channel: field name is price_decimal_places
         or price_increment depending on API version.
         TothBot V2 uses the value as derived from 0411001
         Kraken_WS_v2_Specification Section on instrument
         channel (GAP-C).

ELP-005  ROUND_DOWN rationale:
         Rounding DOWN ensures the entry limit is at or
         below the candle close. This avoids submitting a
         limit price that is slightly above the current
         market (which could cause an immediate taker fill,
         defeating post_only protection).
         ROUND_DOWN is the conservative direction for a
         buy limit order — it is less likely to cross the
         spread than ROUND_UP.

ELP-006  Candle close rationale (AR-069):
         The SSS signal is evaluated at candle close. The
         candle close price is the most recent confirmed
         price at signal evaluation time. Entering at or
         below the candle close is consistent with the
         momentum signal — entry is sought at the same
         price level that triggered the signal.
         Alternative approaches considered and rejected:
           - best_ask: would change continuously, creating
             race condition between signal and order.
           - mid price: split between bid and ask, not a
             clean price level relative to the candle.
           - candle open: stale — from 5 minutes ago.
           - last trade price: same as close in practice
             but semantically less precise.
         Candle close is the correct, deterministic basis.

============================================================
6. QUANTIZATION PRECISION
============================================================

ELP-007  All computations use Python Decimal module.
         candle_close from ohlc event: Decimal(str(close)).
         price_increment from instrument cache: Decimal
         (already stored as Decimal in cache).
         No float arithmetic in price computation.

ELP-008  The quantized price MUST be validated as positive
         and > 0 before dispatch. A zero or negative
         entry_limit_price is a system error. Log and abort.

ELP-009  Example computation:
           candle_close    = Decimal("67234.7")
           price_increment = Decimal("0.1")
           entry_limit_price = Decimal("67234.7")
             .quantize(Decimal("0.1"), rounding=ROUND_DOWN)
           entry_limit_price = Decimal("67234.7")

           candle_close    = Decimal("67234.73")
           entry_limit_price = Decimal("67234.7")
           (Rounds DOWN from 67234.73 to 67234.7)

============================================================
7. INTERFACES
============================================================

7.1 From WS Manager (ohlc event)
  Receives: candle_close as float from ohlc(5m) close event.
  Converts: Decimal(str(candle_close)) immediately.

7.2 From Instrument Cache (WS Manager)
  Receives: price_increment (Decimal) for this symbol.
  Retrieved: from pre-computation cache read at pipeline
  start (I-2). Already a Decimal in cache.

7.3 To Long Module (0811001)
  Provides: entry_limit_price (Decimal) for add_order
  construction (limit_price field).
  Also used: by SC-GATE-5 in Selection Controller for
  position size viability check (qty * entry_limit_price
  >= cost_min).

7.4 To Logger (0511006)
  Logs: ENTRY_PRICE_COMPUTED event.

============================================================
8. HARD RULES
============================================================

HR-ELP-001  entry_limit_price MUST be derived from
            candle_close (ohlc close price) only.
            Never from best_ask, best_bid, mid, or
            any other price source.

HR-ELP-002  Quantization MUST use ROUND_DOWN.
            Never ROUND_UP or ROUND_HALF_UP for entry
            limit price. Buy limits round DOWN.

HR-ELP-003  price_increment MUST come from the instrument
            channel snapshot for this specific symbol.
            Never hardcoded per-pair. Never assumed.
            price_increment varies by pair.

HR-ELP-004  All price values MUST use Decimal arithmetic.
            Decimal(str(float_value)) on all WS message
            numeric inputs. No float in price computation.

HR-ELP-005  entry_limit_price MUST be validated > 0 before
            dispatch. Zero or negative = system error.
            Log and abort dispatch for this pair.

============================================================
9. CIATS PARAMETERS
============================================================

  entry_limit_basis: candle_close
    This is an architectural decision, not a numeric
    parameter. CIATS does not own the price basis.
    Changing the entry limit basis is an architectural
    change requiring document revision, not a CIATS
    parameter update.

  No numeric CIATS parameters in this specification.
  entry_limit_price is fully determined by candle_close
  and price_increment — both externally sourced.

10. WHAT IT LOGS
============================================================

  ENTRY_PRICE_COMPUTED  — symbol, candle_close,
                          price_increment,
                          entry_limit_price (quantized)
  ENTRY_PRICE_INVALID   — symbol, computed_price (CRITICAL)

============================================================
11. FIVE CODING-READINESS QUESTIONS
============================================================

(1) What does Entry Limit Placement DO?
    Computes entry_limit_price = candle_close quantized
    DOWN to price_increment. Returns a single Decimal
    value used as the limit_price in add_order.

(2) What are its interfaces?
    FROM: WS Manager (candle_close from ohlc event),
    instrument cache (price_increment).
    TO: Long Module (entry_limit_price for add_order),
    Selection Controller Gate 5 (for viability check),
    Logger.

(3) What are its hard rules?
    candle_close as basis only. ROUND_DOWN quantization.
    price_increment from instrument snapshot, not hardcoded.
    Decimal arithmetic throughout. Validate > 0 before use.

(4) What triggers it and what does it trigger?
    Triggered by Gate 8 authorization (every pipeline
    evaluation that passes Gates 1-8).
    Triggers: Long Module add_order construction.

(5) What does it log?
    ENTRY_PRICE_COMPUTED (every successful computation).
    ENTRY_PRICE_INVALID (CRITICAL, if zero or negative).
