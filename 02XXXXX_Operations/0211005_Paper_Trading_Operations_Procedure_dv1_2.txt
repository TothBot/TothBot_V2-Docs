============================================================
PAPER TRADING OPERATIONS PROCEDURE
============================================================

============================================================
1. PURPOSE
============================================================

This document defines the complete paper trading phase
operational procedure for TothBot V2. Paper trading is
the mandatory validation gate before any live capital is
deployed. No live trading begins until the paper trading
acceptance criteria in Section 6 are satisfied.

Paper trading uses live Kraken market data and runs the
complete TothBot V2 system — all 8 pipeline gates, all
CIATS functions, all exit logic — but intercepts order
dispatch and simulates fills rather than placing real
orders on Kraken. The Logger records all events as if
trading were live. CIATS accumulates real statistical
data during paper trading.

Paper trading mimics all aspects of live trading EXACTLY
per TB00128 Ratified Decision D-06 and 0511001 dv1_5 ADR
§18 TRUE PAPER-LIVE PARITY. This is not a preference —
it is an architectural invariant enforced at every
boundary. The tradeable universe in paper mode is
IDENTICAL to the tradeable universe in live mode (USD,
USDC, or USDT quoted Kraken spot pairs satisfying
0711003 dv1_3 AS-001 criteria, no top-N cap). The
startup sequence in paper mode executes ALL ELEVEN
steps of 0511001 dv1_5 §4.2 (Step 1 through Step 11)
identically to live mode, governed by PT-MODE-005
below. The minimum divergence set between modes is
restricted to four specific points enumerated in
PT-MODE-001. Any deviation from this divergence-set
constraint is a defect.

The purpose of the paper trading phase is threefold:
  (1) Validate that TothBot V2 executes correctly against
      live market data.
  (2) Accumulate the 200-trade minimum statistical floor
      required for CIATS to activate fully.
  (3) Confirm starting parameters produce expected outcomes
      before real capital is at risk.

3. PAPER TRADING MODE
============================================================

------------------------------------------------------------
PT-MODE-001  EXECUTION MODE DEFINITION
------------------------------------------------------------

Paper trading mode: TothBot V2 runs with a configuration
flag that activates simulated order execution. Under D-06
TRUE PAPER-LIVE PARITY (0511001 dv1_5 ADR §18), paper mode
shares ONE execution code path with live mode. The minimum
divergence set is restricted to four points enumerated in
PT-MODE-005 below.

In paper trading mode:

  LIVE (identical to live mode):
            All Kraken WS connections (public shards AND
            private). Private WS authentication via TRADE
            key. All subscriptions (instrument, status,
            ohlc, ticker, executions, balances) active.
            All market data is real-time live data. All
            pipeline gate evaluations execute in full.
            All CIATS monitoring and analysis runs in
            full. All Logger records are written in full.
            All connection-health monitoring (ping, zombie
            detection, sequence-gap detection,
            ratecounter) runs in full on every connection
            including private. All reconnect logic (per-
            shard and private) runs in full.

  SIMULATED (the four divergence points):
            (1) Order dispatch — six methods (add_order,
                batch_add, cancel_order, amend_order,
                batch_cancel, dispatch_market_sell) gate
                on paper_mode at entry. Paper simulates
                locally; no outbound private-WS order
                traffic. Live transmits via _send_private.
            (2) Capital-ledger initialization source —
                paper initializes spot_usd_balance and
                portfolio_baseline_USD from
                paper_starting_balance ($1,000 per D-05).
                Live initializes both from snap_orders
                spot_usd_balance.
            (3) snap_orders Mirror handling — paper LOGS
                snap_orders / snap_trades for parity-of-
                data-path verification but does NOT
                populate paper Position Mirror from them.
                Paper Mirror is populated EXCLUSIVELY by
                the local simulated-fill path. Live
                reconciles real Mirror against snap_orders
                normally.
            (4) Capital-ledger update source — paper
                updates spot_usd_balance from simulated-
                fill P&L applied locally. Live updates
                from balances events.

  SIMULATED FILLS: When TothBot would have dispatched an
            entry order, a simulated fill is generated at
            the entry limit price by the local
            _simulate_entry_fill helper. The Position
            Mirror is updated as if a real fill occurred
            via the SAME Execution Engine entry-fill
            callback that a real Kraken executions event
            would invoke in live mode. TP and emergSL
            prices are computed from the simulated fill
            price using the actual R:R formula. No
            resting orders are placed on Kraken.

  SIMULATED EXITS: When an exit condition triggers
            (Layer 1a signal, Layer 1b TP via paper-fill
            detection, Layer 2 MAE threshold, Layer 3
            emergSL price breach via paper-fill detection),
            the exit is simulated at the relevant price
            (TP price for Layer 1b, bid price for Layer
            1a / Layer 2 market-sell, emergSL price for
            Layer 3). Net P/L is computed locally with
            full fee application using FEE_MAKER_PCT
            and FEE_TAKER_PCT (CIATS-owned starting
            values aligned with Kraken's published
            spot-trading fee schedule).

------------------------------------------------------------
PT-MODE-002  PAPER TRADING CONFIGURATION FLAG
------------------------------------------------------------

A single configuration parameter controls paper trading
mode: paper_trading_mode = True/False.

This flag is set in the EnvironmentFile (/root/.tothbot.env)
before TothBot starts. It is never changed during a running
session. Starting with paper_trading_mode = True and
switching to False requires a full TothBot restart.

The flag must be logged at startup (PAPER_TRADING_MODE_ON
or PAPER_TRADING_MODE_OFF) so that all Logger records are
unambiguously tagged as paper or live. CIATS Trade Outcome
Bus records must carry a paper_trade: bool field.

------------------------------------------------------------
PT-MODE-003  PRIVATE WS CONNECTION IN PAPER MODE
------------------------------------------------------------

TothBot V2 connects to the Kraken private WS in paper
trading mode IDENTICALLY to live trading mode (D-06 TRUE
PAPER-LIVE PARITY; 0511001 dv1_5 ADR §18). The private WS
connection is established at startup Step 9 and re-
established on every private-WS reconnect in BOTH modes.

API key usage:
  DATA key:    Public WS subscriptions and REST market
               data calls (GetOHLCData, REST Ticker).
               Used in BOTH modes.
  TRADE key:   Private WS authentication
               (GetWebSocketsToken). Used in BOTH modes.
               Both modes acquire a WS auth token via
               REST GetWebSocketsToken using the TRADE
               key, and use that token to authenticate
               the private WS connection.

The TRADE key has both order-dispatch capability and read
capability. In paper mode, the order-dispatch capability is
gated at the §13.2 dispatch boundary in WSManager (six
methods only) — paper simulates locally; no outbound order
messages are transmitted on the private WS. The read
capability is exercised in paper mode for parity-of-data-
path verification: executions and balances events are
received and processed by the same handlers that run in
live mode.

Private-WS data-path behavior in paper mode:
  - WS auth token acquired via GetWebSocketsToken (TRADE
    key) — IDENTICAL to live mode.
  - Private WS connection established — IDENTICAL.
  - executions channel subscribed with full subscription
    flags (ratecounter, snap_orders, snap_trades,
    order_status) — IDENTICAL.
  - balances channel subscribed — IDENTICAL.
  - Receive loop, JSON ping, zombie monitor, sequence-gap
    detection, ratecounter monitoring — IDENTICAL on
    private WS.
  - snap_orders / snap_trades responses are LOGGED
    (event SNAP_ORDERS_RECEIVED_PAPER) but do NOT
    populate paper Position Mirror (paper Mirror is
    populated only by the local simulated-fill path per
    PT-MODE-006).
  - balances events are LOGGED (event
    BALANCES_EVENT_PAPER_LOGGED) but do NOT overwrite
    the synthetic paper spot_usd_balance (paper balance
    is updated only by simulated-fill P&L per PT-MODE-007).
  - executions events that may arrive (e.g., from real
    Kraken activity by the operator outside TothBot) are
    LOGGED at INFO but do NOT populate paper Position
    Mirror.

Rationale: paper-mode validation of the private-WS data
path catches defects in token acquisition, private
connect, executions/balances subscribe, sequence-gap
detection, snap_orders parsing, ratecounter, private
ping, private zombie detection, and private reconnect
BEFORE live capital is at risk. Validation of these
paths is the entire purpose of paper trading; partial
validation defeats that purpose. (Closes the dv1_1
PT-MODE-003 internal contradiction in which paper was
described as connecting private WS but using DATA key
— private WS authentication requires the TRADE key per
HR-WM-001.)

------------------------------------------------------------
PT-MODE-004  PORTFOLIO BASELINE IN PAPER MODE
------------------------------------------------------------

In paper trading mode, portfolio_baseline_USD is set from
paper_starting_balance ($1,000 per D-05 / TB00001 line 51)
at startup Step 11. Live mode initializes
portfolio_baseline_USD from snap_orders spot_usd_balance.

Rationale: paper mode does not place real orders against
the operator's Kraken account. Real Kraken balance
therefore does NOT change in paper mode (no real fills).
If portfolio_baseline_USD were sourced from real Kraken
balance in paper mode, drawdown would be computed against
a static value that never moves, making drawdown
monitoring meaningless. The synthetic $1,000 baseline
is the only value that produces a meaningful drawdown
metric for paper-mode operation.

D-05 prescribes $1,000 as the paper starting capital
because $1,000 is also the planned funding amount for
the live-mode account at first activation (per TB00001
business plan). With paper starting capital matched to
live starting capital, the drawdown thresholds (5%
session pause / 10% full halt) calibrate identically in
both modes — the absolute dollar threshold (5% × $1,000
= $50; 10% × $1,000 = $100) is the same.

portfolio_baseline_USD is set ONCE at startup Step 11
and is NEVER updated or reset on reconnect (HR-WM-011 of
0511001 dv1_5; HR-WM-013 of 1011002 dv1_26) — same rule
in both modes.

If Bill changes paper_starting_balance via config edit
between sessions, the new value takes effect at next
TothBot restart. Mid-session changes are not permitted
(HR-PT-004).

(Closes the dv1_1 PT-MODE-004 contradiction with
0511001 dv1_5 HR-WM-011 / HR-WM-034 which mandate
paper baseline from paper_starting_balance.)

PT-MODE-005  PAPER-MODE STARTUP PARITY BINDING
------------------------------------------------------------

Paper-mode startup executes IDENTICALLY to live-mode
startup through ALL ELEVEN steps of 0511001 dv1_5 §4.2
(Step 1 through Step 11). There is NO paper-mode skip
of any startup step. The minimum divergence set is
restricted to two startup-time points enumerated in
PT-MODE-001 — capital-ledger initialization source
(Step 11) and snap_orders Mirror handling (Step 11) —
both confined to Step 11 only.

Enforcement references (paper-mode MUST mirror live-mode):

  0511001 dv1_5 HR-WM-026
    "TRUE PAPER-LIVE PARITY (D-06). Paper mode and live
    mode share ONE execution code path. The eleven
    startup steps (§4.2 Step 1 through Step 11) all
    execute in BOTH modes. There is NO paper-mode skip
    of any startup step. ... The minimum divergence set
    is restricted to four specific points enumerated in
    §13.1."

  0511001 dv1_5 HR-WM-021
    "paper_mode is read once from config at __init__.
    Defaults False. Cannot change at runtime. Under
    D-06 TRUE PAPER-LIVE PARITY (HR-WM-026), paper_mode
    governs ONLY the four divergence points enumerated
    in §13.1: (1) The order-dispatch boundary (six
    methods in §13.2); (2) Step 11 capital-ledger
    initialization source; (3) Step 11 + reconnect
    snap_orders Mirror handling; (4) Capital-ledger
    update source."

  0711003 dv1_3 HR-AS-010
    "Paper mode executes AS-004 Steps 1 through 8
    IDENTICALLY to live mode. Skipping any step in paper
    mode is a defect."

Paper-mode startup ordering (must match live-mode exactly
per the rules above) — eleven steps:

  Step 1  Acquire WS auth token via REST
          GetWebSocketsToken using TRADE API key.
          BOTH modes (private WS connects in both modes
          per D-06).
  Step 2  Connect public WS shards (provisional
          N_conns=1; final N_conns at Step 5a).
          IDENTICAL.
  Step 3  Subscribe instrument channel on shard 0.
          Build per-pair status cache. Compute
          tradeable_universe per 0711003 dv1_3 AS-001
          (USD/USDC/USDT quote + online status + AS-001
          candidate list). IDENTICAL.
  Step 4  REST Ticker call for AS-001 candidates;
          apply $500k/day USD volume filter; build
          final tradeable_universe. Add regime_anchor
          handle (BTC/USD; member of tradeable_universe
          under D-03 amended; default Gate 1 excludes
          BTC/USD from entry-evaluation per AR-074 /
          HR-AS-009). IDENTICAL.
  Step 5  Subscribe status channel on shard 0.
          IDENTICAL.
  Step 5a SHARDING: compute final N_conns, connect
          shards 1..N_conns-1, build pair_to_shard_index
          mapping. IDENTICAL.
  Step 6  Subscribe ohlc(5m) for each pair in
          tradeable_universe. ohlc(60m) NOT subscribed
          via WS (Kraken WS v2 rejects second ohlc
          interval); 1H HTF cache seeded via REST in
          Step 8. IDENTICAL.
  Step 6.5 Silent-pair handling: per-pair state machine
          for SUBSCRIBED → DATA_READY / DATA_PENDING.
          IDENTICAL.
  Step 7  Subscribe ticker channel for tradeable_universe
          pairs (event_trigger:trades initially).
          IDENTICAL.
  Step 8  Indicator warm-up via REST GetOHLCData (5m,
          60m, daily for regime_anchor). IDENTICAL.
  Step 9  Connect private WS using token from Step 1.
          BOTH modes.
  Step 10 Subscribe executions channel (with
          ratecounter:true, snap_orders:true,
          snap_trades:true, order_status:true) and
          balances channel. Begin sequence-gap
          detection. IDENTICAL on both modes (paper
          subscribes for parity-of-data-path).
  Step 11 Process snap_orders / snap_trades response.
          DIVERGENCE POINT (1 of 2 startup-time
          divergence points):
            LIVE: reconcile Position Mirror against
              snap_orders, populate Pending Order
              Registry, capture spot_usd_balance from
              balances snapshot, set
              portfolio_baseline_USD =
              spot_usd_balance.
            PAPER: log SNAP_ORDERS_RECEIVED_PAPER at
              INFO; do NOT populate paper Position
              Mirror; set spot_usd_balance =
              paper_starting_balance ($1,000 per
              D-05); set portfolio_baseline_USD =
              spot_usd_balance; log
              PAPER_BALANCE_SET.

Paper-mode bypass of ANY Step 1-11 requirement (other
than the Step 11 divergence above) is a defect matching
the OI-072 root cause and must be treated as a session-
halting condition.

Paper-mode startup MUST log PAPER_TRADING_MODE_ON with
a payload confirming each step completed against the
live-parity reference. The log entry schema (dv1_2
update):

  event:                  PAPER_TRADING_MODE_ON
  paper_trade:            True
  parity_binding:         0511001_dv1_5_HR-WM-026
  universe_source:        0711003_dv1_3_AS-001
  universe_scope:         ["USD", "USDC", "USDT"]
  top_n_cap:              null  (retired per D-08)
  regime_anchor:          "BTC/USD"
  regime_anchor_eval:     "CIATS-owned, default-disabled"
  steps_executed:         [1, 2, 3, 4, 5, "5a", 6, "6.5",
                           7, 8, 9, 10, 11]
  step_11_capital_source: "paper_starting_balance"
  step_11_balance_usd:    1000  (or configured value)
  private_ws_connected:   True
  trade_key_used:         True

Any missing step in steps_executed is a defect.

------------------------------------------------------------
PT-MODE-006  PAPER POSITION-MIRROR SOURCING
------------------------------------------------------------

In paper mode, Position Mirror is populated EXCLUSIVELY
by the local simulated-fill path:
  - Entry fills: _simulate_entry_fill (called from the
    paper-mode branch of add_order)
  - TP / emergSL fills: _maybe_paper_fill (called from
    _handle_ticker on every bbo event for symbols with
    open positions)
  - Market-sell exits: dispatch_market_sell paper-mode
    branch

Real Kraken executions events received on the private WS
in paper mode are LOGGED at INFO but do NOT populate or
mutate paper Position Mirror. snap_orders / snap_trades
responses (received at startup Step 11 and on every
private-WS reconnect Step 4) are LOGGED but do NOT
populate paper Position Mirror.

This separation prevents real Kraken positions held by
the operator outside TothBot from contaminating paper-
trading state. Bill may hold manual positions in his
Kraken account during paper-mode operation without
TothBot attempting to manage them.

Cross-references:
  0511001 dv1_5 HR-WM-033
  1011002 dv1_26 HR-WM-033

------------------------------------------------------------
PT-MODE-007  PAPER CAPITAL-LEDGER UPDATE SOURCE
------------------------------------------------------------

In paper mode, spot_usd_balance is updated EXCLUSIVELY
by the local simulated-fill P&L path:

  Entry fill:        spot_usd_balance -= entry_cost_usd
                     where entry_cost_usd =
                     qty * fill_price * (1 + FEE_MAKER_PCT)
  TP fill:           spot_usd_balance += tp_proceeds
                     where tp_proceeds =
                     qty * tp_price * (1 - FEE_MAKER_PCT)
  emergSL fill:      spot_usd_balance += sl_proceeds
                     where sl_proceeds =
                     qty * sl_price * (1 - FEE_TAKER_PCT)
  Market-sell exit:  spot_usd_balance += ms_proceeds
                     where ms_proceeds =
                     qty * current_bid * (1 - FEE_TAKER_PCT)

FEE_MAKER_PCT and FEE_TAKER_PCT are CIATS-owned starting
values aligned with Kraken's published spot-trading fee
schedule (0411003 KRAKEN-FEE-001).

Real Kraken balances events received on the private WS
in paper mode are LOGGED at INFO
(event BALANCES_EVENT_PAPER_LOGGED) but do NOT overwrite
the synthetic paper spot_usd_balance.

drawdown_pct is computed identically in both modes using
the same formula (AR-052 / 0511001 dv1_5 §5.4):

  drawdown_pct = (spot_usd_balance -
                  portfolio_baseline_USD) /
                 portfolio_baseline_USD

The formula is mode-agnostic; only the source of
spot_usd_balance updates differs.

Cross-references:
  0511001 dv1_5 HR-WM-034
  0511001 dv1_5 §13.8 Simulated-Fill P&L Application
  1011002 dv1_26 HR-WM-034
  1011002 dv1_26 §6.13 Paper P&L Application

4. CIATS ACTIVATION SEQUENCE DURING PAPER TRADING
============================================================

CIATS activates in stages during paper trading. These
stages are not optional — they are statistical floors
that cannot be bypassed.

------------------------------------------------------------
PT-CIATS-001  STAGE 1 — EWMA MONITOR ACTIVATION
              (50 cumulative candle evaluations)
------------------------------------------------------------

At 50 cumulative candle evaluations (~4 hours from first
pipeline evaluation):

  EWMA Monitor activates. Three monitoring signals begin
  updating every candle close:
    (1) rejection_rate_by_regime
    (2) rate_counter_by_pair
    (3) ws_roundtrip_latency_ms

  This is MONITORING ONLY. No inference. No proposals.
  No parameter changes. The EWMA Monitor provides early
  warning signals that Bill monitors during paper trading.

  Bill action at Stage 1:
    Review EWMA Monitor signals periodically. Look for
    unusual rejection rate patterns or latency spikes.
    These are signals to investigate, not to act on.

------------------------------------------------------------
PT-CIATS-002  STAGE 2 — PROPOSAL ENGINE ACTIVATION
              (200 closed paper trades)
------------------------------------------------------------

At 200 closed paper trades (HARD FLOOR):

  Statistical Engine activates. All statistical methods
  (Mann-Whitney U α=0.01, Spearman, CUSUM, Sharpe) are
  now valid for inference.

  Proposal Engine activates. CIATS may now generate
  parameter change proposals through the PDCA cycle.

  Half-Kelly position sizing activates. Fixed per_trade_pct
  (5%) is replaced by computed Half-Kelly applied_pct.

  The 200-trade floor is the most important milestone in
  the paper trading phase. All starting parameters should
  be evaluated against actual paper trading performance
  data at this point.

  Bill action at Stage 2:
    Review the first CIATS performance report when the
    200-trade floor is reached. Review any proposals
    generated. If a proposal passes Mann-Whitney U at
    α=0.01 and Bill approves, apply to Parameter Store.
    Note that 200 paper trades are required — simulated
    trades count. At ~1-5 trades/day, this milestone
    takes approximately 40-200 trading days to reach.

------------------------------------------------------------
PT-CIATS-003  STAGE 3 — REGIME LIBRARY ACTIVATION
              (600 closed paper trades, 100+ per bucket)
------------------------------------------------------------

At 600 closed paper trades with 100+ in each regime bucket:

  Regime Library activates. Per-regime parameter
  optimization is now valid. CIATS can generate regime-
  segmented proposals.

  Stage 3 is not a required gate for transitioning to
  live trading (see Section 6). However, reaching Stage 3
  before going live is preferred because it provides the
  most complete picture of strategy performance across
  all market conditions.

  Bill action at Stage 3:
    Review per-regime performance statistics. Identify
    any regime buckets with significantly worse outcomes.
    These may indicate parameter adjustments specific to
    those regimes. Engage CIATS PDCA cycle for regime-
    specific proposals before going live if significant
    issues are identified.

  [ ] No unacknowledged CRITICAL alerts in alerts@tothbot.com
  [ ] Logger queue not approaching capacity
  [ ] Paper trade count progressing
  [ ] No unexpected incident categories from 0211004

  [ ] Review actual win rate vs break-even win rate

  [ ] Review Half-Kelly applied_pct computed value
  [ ] Review any CIATS proposals and decide on each
  [ ] Evaluate whether all acceptance criteria (Section 6)

------------------------------------------------------------

  [ ] All acceptance criteria (Section 6) satisfied

  [ ] All CIATS proposals reviewed and dispositioned

============================================================
6. ACCEPTANCE CRITERIA FOR LIVE TRANSITION
============================================================

All criteria in this section must be satisfied before
TothBot V2 transitions from paper trading to live trading.
Bill evaluates each criterion. No criterion may be waived.

------------------------------------------------------------
PT-AC-001  MINIMUM TRADE COUNT: 200 CLOSED PAPER TRADES
------------------------------------------------------------

Required: 200 closed paper trades minimum.
Rationale: The 200-trade floor is the statistical minimum
for valid inference (SE(win_rate)≈3.5%, SE(Sharpe)≈7.2%).
No live trading before this floor is reached regardless
of how the paper trading period appears.

This is the only hard quantitative gate. All other
criteria are evaluated by Bill using judgment informed
by the data.

------------------------------------------------------------
PT-AC-002  NO CRITICAL DEFECTS
------------------------------------------------------------

Required: No open Critical defects in TothBot V2 code
or configuration. A Critical defect is defined as:
  - Any Layer 3 emergSL fire during paper trading
    (emergSL should never fire in normal operation)
  - Any Position Mirror inconsistency vs expected state
  - Any CIATS Trade Outcome Bus data loss (Logger queue
    full events that dropped Trade Outcome Bus records)
  - Any panic, assertion error, or unhandled exception
    that crashed TothBot more than 3 times in 24 hours
  - Any incorrect R:R computation (net_gain not matching
    expected formula output)
  - Any paper-mode startup step skipped relative to
    PT-MODE-005 parity binding (OI-044 pattern
    recurrence)
  - Any paper-mode universe mismatch vs 0711003 dv1_3
    AS-001 (wrong quote currency set, top-N cap applied,
    volume filter bypassed)

All Critical defects must be identified, root-caused,
fixed, and verified before transitioning to live.

------------------------------------------------------------
PT-AC-003  POSITIVE EXPECTATION CONFIRMED
------------------------------------------------------------

Required: Paper trading data shows positive expectation.
Evaluation: CIATS Statistical Engine output at 200+ trades.

  Minimum acceptable performance (all required):
    Win rate:      ≥ 40% (break-even at net 1:1.5 R:R)
    Realized R:R:  ≥ 1.3 net (allows for market impact)
    Sharpe ratio:  ≥ 0 (non-negative risk-adjusted return)

  These are minimum floors, not targets. A win rate of
  40% and Sharpe of 0 indicates the system is barely
  viable. The decision to go live at minimums vs waiting
  for better performance is Bill's judgment call.

  If any metric is below its floor: do not go live.
  Engage CIATS PDCA cycle to identify and test parameter
  changes. Return to live evaluation after another 50+
  trades under revised parameters.

------------------------------------------------------------
PT-AC-004  CIATS OPERATING CORRECTLY
------------------------------------------------------------

Required: CIATS has completed at least one full PDCA
cycle (Plan → Do → Check → Act or Plan → Reject) after
the 200-trade floor. This confirms CIATS is functioning,
the statistical engine is producing valid output, and
the Logger → CIATS → Parameter Store pipeline is intact.

If CIATS has not triggered a PDCA cycle by 200 trades:
verify CUSUM k and h parameters, verify Trade Outcome
Bus is being populated correctly, verify CIATS asyncio
task is running without exceptions.

------------------------------------------------------------
PT-AC-005  NO OPEN CRITICAL ALERTS
------------------------------------------------------------

Required: No unacknowledged CRITICAL alerts outstanding
at the time of live transition. All incidents from 0211004
are either resolved or have documented disposition.

------------------------------------------------------------
PT-AC-006  BILL FORMAL APPROVAL
------------------------------------------------------------

Required: Bill explicitly approves transition to live
trading after reviewing all acceptance criteria above.
Approval is recorded in the session log with:
  - Date and time of approval
  - Trade count at approval
  - Win rate, realized R:R, and Sharpe at approval

8. LIVE TRANSITION PROCEDURE
============================================================

approved the transition:

  Step 3: Update EnvironmentFile on VPS:
          paper_trading_mode = False

          - logrotate configured and active
          - Both API keys IP-whitelisted
          - systemd service enabled
          - TRADE key credentials confirmed in EnvironmentFile
          - VPS disk space adequate for 90-day log retention

  Step 5: Start TothBot in live mode:
          systemctl start tothbot

  Step 6: Verify startup log shows PAPER_TRADING_MODE_OFF.

          now "TRADE_KEY_FULL" instead of "DATA_KEY_READ_

          Step 7 subscription set is a defect.

  Step 7: Verify first pipeline evaluation log shows
          live order dispatch (not simulated).

  Step 8: Monitor alerts@tothbot.com closely for the
          first 24-48 hours of live operation.

  Step 9: Record transition date and time in session log.

  HR-PT-001  Paper trading is mandatory before live trading.
             No live capital is deployed without completing
             the paper trading phase and satisfying all
             acceptance criteria.

  HR-PT-002  The 200-trade minimum (PT-AC-001) is absolute.
             No waiver. No exception. Fewer than 200 trades
             is insufficient for valid inference regardless
             of apparent performance.

  HR-PT-003  Any Layer 3 emergSL fire during paper trading
             is a Critical defect (PT-AC-002). Must be
             root-caused and resolved before live transition.

  HR-PT-004  paper_trading_mode flag is never changed during
             a running session. Mode changes require a
             full TothBot restart.

  HR-PT-005  All paper trading Trade Outcome Bus records
             carry paper_trade: True. Live records carry
             paper_trade: False. These are never mixed
             in CIATS statistical computations after
             live trading begins.

  HR-PT-006  Bill formal approval (PT-AC-006) is required
             before live transition. No automated process
             or CIATS output can substitute for this.

  HR-PT-007  The parameter baseline (PT-BASE-001) must be
             documented and approved before live mode is
             activated. It is the immutable reference point
             for all future parameter change tracking.

  HR-PT-008  PAPER-TO-LIVE PARITY BINDING (D-06).
             Paper-mode startup MUST execute 0511001
             dv1_5 §4.2 ALL ELEVEN STEPS (Step 1
             through Step 11) identically to live mode
             per PT-MODE-005. Private WS connects in

             runtime the additional divergences are

             balances events). All other code paths
