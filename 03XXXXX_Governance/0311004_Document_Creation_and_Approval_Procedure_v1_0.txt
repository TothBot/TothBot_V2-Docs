DOCUMENT CREATION AND APPROVAL PROCEDURE
============================================================

============================================================
1. PURPOSE
============================================================

This document defines the procedure for creating, reviewing,
approving, and retiring controlled documents in the TothBot
V2 document control system. It governs how all documents
progress through their lifecycle and defines the standard
template for all new documents.

3.1 STANDARD DOCUMENT TEMPLATE [PL-001 RESOLVED]
------------------------------------------------------------

DC-TMPL-001  All controlled documents MUST begin with
             the 7-field header in exactly this order:

===== MANDATORY HEADER FORMAT =====

DocDCN:     [7-digit DCN, format AABCDDD, no spaces]
DocTitle:   [Title_With_Underscores_No_Spaces]
DocVersion: dv1_1 + major_minor, e.g., dv1_0]
DocOwner:   [Bill]
DocPath:    [GitHub.com/TothBot/TothBot_V2-Docs/FOLDER/FILENAME_VERSION.txt]
DocDate:    04-04-2026
DocTime:    23:59:59 UTC UTC, 24-hour]

===================================

DC-TMPL-002  Following the 7-field header, the standard
             document body structure is:

             ============================================================
             [DOCUMENT TITLE — ALL CAPS]
             ============================================================

             ============================================================
             1. PURPOSE
             ============================================================
             [Why this document exists. What it governs.]

             ============================================================
             2. PARENT CHAIN
             ============================================================
             [Explicit trace to Domain Document via Anchor.]

             ============================================================
             3. MUST BE INCLUDED FROM PREVIOUS ANALYSIS
             ============================================================
             [Present when applicable. See Section 4 of this doc.]

             ============================================================
             4. [CONTENT SECTIONS]
             ============================================================
             [Document-specific content.]

             ============================================================
             N-1. RELATED DOCUMENTS
             ============================================================
             [DCN references to related documents.]

             ============================================================
             N. REVISION HISTORY
             ============================================================
             [Version | Date | Description of change]

             ============================================================
             END OF DOCUMENT
             ============================================================

DC-TMPL-003  DocPath format: the path must exactly match
             the file's location in the repository.
             Folder: matches the DCN's AA domain prefix.
             Filename: [DocDCN]_[DocTitle]_[DocVersion].txt
             Example:
             0311001_Namespace_Specification_dv1_2.txt
             in folder 03XXXXX_Governance/

DC-TMPL-004  DocVersion format:
             dv = working draft (development)
             rv = review version (under review)
             v  = approved/validated
             rt = retired
             Version number: major_minor (e.g., dv1_0,
             dv1_2, rv2_0, v2_1, rt1_0)

DC-TMPL-005  DocDate and DocTime: set to the date and time
             of the version change in UTC. 24-hour format.
             Never use local time. Always use UTC.

------------------------------------------------------------
3.2 WORKING DRAFT EXCEPTION DOCUMENTS
------------------------------------------------------------

DC-WD-001  Working Draft documents created under the WD
           Exception (0311002 Section 1) must include:

           (a) STATUS line after the header stating:
               "Working Draft — Placeholder" or
               "Working Draft — [specific note]"

           (b) A "Must be Included From Previous Analysis"
               section (Section 3) that captures all
               requirements from prior analysis sessions.
               This section is authoritative and must be
               fully implemented in the final approved
               version.

           (c) All other standard template sections, with
               "TBD in Phase X" markers for content not
               yet derivable.

DC-WD-002  WD documents do not require Bill approval for
           creation. They are working documents. Bill
           approves when promoting dv → v (direct approval)
           or rv → v (approval after revision).
