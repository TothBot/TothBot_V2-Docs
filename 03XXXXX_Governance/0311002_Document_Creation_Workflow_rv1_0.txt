============================================================
1. PURPOSE
============================================================

This document defines the mandatory sequenced order in
which all TothBot V2 controlled documents must be created.
It is the authoritative work plan for building the complete
TothBot V2 document set from which the system will be coded.

Sequence is governed by four rules:

  RULE 1 — Domain dependency order.
  Lower AA domain documents must exist before higher AA
  domain documents can be written.

  RULE 2 — Tier dependency order within a domain.
  Domain Document before Sub-Domain Anchor. Anchor before
  Instance Documents in that sub-domain.

  RULE 3 — AA=10 coding spec timing is coupling-gated.
  No AA=10 Coding Specification may be written until its
  parent specification document (AA=04 through AA=08)
  is in approved (v) state, except for Working Draft (dv)
  coding specs created under the WD Exception below.

  WD EXCEPTION — Working Draft Coding Specs:
  Working Draft (dv) placeholder coding specifications may
  be created at any time to capture requirements from
  analysis, validation, or FP/DP sessions before their
  parent specification documents exist. WD coding specs
  carry a "Must be Included From Previous Analysis" section.
  They do not violate document control because they are
  working drafts that will be completed and approved only
  after their parent specifications are in approved (v)
  state. This exception prevents requirement loss.

STEP 8.2.1  CODE FILE REGISTRY — MANDATORY MAINTENANCE RULE
------------------------------------------------------------

1010000 Trading_System_Coding_Anchor Section 5 contains
the Code File Registry. This registry is the formal
controlled link between every Pathway 2 code file (.py)
and its governing AA=10 coding specification.

RULE — CODE FILE REGISTRY UPDATE IS MANDATORY:
After every session in which any Pathway 2 code file
(.py in TothBot_V2-Code) is created or modified, the
Code File Registry in 1010000 Section 5 MUST be updated
before the session closes. The registry must reflect:

  (1) The correct governing coding spec DCN and title
      for every code file.
  (2) The current version of the governing coding spec
      at the time of the code change.
  (3) The git commit hash of the code file after the
      session's commit to TothBot_V2-Code.
  (4) The date of the registry update (UTC).

Failure to update the Code File Registry before session
close is a document control violation equivalent to any
other 7-field header violation — it breaks the formal
traceability chain between specifications and code.

This rule applies retroactively from Phase 8 start.
The Code File Registry was not created at Phase 8 start.
This is the corrective action establishing it formally.

CHANGE 2 — Section 2.3 API Rate Limits
  ADD row: Amend Order (WS v2) | +1 fixed | +3 (<5s) | +2 (<10s) | +1 (<15s)
  NOTE: amend_order is 43% cheaper than edit_order for
    orders resting <5 seconds (+4 total vs +7 total).
  ADD note: batch_cancel penalty = sum of individual
    cancel costs for n orders.

CHANGE 3 — Section 2.4 WS Operational Requirements
  ADD A-7: WS Ping Strategy:
    WS server disconnects after ~60 seconds of inactivity.
    WS Manager sends {"method":"ping"} on each connection
    every 20-30 seconds. Expects {"method":"pong"} response.
    No pong within 10-second timeout = dead connection.
    Reconnect immediately. This is application-level ping,
    distinct from TCP-level keepalive.
    Cloudflare idle timeout ~100 seconds on Free/Pro plans.
    30-second ping interval clears all known proxy defaults.
    Assign to 0511001 (WS Manager), 1011002 (coding spec).

  ADD A-8: Zombie Connection Detection:
    A WS connection can appear alive (ping/pong working)
    while delivering no real market data. This occurs when
    the upstream stops sending without closing the connection.
    WS Manager tracks last_real_data_time per connection
    using monotonic clock (time.monotonic()). Any real data
    message resets the timestamp. Heartbeat messages alone
    do not reset it — only market data events count.
    If time.monotonic() - last_real_data_time > 90 seconds:
    alert and trigger reconnection.
    Assign to 0511001, 1011002.

  ADD A-9: Balances Channel Sequence Gap Detection:
    Each balances channel message carries a sequence integer.
    WS Manager tracks last-seen sequence number. Any gap
    (sequence jump > 1) indicates missed ledger events.
    On gap: alert immediately, trigger REST GetAccountBalance
    reconciliation to restore accurate capital state.
    Missed balance events cause incorrect available capital
    calculation — direct loss risk.
    Assign to 0511001, 1011002.

  UPDATE executions subscription note:
    snap_orders:true and snap_trades:true are the current
    parameters. snapshot and snapshot_trades are deprecated.
    Use only snap_orders and snap_trades.

CHANGE 4 — Gate 1 / Gate 2 (Pipeline section)
  ADD per-pair status check from instrument channel:
    Gate 1 or Gate 2 must verify per-pair status from the
    instrument channel cache before pipeline evaluation.
    Pairs in the following statuses are NO-ENTRY:
      reduce_only, work_in_progress, delisted, limit_only
    Only pairs in online or post_only status proceed.
    Instrument channel subscription maintained by WS Manager.
    Cache updated on instrument channel events.
    Assign to 0511001, 0511002.

CHANGE 5 — Regime Engine section (Section 5 or equivalent)
  ADD CRITICAL RULE — GetOHLCData Last Entry Exclusion:
    REST GetOHLCData always returns the current not-yet-
    committed candle as the last entry (response[-1]).
    Kraken documentation: "The last entry in the OHLC array
    is for the current, not-yet-committed timeframe, and will
    always be present, regardless of the value of since."
    Regime Engine MUST exclude response[-1] from ALL
    calculations: ADX, EMA(20), EMA(50), ATR(14).
    Only response[:-1] (committed candles) is valid for
    computation. Including a partial candle corrupts all
    regime indicators and produces incorrect regime
    classification.
    Assign to 0711002, 1011012.

    GetOHLCData with auth, GetOpenOrders, GetAccountBalance,
