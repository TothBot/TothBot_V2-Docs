DOCUMENT CREATION AND APPROVAL PROCEDURE
============================================================

============================================================
1. PURPOSE
============================================================

This document defines the procedure for creating, reviewing,
approving, and retiring controlled documents in the TothBot
V2 document control system. It governs how all documents
progress through their lifecycle and defines the standard
template for all new documents.

This procedure applies to ALL controlled documents in both
TothBot_V2-Docs (specification documents) and
TothBot_V2-Code (code and configuration files). All files
in TothBot_V2-Code are controlled documents per
0311001 HR-DC-001.

3.2 CODE FILE DOCUMENT TEMPLATE — TothBot_V2-Code
------------------------------------------------------------

DC-TMPL-003  All files in TothBot_V2-Code are controlled
             documents. They use the same 7-field header
             as TothBot_V2-Docs documents, adapted for
             embedding as a comment block.

===== MANDATORY HEADER FORMAT — TothBot_V2-Code (Python) =====

# DocDCN:     [DCN of governing AA=10 coding spec]
# DocTitle:   [Descriptive_File_Title_Underscores]
# DocVersion: [dv/rv/v + major_minor, e.g., dv1_0]
# DocOwner:   [Bill]
# DocPath:    [github.com/TothBot/TothBot_V2-Code/path/filename]
# DocDate:    [MM-DD-YYYY]
# DocTime:    [HH:MM:SS UTC, 24-hour]

==============================================================

DC-TMPL-003A  FIELD RULES FOR CODE FILE HEADERS:

             DocDCN:
               The DCN of the governing AA=10 coding
               specification for this file.
               Example: ws_manager.py → 1011002
               Example: .gitignore → 1011001
               Example: pytest.ini → 1011001
               Example: requirements.txt → 1011001

             DocTitle:
               Descriptive title of the file.
               Underscores only. No spaces.
               Example: WS_Manager, Git_Ignore_Configuration,
               TothBot_Systemd_Service_Unit

             DocVersion:
               Follows same rules as all controlled docs.
               Starts at dv1_0. Increments on every change.
               Version NOT embedded in filename (unlike
               TothBot_V2-Docs). Git history tracks versions.

             DocPath:
               Full repository path:
               github.com/TothBot/TothBot_V2-Code/[path/file]
               NOT the VPS deploy path (e.g., not
               /etc/systemd/system/tothbot.service).
               NOT the Windows local path.

             DocDate / DocTime:
               Same rules as all controlled documents.
               Update on every version increment.

DC-TMPL-003B  NON-PYTHON FILE HEADERS:
             For non-Python files, use the file's native
             comment syntax. Examples:

             .gitignore (# prefix):
               # DocDCN:     1011001
               # DocTitle:   Git_Ignore_Configuration
               [... remaining fields ...]

             .ini files (# or ; prefix):
               # DocDCN:     1011001
               [... remaining fields ...]

             .service files (# prefix):
               # DocDCN:     1011013
               [... remaining fields ...]

             README.md (no native comment syntax):
               Place the 7-field header as HTML comments
               at the top of the file:
               <!-- DocDCN:     1011001 -->
               <!-- DocTitle:   TothBot_V2_Code_README -->
               [... remaining fields ...]

DC-TMPL-003C  REVISION HISTORY IN CODE FILES:
             Every code file MUST include a Revision
             History section in comment format:

             # ============================================================
             # REVISION HISTORY
             # ============================================================
             #
             #   dv1_0  MM-DD-YYYY  Initial. [brief summary]
             #   dv1_1  MM-DD-YYYY  [what changed]

             The Revision History is cumulative. No entry
             is ever removed.

DC-TMPL-003D  GOVERNING RULES REFERENCE:
             Code file header implementation is further
             governed by 1011001 Engineering_Best_Practices
             BP-HDR-001 through BP-HDR-006. Both this
             document (0311004) and 1011001 apply.
             0311001 Sections 5.1-5.4 define the namespace
             rules. This section defines the template rules.

DC-WD-001    WD Exception documents MUST include the
             standard 7-field header.

           (a) DocVersion must be dv1_0 on creation.

           (b) "Must be Included From Previous Analysis"
               section required:
               This section is authoritative and must be
               fully implemented in the final approved
               version.

           (c) All other standard template sections, with
               "TBD in Phase X" markers for content not
               yet derivable.

DC-WD-002  WD documents do not require Bill approval for
           creation. They are working documents. Bill
           approves when promoting dv → v (direct approval)
           or rv → v (approval after revision).
