============================================================
POSITION MIRROR SPECIFICATION
============================================================

============================================================
1. PURPOSE
============================================================

This document is the system-level specification for the
Position Mirror component of TothBot V2. It defines what
the Position Mirror does, its interfaces, its hard rules,
what triggers it, and what it logs. It is the authoritative
parent document for 1011006 Position_Mirror_Coding_Spec.

The Position Mirror is TothBot's in-memory authoritative
record of all open positions. It is the single source of
truth for what positions TothBot believes it holds at any
moment. Every component that needs to know position state
reads from the Position Mirror.

The Position Mirror is mode-blind by architectural intent.
Per TB00000 v2_20 §4.4 PA-001..010 PAPER-AS-MASTER and
0500000 dv1_24 §12 Paper-Mode Dispatch Boundary
Architecture, paper trading is the empirically-validated
master configuration; live trading is built to MIMIC paper.
The Position Mirror data structure, write helper methods,
read access patterns, hard rules, triggers, and log
emissions are byte-identical between paper and live modes
per §6A PM-PAPER-001. The ONLY physical divergence is the
SOURCE of the data populating Mirror records (PA-004 #4
Position Mirror Sourcing): paper Mirror is populated
EXCLUSIVELY by the local simulated-fill path inside
WSManager (per HR-WM-033 in 0511001 dv1_5); live Mirror is
populated by Kraken executions channel events and
snap_orders reconciliation. Both populate Mirror via the
SAME single writer (WSManager) per HR-PM-009 + new
HR-PM-011, and through the SAME pm helper-method pathway.

============================================================
2. COMPONENT SUMMARY
============================================================

What it does:
  Maintains an O(1) symbol-keyed dict of all open positions.
  Recorded at dispatch (no async gap). Updated on fill,
  partial fill, amendment, and close events. Reconciled
  against Kraken snap_orders on startup and reconnect
  (LIVE MODE ONLY — paper mode has no Kraken-side state
  to reconcile against per §6A PM-PAPER-002). Read by
  Signal Pipeline, Exit Controller, Risk Engine, and
  CIATS EWMA Monitor. Byte-identical Mirror behavior
  between paper and live modes per §6A PM-PAPER-001.

Primary inputs:
  Execution Engine dispatch events (new position record;
    routed via WSManager seam in both modes per 0500000
    dv1_24 §12.3)
  WS executions channel events (fills, amends, closes)
    — LIVE MODE ONLY
  WSManager simulated-fill path (entry fill,
    TP fill detection, emergSL trigger, market sell)
    — PAPER MODE ONLY (per HR-WM-024, HR-WM-033)
  snap_orders response (reconciliation)
    — LIVE MODE ONLY

Primary outputs:
  Read-only access to all components needing position state
  Logger entries on all state changes (mode-agnostic)

Data structure type: dict[str, PositionRecord]
  Key: symbol (str)
  Access: O(1) lookup, O(1) insert, O(1) delete (AR-002)

============================================================
3. DATA STRUCTURE
============================================================

3.1 PositionRecord fields

  symbol:              str     — Kraken pair name (e.g. BTC/USD)
  entry_fill_price:    Decimal — actual fill price (avg_price)
                                 NOT the limit price (AR-008)
  qty:                 Decimal — current position quantity
                                 (cum_qty at time of record)
  tp_order_id:         str     — Kraken-assigned TP order_id
  tp_cl_ord_id:        str     — TothBot-assigned TP cl_ord_id
  emgsl_order_id:      str     — Kraken-assigned emergSL order_id
  emgsl_cl_ord_id:     str     — TothBot-assigned emergSL cl_ord_id
  entry_timestamp_utc: str     — ISO 8601 entry fill time
  entry_atr_14:        Decimal — ATR(14) at entry (for exit calcs)
  asset_regime:        str     — regime at entry time (CIATS tagging)
  market_regime:       str     — BTC/USD regime at entry (CIATS)
  signal_params:       dict    — SSS params at entry (CIATS)
  hold_candle_count:   int     — incremented by WS Manager on
                                 each ohlc(5m) close (L1a-003)

3.2 Design rationale (AR-002)

  Symbol-keyed dict provides O(1) lookup for all hot-path
  operations. The Signal Pipeline checks for open positions
  at Gate 5 SC-GATE-3 on every evaluation. Exit Controller
  reads TP and emergSL order_ids on every exit trigger.
  The ticker drawdown loop reads qty for every open pair.
  All these are O(1) with a symbol-keyed dict. A list or
  ordered structure would be O(n) — unacceptable at 20
  concurrent positions with 288 pipeline evals/day.

3.3 PositionRecord schema extension (cascade citation, dv1_1)

  Per 1011002 dv1_26 §16A.1 WM-PAPER-LEDGER-002 and
  0500000 dv1_24 §12.4 Synthetic Capital Ledger Single-
  Owner Architecture, the PositionRecord schema includes
  a fees_entry_usd: Decimal field populated at entry-fill
  time in BOTH paper and live modes (paper: WSManager
  computes (entry_qty * entry_price * FEE_MAKER_PCT) at
  _simulate_entry_fill; live: 0511003 dv1_1 §5A
  EE-PAPER-005 binds the EE-driven entry fill handler to
  populate from the executions channel fees field).
  Exit Controller consumes fees_entry_usd at exit time
  per 1011005 dv1_3 §10A EC-PAPER-CODE-003(a) — EC does
  NOT recompute entry fees on exit; they are read from
  the PositionRecord. The 1011002 dv1_26 §16A.1 entry is
  the authoritative source-of-truth for the schema-
  extension field. Field-level schema-table updates to
  §3.1 above and to 1011006 Position_Mirror_Coding_Spec
  are OUT OF SCOPE for this parent-spec amendment per
  RR-SCOPE-002 — they live at the AA=10 layer (1011002
  dv1_26 + future 1011006 cascade if and when authored).
  HR-PM-012 (NEW dv1_1) elevates fees_entry_usd field
  population to a hard rule in both modes.

============================================================
4. WRITE RULES — WHEN AND HOW IT IS UPDATED
============================================================

4.1 Record Creation (on entry dispatch)

  Triggered: Execution Engine dispatches add_order for entry.
  Action: WS Manager creates PositionRecord immediately.
  Record created with:
    symbol, entry_limit_price (used as placeholder until fill),
    entry_qty, tp_cl_ord_id (assigned by EE), emgsl_cl_ord_id.
    tp_order_id and emgsl_order_id: empty — populated on
    batch_add ACK from Kraken (after entry fill).
    entry_fill_price: populated on exec_type=filled event.
  Rationale (A-2 record-at-dispatch rule):
    Position Mirror records cl_ord_id at dispatch BEFORE
    Kraken ACK. This eliminates the async gap where a fill
    arrives before the add_order ACK, leaving TothBot with
    an orphaned position. With record-at-dispatch, any
    subsequent fill event is matched immediately.
  Mode parity (PA-005, §6A PM-PAPER-001):
    Record creation occurs identically in paper and live
    modes through the WSManager dispatch seam per 0500000
    dv1_24 §12.3. EE calls WSManager.add_order(); WSManager
    creates the PositionRecord at the dispatch moment
    BEFORE returning, in BOTH modes — paper does NOT skip
    record creation. The seam method is mode-opaque to
    the EE caller per 0511003 dv1_1 §5A EE-PAPER-002.

4.2 Update on Entry Fill (exec_type=filled, entry order)

  Update PositionRecord:
    entry_fill_price = Decimal(str(avg_price))
    qty = Decimal(str(cum_qty))
    entry_timestamp_utc = timestamp from fill event
  Trigger: Execution Engine dispatches batch_add (TP+emergSL).
  After batch_add ACK:
    tp_order_id = Kraken-assigned order_id for TP leg
    emgsl_order_id = Kraken-assigned order_id for emergSL leg
  Mode source — entry fill (PA-004 #4, §6A PM-PAPER-002):
    PAPER MODE: avg_price = entry_limit_price and
      cum_qty = full entry qty originate from
      WSManager._simulate_entry_fill (an
      asyncio.create_task scheduled by WSManager.add_order
      in paper mode per HR-WM-024). Per 1011002 dv1_26
      §16A.1 WM-PAPER-LEDGER-002, WSManager additionally
      populates fees_entry_usd at this entry-fill moment
      using FEE_MAKER_PCT.
    LIVE MODE: avg_price + cum_qty originate from the
      Kraken executions channel exec_type=filled event
      arriving via private WS. Live mode populates
      fees_entry_usd from the executions channel fees
      field per 0511003 dv1_1 §5A EE-PAPER-005.
    Mirror update pathway is byte-identical in both modes
    per HR-PM-009 + HR-PM-010.
  Mode source — batch_add ACK (§6A PM-PAPER-003):
    PAPER MODE: tp_order_id = "PAPER_TP_<cl_ord_id>" and
      emgsl_order_id = "PAPER_SL_<cl_ord_id>" per 0511001
      dv1_5 §13.2 — synthetic IDs assigned locally inside
      the paper batch_add() seam method. No Kraken ACK
      because no Kraken transmission occurred.
    LIVE MODE: tp_order_id and emgsl_order_id =
      Kraken-assigned values from the batch_add ACK on
      private WS.
    Both modes populate Mirror via the same
    pm.update_resting_orders() pathway per 0511003 dv1_1
    §5A EE-PAPER-003.

4.3 Update on TP Partial Fill (exec_type=trade on TP order, AR-066)

  When exec_type=trade arrives with order_id matching
  tp_order_id in Position Mirror:
    remaining_qty = tp_order_qty - Decimal(str(cum_qty))
    Update: qty = remaining_qty
  If remaining_qty < qty_min OR remaining_qty * bid < cost_min:
    Initiate position close sequence (EC handles).
  Do NOT fire CIATS Trade Outcome Bus on partial fill.
  Fire ONCE on full position close (aggregate all fills).
  Mode source (§6A PM-PAPER-002):
    PAPER MODE: TP partial fill is detected locally in
      WSManager._handle_ticker per HR-WM-024 (paper fill
      detection). When ticker ask price >= pos.tp_price,
      WSManager treats this as a TP fill event and
      applies the qty update via the same Mirror write
      helper used in live mode.
    LIVE MODE: exec_type=trade arrives via the Kraken
      executions channel on the private WS.
    The qty-update pathway is byte-identical between
    modes.

4.4 Record Deletion (on position close)

  Triggered by Exit Controller on exit sequence completion
  OR by reconciliation detecting gap-closed position
  (live mode only).
  Action: del position_mirror[symbol]
  Hold_candle_count for symbol reset (counter lives in
  WS Manager state dict, not in PositionRecord — reset
  on same event).
  Selection Controller state updated:
    exit_cooldown_log[symbol] = time.monotonic()
    consecutive_loss_count updated per exit_reason (AR-073).
  Mode parity (§6A PM-PAPER-001, PA-005):
    Record deletion is byte-identical in paper and live
    modes. Exit Controller is the SOLE driver of Mirror
    deletion in BOTH modes per 0511004 dv1_3 HR-EC-013
    + HR-EC-014. WSManager (the sole writer per HR-PM-009)
    performs the physical del operation on Exit
    Controller's instruction. The dv1_25 parallel
    ws_manager._fire_ciats_outcome path (which formerly
    deleted Mirror records in paper mode) is RETIRED
    per 1011002 dv1_26 §16A.2 WM-PAPER-EXIT-005 and
    0511004 dv1_3 §6A EC-PAPER-005. Reconciliation-
    based deletion (gap-closed positions) applies in
    LIVE MODE ONLY per §5.

4.5 Update on amend_order for emergSL (TP partial fill sequence)

  When Exit Controller amends emergSL qty to remaining_qty
  after TP partial fill: update emgsl_order_id if new
  order_id assigned (amend_order may return updated order_id).
  Verify: net_gain = net_loss * 1.5 still satisfied at
  remaining_qty.
  Mode parity (§6A PM-PAPER-001):
    amend_order is a WSManager seam method per 0500000
    dv1_24 §12.3. Mirror update on amend completion is
    byte-identical in both modes. In paper, the amend is
    simulated locally (PAPER_AMEND_SIMULATED log) with
    the Mirror update applied via the same pathway used
    in live mode.

============================================================
5. RECONCILIATION
============================================================

Reconciliation against Kraken snap_orders applies in LIVE
MODE ONLY. Per PA-004 divergence point #4 (Position Mirror
Sourcing) and 0500000 dv1_24 §12.1, paper mode does NOT
connect private WS (HR-WM-022 + PA-004 #1), therefore no
snap_orders event is received and no Kraken-side
reconciliation source exists. Paper Mirror is populated
EXCLUSIVELY by the local simulated-fill path inside
WSManager (HR-WM-033) and is authoritative-by-construction
(it is populated only from the same process that reads
from it). Per §6A PM-PAPER-002.

5.1 At Startup (Step 6) — LIVE MODE ONLY

  After executions subscription returns snap_orders:
  For each order in snap_orders with status new/pending_new:
    If order matches a known Position Mirror entry by cl_ord_id:
      Confirm — no action needed.
    If order is NOT in Position Mirror (unexpected open order):
      Log UNEXPECTED_OPEN_ORDER (WARN). Alert operator.
      Do NOT auto-manage. Operator decides.
  For each symbol in Position Mirror with no matching
  snap_orders entry:
    Position was closed during prior session's gap.
    Log GAP_CLOSED_POSITION.
    Delete from Position Mirror.
    Fire CIATS Trade Outcome Bus with available data.
  PREFERRED reconciliation source: snap_orders:true on
  executions subscription (AR-003). FALLBACK: REST
  GetOpenOrders.

5.2 On Mid-Session Reconnect (AR-056) — LIVE MODE ONLY

  Same reconciliation process as startup Step 6.
  Pre-disconnect Position Mirror state preserved in memory.
  snap_orders compared against pre-disconnect state.
  gap-closed positions detected and processed.
  Pending Order Registry also reconciled.
  portfolio_baseline_USD NOT reset (AR-052).

============================================================
6. READ ACCESS
============================================================

All reads are O(1) symbol lookups. Position Mirror is
read-only from the perspective of all components except
WS Manager (sole writer). No locking required in single-
threaded asyncio event loop. Read access is byte-identical
between paper and live modes per §6A PM-PAPER-001 — the
same record fields are read by the same readers in the
same way. Per HR-PM-011 (NEW dv1_1) all read access goes
through pm helper methods; no module holds direct write
references to position_mirror in either mode.

  Signal Pipeline (Gate 5 SC-GATE-3): symbol NOT in mirror
  Signal Pipeline (Gate 7 Risk Guard): sum of position
    values for drawdown computation
  Exit Controller: tp_order_id, emgsl_order_id, qty,
    entry_fill_price, entry_atr_14, fees_entry_usd
    for exit calculations
  CIATS EWMA Monitor: position count, regime tags
  WS Manager: per-symbol bid price lookup for drawdown MTM
  Execution Engine: confirmation that record exists before
    batch_add dispatch

============================================================
6A. PAPER MODE POSITION MIRROR BEHAVIOR (PM-PAPER) — NEW dv1_1
============================================================

This section specifies how the Position Mirror behaves in
paper mode. Per TB00000 v2_20 §4.4 PA-001..010 PAPER-AS-
MASTER and 0500000 dv1_24 §12 Paper-Mode Dispatch Boundary
Architecture, paper trading is the empirically-validated
master configuration; live trading is built to MIMIC paper.
Outside the four PA-004 divergence points (private WS
connection; order dispatch; capital ledger; Position Mirror
sourcing), paper and live operation MUST be byte-identical
(PA-005).

The Position Mirror is mode-blind. It does NOT inspect
mode state, does NOT read paper_trading_mode, and does NOT
branch on mode. The paper-vs-live divergence at PA-004 #4
(Position Mirror Sourcing) is absorbed by the WSManager
dispatch seam per 0500000 dv1_24 §12.3 and §12.4 — the
Position Mirror sees identical write calls from a single
writer (WSManager) in both modes; the only difference is
the upstream SOURCE of the data being written.

------------------------------------------------------------
6A.1 Architectural Principle
------------------------------------------------------------

PM-PAPER-001  PAPER-LIVE BYTE-IDENTICAL MIRROR PATH.

           The Position Mirror data structure, write
           helper methods (pm.create, pm.update_resting_
           orders, pm.update_qty, pm.update_fill_price,
           pm.delete), read access patterns, and hard
           rules are byte-identical between paper and
           live modes. Every PositionRecord field, every
           pm.create() call, every pm.update_resting_
           orders() call, every pm.update_qty() call,
           every del position_mirror[symbol] operation,
           every read of position_mirror[symbol], and
           every reconciliation read MUST execute
           identically regardless of mode. Mode-
           conditional branching in the Position Mirror
           module is PROHIBITED per HR-PM-010.

           The ONLY physical divergence between paper
           and live, viewed from the Position Mirror, is
           the SOURCE of the data populating Mirror
           records (per PM-PAPER-002) and the ID parity
           on tp_order_id / emgsl_order_id (per
           PM-PAPER-003). Both divergences are absorbed
           by the WSManager seam per 0500000 dv1_24
           §12.3 and are invisible to the Position
           Mirror data structure itself.

           Per 0500000 dv1_24 §12.2 WHO READS IT: "All
           other modules: Do NOT read paper_trading_mode.
           Mode is not their concern." The Position
           Mirror is not a module that reads
           paper_trading_mode. Mode is WSManager's
           concern, not the Mirror's.

PM-PAPER-002  ENTRY RECORD POPULATION SOURCE.

           PA-004 divergence point #4 — POSITION MIRROR
           SOURCING. The SOURCE of fields populated on
           PositionRecord differs by mode; the field
           values, schema, and write pathway are
           byte-identical:

             PAPER MODE: Mirror records are populated
               EXCLUSIVELY by the local simulated-fill
               path inside WSManager (per HR-WM-033 +
               HR-WM-024):
                 - Entry fill: WSManager._simulate_entry_fill
                   (asyncio.create_task scheduled by
                   WSManager.add_order in paper mode)
                   writes entry_fill_price, qty,
                   entry_timestamp_utc, fees_entry_usd.
                 - Resting orders set: WSManager.batch_add()
                   paper-mode gate writes tp_order_id,
                   tp_cl_ord_id, emgsl_order_id,
                   emgsl_cl_ord_id with PAPER_TP_/
                   PAPER_SL_ prefixed synthetic IDs per
                   0511001 dv1_5 §13.2.
                 - Partial TP fill / qty update: paper
                   fill detection in
                   WSManager._handle_ticker fires when
                   ticker ask >= pos.tp_price per
                   HR-WM-024.
                 - Record deletion: routed through Exit
                   Controller per HR-WM-033 (Exit
                   Controller drives _close_position on
                   simulated exit detection; WSManager
                   performs the physical del).
               No external Kraken event source. No
               snap_orders. No private-WS events. No
               REST GetOpenOrders fallback.

             LIVE MODE: Mirror records are populated by
               Kraken executions channel events (entry
               fill, TP partial fill / exec_type=trade,
               and other order-state events) and
               snap_orders reconciliation responses
               arriving via private WS. WSManager
               receives the events and writes Mirror
               records via pm helper methods.

           Reconciliation (§5.1, §5.2) does NOT apply
           in paper mode because no Kraken-side state
           exists to reconcile against. Paper Mirror
           is authoritative-by-construction.

PM-PAPER-003  TP / EMERGSL ID PARITY.

           tp_order_id and emgsl_order_id are present
           and populated in BOTH paper and live modes,
           via the same pm.update_resting_orders()
           pathway and the same PositionRecord fields.
           ID values differ by mode:

             PAPER MODE: Synthetic locally-assigned
               IDs prefixed "PAPER_TP_" / "PAPER_SL_"
               per 0511001 dv1_5 §13.2. WSManager's
               batch_add() paper-mode gate constructs
               these as f"PAPER_TP_{cl_ord_id}" and
               f"PAPER_SL_{cl_ord_id}".

             LIVE MODE: Kraken-assigned order_id values
               from the batch_add ACK message (e.g.,
               "OABCDE-12345-XYZ").

           Readers (Exit Controller, Risk Engine) treat
           tp_order_id and emgsl_order_id as opaque
           string identifiers and MUST NOT branch on
           the value to infer mode. Live-mode Exit
           Controller passes the IDs to WSManager
           cancel_order / amend_order seam methods which
           dispatch to Kraken; paper-mode Exit
           Controller passes the IDs to the same seam
           methods which gate at entry, log
           PAPER_CANCEL_SIMULATED / PAPER_AMEND_SIMULATED,
           and return without transmitting. The
           caller-visible post-conditions are identical
           per 0500000 dv1_24 §12.3 CALLER CONTRACT.

PM-PAPER-004  fees_entry_usd FIELD PARITY.

           Per 1011002 dv1_26 §16A.1 WM-PAPER-LEDGER-002
           and 0500000 dv1_24 §12.4 Synthetic Capital
           Ledger Single-Owner Architecture, the
           PositionRecord schema includes a
           fees_entry_usd: Decimal field populated at
           entry-fill time in BOTH modes:

             PAPER MODE: Per 1011002 dv1_26 §16A.1
               WM-PAPER-LEDGER-002, WSManager._simulate_
               entry_fill populates fees_entry_usd from
               (entry_qty * entry_price * FEE_MAKER_PCT)
               using the SAME FEE_MAKER_PCT constant
               as live per AR-012 / 0411003.

             LIVE MODE: Per 0511003 dv1_1 §5A
               EE-PAPER-005, the EE-driven entry fill
               handler populates fees_entry_usd from
               the Kraken executions channel
               exec_type=filled event's fees field
               (Kraken-reported maker fee).

           Exit Controller consumes fees_entry_usd at
           exit time per 1011005 dv1_3 §10A
           EC-PAPER-CODE-003(a) — EC does NOT recompute
           entry fees on exit; they are read from the
           PositionRecord. Failure to populate
           fees_entry_usd in either mode is a defect
           under HR-PM-012 (NEW dv1_1) and breaks
           PA-005 byte-identical CIATS data flow
           downstream of Exit Controller P/L
           computation.

PM-PAPER-005  SINGLE-WRITER (WSMANAGER) PARITY.

           HR-PM-009 (WS Manager is the SOLE writer to
           Position Mirror) holds in BOTH paper and
           live modes per HR-PM-011 (NEW dv1_1). Per
           0500000 dv1_24 §12.4 Synthetic Capital
           Ledger Single-Owner Architecture: "WSManager
           owns spot_usd_balance. WSManager owns
           Position Mirror writes. Other modules READ
           via WSManager helper methods (HR-PM-009
           read-only-via-helpers pattern); they do NOT
           WRITE."

           This single-writer property is a PA-005
           byte-identical architectural invariant — it
           is not a paper-only or live-only rule. The
           TB00148 finding 15 root-cause analysis
           showed that distributed Position Mirror
           writes from multiple modules (WSManager,
           Execution Engine, Exit Controller in
           pre-OPTION-B code) created a class of races
           and inconsistencies that no amount of
           locking could fully eliminate. The
           architectural fix is single-writer-by-
           design in BOTH modes.

           Read access by Signal Pipeline, Exit
           Controller, Risk Engine, Execution Engine,
           and CIATS EWMA Monitor occurs through pm
           helper methods (read-only views) in both
           modes per HR-PM-011. Direct mutation of
           position_mirror[symbol] from any module
           other than WSManager is PROHIBITED in both
           modes and is a session-halting defect under
           PA-001 (paper is master) and HR-PM-009.

------------------------------------------------------------
6A.2 What This Section Does NOT Change
------------------------------------------------------------

  - Data structure (§3.1) PositionRecord field list is
    unchanged. The fees_entry_usd schema-extension field
    is documented in §3.3 (NEW dv1_1) by reference to
    1011002 dv1_26 §16A.1 WM-PAPER-LEDGER-002 — the
    authoritative source-of-truth for the field. Field-
    level updates to §3.1 itself and to 1011006 are
    OUT OF SCOPE per RR-SCOPE-002.
  - Write rules (§4) are unchanged in their mechanics.
    Mode-source paragraphs were appended where the
    upstream data origin differs (§4.1, §4.2, §4.3,
    §4.4, §4.5).
  - Reconciliation (§5) is unchanged in mechanics. The
    LIVE MODE ONLY applicability tag was added per
    PM-PAPER-002.
  - Read access (§6) is unchanged in mechanics. Mode-
    agnostic read paragraph was added.
  - Hard rules HR-PM-001 through HR-PM-009 are
    unchanged.
  - Live-mode behavior is unchanged.
  - Log emissions (§10) are unchanged. Position Mirror
    emits POSITION_RECORD_CREATED, POSITION_FILL_
    CONFIRMED, POSITION_ORDERS_SET, POSITION_QTY_UPDATED,
    POSITION_CLOSED, etc. These are mode-agnostic
    events. PAPER_* events (PAPER_ORDER_SIMULATED,
    PAPER_BATCH_ADD_SIMULATED, PAPER_LEDGER_UPDATED,
    PAPER_TP_FILL_DETECTED, PAPER_EMERG_SL_TRIGGERED,
    etc.) are emitted by WSManager at the dispatch
    seam per 0500000 dv1_24 §12.6 — NOT by the
    Position Mirror module.

6A.3 Closes
------------------------------------------------------------

This §6A PM-PAPER section closes the parent-spec layer of
the Position Mirror paper-as-master cascade. It elevates
the Position Mirror sourcing rule (PA-004 #4) from
HR-WM-033 in 0511001 dv1_5 + PT-MODE-001 in 0211005 dv1_3
to TB00000 v2_20 §4.4 PA-001..010 PAPER-AS-MASTER absolute
standing rule + 0500000 dv1_24 §12 Paper-Mode Dispatch
Boundary Architecture, and binds the Mirror's single-
writer property (HR-PM-009) to the architectural single-
owner pattern of 0500000 dv1_24 §12.4 explicitly across
both modes (HR-PM-011 NEW dv1_1).

Cascade alignment:
  0500000 dv1_24 §12.0 — first-class architectural
                          element status.
  0500000 dv1_24 §12.1 — PA-004 four divergence points
                          (this spec binds primarily to
                          #4 Position Mirror Sourcing
                          and cascades from #2 Order
                          Dispatch and #3 Capital Ledger).
  0500000 dv1_24 §12.2 — paper_trading_mode flag read
                          ONCE at WSManager.__init__;
                          Position Mirror does NOT read
                          it.
  0500000 dv1_24 §12.3 — WSManager dispatch seam SOLE
                          gatekeeper; Mirror writes
                          driven by the seam.
  0500000 dv1_24 §12.4 — synthetic capital ledger
                          single-owner architecture;
                          Mirror is the parallel single-
                          writer pattern (HR-PM-009 +

8. HARD RULES
============================================================

HR-PM-001  O(1) symbol-keyed dict. No list, queue, or
           ordered structure for main position store (AR-002).

HR-PM-002  Record created at entry dispatch (BEFORE Kraken
           fill ACK). cl_ord_id recorded at dispatch. No
           async gap between dispatch and position tracking
           (A-2, record-at-dispatch rule).

HR-PM-003  entry_fill_price MUST use actual fill price
           (avg_price from exec_type=filled). NOT the
           limit price. All R:R calculations use actual
           fill price. OTO was rejected because it uses
           limit price (AR-008).

HR-PM-004  All Decimal values from WS messages: Decimal(str())
           immediately on receipt. No float arithmetic in
           position tracking (AR-047).

HR-PM-005  CIATS Trade Outcome Bus fires ONCE on full position
           close with complete trade record (AR-066). Not on
           partial fills.

HR-PM-006  On mid-session reconnect: Position Mirror preserved
           from pre-disconnect state. Reconciled against
           snap_orders. portfolio_baseline_USD never reset.
           drawdown_pct preserved (AR-056, AR-052).

HR-PM-007  Unexpected open orders detected in snap_orders (not
           in Position Mirror): logged and operator alerted.
           Not auto-managed. Bill decides.

HR-PM-008  One position per symbol maximum. Position Mirror
           enforces this by construction (dict key = symbol).
           Gate 5 SC-GATE-3 checks this before entry.

HR-PM-009  WS Manager is the SOLE writer to Position Mirror.
           No other component may directly modify it.

HR-PM-010  PAPER-LIVE BEHAVIORAL PARITY (NEW dv1_1).
           Position Mirror has NO mode-conditional
           branching. Paper and live execute byte-
           identical Mirror code paths in every helper
           method, every read access, every write
           operation, every reconciliation read, every
           log emission, and every triggered update.
           The paper-vs-live data-source divergence at
           PA-004 #4 (Position Mirror Sourcing) is
           absorbed by the WSManager dispatch seam per
           0500000 dv1_24 §12.3 and is invisible to the
           Position Mirror module. Per TB00000 v2_20
           §4.4 PA-005 byte-identical paper-live
           outside the four PA-004 divergence points.
           Position Mirror MUST NOT read
           paper_trading_mode. Position Mirror MUST NOT
           read ws_manager.paper_mode. Position Mirror
           MUST NOT branch on mode anywhere in its
           code. Closes parent-spec layer of TB00148
           cluster 1 audit findings 09, 29, 30 (paper-
           mode dispatch seam undefined) at the
           Position Mirror layer.

HR-PM-011  SINGLE-WRITER ENFORCEMENT IN BOTH MODES
           (NEW dv1_1). Strengthening of HR-PM-009 to
           PA-005 byte-identical status. WSManager is
           the SOLE writer of position_mirror in BOTH
           paper and live modes. Per 0500000 dv1_24
           §12.4 single-owner architecture: "WSManager
           owns Position Mirror writes. Other modules
           READ via WSManager helper methods (HR-PM-009
           read-only-via-helpers pattern); they do NOT
           WRITE." Specifically, Execution Engine,
           Exit Controller, Long Module, Selection
           Controller, Risk Engine, Regime Engine,
           Signal Pipeline, and CIATS EWMA Monitor
           MUST NOT:
             (a) Hold a write reference to
                 position_mirror that bypasses
                 WSManager helper methods.
             (b) Construct or mutate a PositionRecord
                 outside of a WSManager-driven write
                 path.
             (c) Delete entries from position_mirror
                 directly. Deletion is performed by
                 WSManager on Exit Controller's
                 instruction per §4.4 + 0511004 dv1_3
                 HR-EC-013 / HR-EC-014.
           Violation is a session-halting defect under
           PA-001 (paper is master) and TB00148 finding
           15 multi-writer ambiguity (the originating
           defect this rule prevents in the rebuild).

HR-PM-012  fees_entry_usd FIELD MANDATORY IN BOTH MODES
           (NEW dv1_1). The PositionRecord
           fees_entry_usd: Decimal field (per 1011002
           dv1_26 §16A.1 WM-PAPER-LEDGER-002 schema
           extension) MUST be populated at entry-fill
           time in BOTH paper and live modes:
             PAPER MODE: WSManager._simulate_entry_fill
               populates fees_entry_usd =
               entry_qty * entry_price * FEE_MAKER_PCT
               per 1011002 dv1_26 §16A.1
               WM-PAPER-LEDGER-002.
             LIVE MODE: The EE-driven entry fill
               handler populates fees_entry_usd from
               the Kraken executions channel
               exec_type=filled event's fees field
               (Kraken-reported maker fee) per
               0511003 dv1_1 §5A EE-PAPER-005.
           Exit Controller consumes fees_entry_usd at
           exit time per 1011005 dv1_3 §10A
           EC-PAPER-CODE-003(a) — EC does NOT
           recompute entry fees on exit; they are
           read from the PositionRecord. Absence of
           fees_entry_usd in live mode is a defect
           that breaks PA-005 byte-identical CIATS
           data flow downstream of Exit Controller
           P/L computation. Per TB00000 v2_20 §4.4
           PA-005.
