Components sub-domain (AA=05, B=1). It anchors all TothBot
V2 system component specification instance documents
(0511002 through 0511006) to the System Architecture
Domain Document (0500000).

hierarchy chain for the System Components sub-domain,
allowing instance documents to have a valid parent chain.

to GitHub without this anchor and 0500000 already present

4. SUB-DOMAIN SCOPE
============================================================

The System Components sub-domain governs the complete
internal component specifications for all TothBot V2
modules that execute on the VPS. These documents define
what each component does, its interfaces, its hard rules,
what triggers it, and what it logs. Each document is
a coding-ready specification from which AA=10 coding
specifications and code can be directly derived.

Each instance document elaborates one component:

  0511002  Signal_Pipeline_Specification
           The Signal Pipeline owns the 8-gate evaluation
           sequence that fires on every 5-minute OHLC
           candle close event. Governs: Parameter Store
           snapshot freeze (I-4), pre-computation cache
           read (I-2), per-pair instrument status pre-check,
           Gate 1 (State Machine), Gate 2 (Liquidity),
           Gate 3 (Regime Pre-Filter), Gate 4 (1H HTF),
           SSS Signal Engine (AR-067, AR-076), Gate 5
           (Selection Controller), Gate 6 (Regime Gate),
           Gate 7 (Risk Guard), Gate 8 (Position Sizer),
           and OHLC stall handling. All rejection codes
           and pass/fail logic defined here.

  0511003  Execution_Engine_Specification
           The Execution Engine owns order dispatch to
           Kraken. Receives sizing output from Gate 8.
           Constructs and sends: add_order (entry), and
           batch_add (TP + emergSL atomic on fill). All
           field requirements, parameter values, and error
           handling. Owns cl_ord_id assignment, req_id
           tracking, and Pending Order Registry population.

  0511004  Exit_Controller_Specification
           The Exit Controller owns all normal position
           exits. Three-layer architecture: Layer 1a
           (signal-based: HTF reversal, daily downgrade,
           max hold), Layer 1b (TP fill confirmation and
           emergSL cancellation), Layer 2 (MAE threshold
           breach with cancel timeout fallback per I-6
           and MPP handling per C-1). Layer 3 (emergency
           SL) is crash protection only — NEVER in normal
           operation. Owns ticker-driven continuous
           drawdown monitoring (I-7), batch_cancel for
           Full Halt (AR-019, AR-041), pair status
           adaptation for open positions (AR-040), and
           TP partial fill handling (AR-066).

  0511005  Position_Mirror_Specification
           The Position Mirror is TothBot's in-memory
           authoritative record of all open positions.
           O(1) symbol-keyed dict (AR-002). Records:
           symbol, entry_fill_price, qty, TP order_id,
           cl_ord_id, emergSL order_id. Recorded at
           dispatch (no async gap per A-2). Reconciled
           at startup and reconnect. Defines all update
           rules: on fill, on TP partial fill (AR-066),
           on position close, on reconciliation.

  0511006  Logger_Specification
           The Logger is the sole data interface between
           TothBot and CIATS. Async bounded queue using
           queue.Queue (stdlib) with maxsize=10,000
           (AR-014, AR-063). NEVER blocks the trading
           hot path. QueueHandler + QueueListener pattern.
           Defines all event types that must be logged,
           minimum fields per event type, CIATS Trade
           Outcome Bus fields, EWMA Monitor stream fields,
           and alert levels.
