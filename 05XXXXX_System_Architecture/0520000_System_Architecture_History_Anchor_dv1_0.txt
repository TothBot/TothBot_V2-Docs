SYSTEM ARCHITECTURE HISTORY ANCHOR
============================================================

============================================================
1. PURPOSE
============================================================

This document is the Sub-Domain Anchor for the System
Architecture History sub-domain (AA=05, B=2). It anchors
the System Architecture History sub-domain to the System
Architecture Domain Document (0500000).

It exists to give the relocated 0500000 revision history a
valid three-tier parent chain. The 0500000 Section 14
revision history grew large enough that its pre-consolidation-
campaign entries were relocated out of the live design
document into a dedicated archive instance document under
this anchor, keeping 0500000 itself focused on the canonical
design diagrams plus a campaign-forward revision tail.

Its purpose is structural: it completes the three-tier
hierarchy chain for the System Architecture History
sub-domain, allowing the revision-history archive instance
document to have a valid parent chain. No instance document
in this sub-domain may be committed to GitHub without this
anchor and 0500000 already present and approved.

This anchor holds NO architecture. Per the binary
architecture test (DEC-096) revision-history narrative is
not trading-organism architecture and does not belong in a
0500000 design diagram; it is preserved, in its correct
home, as the archive instance document under this anchor.

3. TRACEABILITY TO PARENT DOMAIN DOCUMENT
============================================================

This anchor anchors the relocated revision history of
0500000. The single instance document under it
(0521001) holds the verbatim Section 14 revision-history
record of 0500000, dv1_0 through the current version.

The instance document is a historical/forensic record, not
a design source. It traces to 0500000 as the document whose
revision history it preserves. No architectural decision,
hard rule, namespace token, parameter, or diagram content
is defined in this sub-domain; all such content remains
canonical in the 0500000 diagrams (DD-001 / DD-002) and in
its named non-architectural homes.

============================================================
4. SUB-DOMAIN SCOPE
============================================================

The System Architecture History sub-domain governs the
relocated revision-history archive of the 0500000 System
Architecture Overview. It contains exactly one instance
document, 0521001 System_Architecture_Overview_Revision_History,
which holds the complete Section 14 revision history of
0500000 (dv1_0 through the current version) preserved
verbatim.

The live 0500000 Section 14 retains only the consolidation-
campaign-forward revision entries (the campaign-seed entry
dv1_113 / TB00395 Phase 0 and all later entries). Every
earlier entry, and the complete record, lives in 0521001 as
the authoritative archive. This relocation moves a
non-architectural forensic record to its correct home per
the binary architecture test (DEC-096); it migrates no
architecture and loses no content.
