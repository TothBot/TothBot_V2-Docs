============================================================
SIGNAL PIPELINE SPECIFICATION
============================================================

============================================================
1. PURPOSE
============================================================

This document is the system-level specification for the
Signal Pipeline component of TothBot V2. It defines what
the Signal Pipeline does, its interfaces, its hard rules,
what triggers it, and what it logs. It is the authoritative
parent document for 1011003 Signal_Pipeline_Coding_Spec.

The Signal Pipeline is the core evaluation engine of
TothBot V2. It fires on every 5-minute OHLC candle close
event and evaluates each monitored pair through an 8-gate
sequence to determine whether to dispatch a trade entry.

============================================================
2. COMPONENT SUMMARY
============================================================

What it does:
  Evaluates a closed 5-minute candle for one symbol
  through 8 sequential gates. Each gate is a pass/fail
  condition. On full pass through all 8 gates, hands
  off to Execution Engine (0511003). On any fail, logs
  rejection code and terminates evaluation for that
  symbol without side effects.

Primary inputs:
  Closed 5-minute OHLC candle (from WS Manager)
  Parameter Store snapshot (frozen at pipeline start)
  Pre-computation cache (regime, ATR, HTF EMA, SSS state,
  liquidity, per-pair status)

Primary outputs:
  Entry instruction to Execution Engine (Gate 8 pass)
  Rejection log entry (any gate fail)
  CIATS data feed via Logger (all gate decisions)

Trigger:
  WS Manager fires pipeline once per symbol per 5-minute
  OHLC candle close. The candle that fires is the completed
  (closed) candle — not the in-progress candle.
  OHLC stall: if no trades occur after candle close, Kraken
  sends no OHLC message. Pipeline does not fire for stalled
  symbols. System handles this correctly by design — pipeline
  only fires when Kraken sends a candle event.

============================================================
3. PRE-PIPELINE STEPS (before Gate 1)
============================================================

3.1 Parameter Store Snapshot Freeze (I-4)

  At the start of each pipeline evaluation for a symbol,
  TothBot takes a frozen read-only snapshot of ALL CIATS
  parameter values. All gate evaluations within this
  pipeline run use this snapshot. CIATS writes to the
  Parameter Store are queued and applied only at confirmed
  inter-trade boundaries. This prevents parameter
  inconsistency within a single pipeline evaluation.

  Parameters captured in snapshot (starting values):
    tradeable_pct:          0.50
    per_trade_pct:          0.05 (→ Half-Kelly at 200 trades)
    max_concurrent:         20
    mae_mult:               1.5  (ATR multiplier)
    emergency_sl_mult:      3.0  (ATR multiplier)
    entry_timeout_sec:      30-60 (GTD seconds)
    full_halt_drawdown:     0.10
    session_pause_drawdown: 0.05
    adx_threshold:          25
    atr_percentile_threshold: 0.67
    htf_ema_periods:        [20, 50]
    min_volume_usd_daily:   500000
    max_hold_candles:       24
    rsi_entry_low:          50
    rsi_entry_high:         70
    volume_sss_threshold:   1.0
    sc_body_threshold:      0.3
    sc_cooldown_seconds:    300
    sc_consecutive_limit:   3

3.2 Pre-Computation Cache Read (I-2)

  Hot path reads from in-memory cache (no computation,
  no disk I/O). Cache updated incrementally by WS Manager
  between pipeline evaluations.

  Cache contents read at pipeline start:
    regime[symbol]:         dict (asset regime classification)
    market_regime:          dict (BTC/USD regime, proxy)
    htf_ema_20[symbol]:     Decimal (1H EMA(20))
    htf_ema_50[symbol]:     Decimal (1H EMA(50))
    atr_14[symbol]:         Decimal (incremental ATR running value)
    rsi_14[symbol]:         Decimal (current RSI — computed from
                            avg_gain / avg_loss state — AR-076)
    ema_9[symbol]:          Decimal
    ema_21[symbol]:         Decimal
    volume_ma_20[symbol]:   Decimal
    volume_24h_usd[symbol]: Decimal (24h USD volume)
    pair_status[symbol]:    str (instrument channel status)
    spot_usd_balance:       Decimal (current from balances)
    position_mirror:        dict (current open positions)
    drawdown_pct:           Decimal (current drawdown)
    system_state:           str (NORMAL|SESSION_PAUSE|FULL_HALT)

3.3 Per-Pair Instrument Status Pre-Check

  Before Gate 1, check pair_status[symbol].
  Skip pairs in ANY of these states:
    reduce_only, work_in_progress, delisted, limit_only,
    cancel_only, maintenance (AR-039, dv1_12)
  Only pairs in online or post_only status proceed.
  Rejection code: INSTRUMENT_STATUS_BLOCKED
  Prevents wasted rate counter on blocked pairs.

============================================================
4. GATE 1 — STATE MACHINE
============================================================

  Condition: Kraken engine status (from status channel)
  PASS: engine = online OR post_only
  FAIL: engine = cancel_only OR maintenance
    Action on FAIL: pipeline WAITS. No rejection code.
    No entry attempts. Existing positions managed by
    Exit Controller. Resume when engine returns to
    online or post_only.
  Rejection code (logged on FAIL): SYSTEM_STATE_BLOCKED

  NOTE: post_only state is a PASS. TothBot limit+post_only
  entries ARE valid during Kraken post_only state.

============================================================
5. GATE 2 — LIQUIDITY GATE
============================================================

  Condition: 24h USD volume >= min_volume_usd_daily
             (starting: $500k. CIATS-owned)
  Data source: daily ticker snapshot or daily OHLC pull
  PASS: volume >= threshold
  FAIL: volume < threshold
  Rejection code: LIQUIDITY_REJECTED

============================================================
6. GATE 3 — REGIME PRE-FILTER (I-1)
============================================================

  Condition: asset regime must NOT be NO-ENTRY regime.
  NO-ENTRY regimes (block all entries):
    TRENDING_NEGATIVE (any volatility)
    NON_DIRECTIONAL + ELEVATED_VOL
  PASS: TRENDING_POSITIVE (any vol) OR NON_DIR + NORMAL_VOL
  FAIL: TRENDING_NEG (any) OR NON_DIR + ELEVATED_VOL
  Rejection code: REGIME_BLOCKED

  Gate 3 eliminates SSS computation on no-trade regimes.
  SSS runs ONLY when Gate 3 passes. This gate uses the
  ASSET regime (per-pair), not market_regime (BTC proxy).

  Regime computation: See Regime Engine (1011012).
  Computed daily at 00:00 UTC via REST GetOHLCData.
  CRITICAL: response[-1] ALWAYS excluded (AR-017).

  REGIME DEFINITIONS (CIATS-owned thresholds):
    TRENDING_POSITIVE:  ADX(14) > adx_threshold (25)
                        AND EMA(20) > EMA(50) on daily
    TRENDING_NEGATIVE:  ADX(14) > adx_threshold (25)
                        AND EMA(20) < EMA(50) on daily
    NON_DIRECTIONAL:    ADX(14) <= adx_threshold (25)
    NORMAL_VOL:         ATR(14) percentile <= 67th in
                        50-day rolling window
    ELEVATED_VOL:       ATR(14) percentile > 67th

============================================================
7. GATE 4 — 1H HTF CONFIRMATION
============================================================

  Condition: 1H EMA(20) > 1H EMA(50) for TRENDING_POS pairs
  Data source: htf_ema_20[symbol] and htf_ema_50[symbol]
  (pre-computation cache — seeded from ohlc(60) stream)
  PASS: htf_ema_20 > htf_ema_50 OR regime is NON_DIR+NORMAL
  FAIL: TRENDING_POS pair AND htf_ema_20 <= htf_ema_50
  Rejection code: HTF_GATE_REJECTED

  Gate 4 applies to TRENDING_POSITIVE pairs only.
  NON_DIR+NORMAL pairs skip Gate 4 and proceed directly.
  Evidence: 15-20% higher win rates with daily+hourly
  confirmation (5 independent sources, 2024-2025).

============================================================
8. SSS SIGNAL ENGINE (AR-067, AR-076)
============================================================

  SSS = Simple Signal System. Runs only if Gate 4 passed.
  SSS PASS = ALL THREE conditions simultaneously true.

  SC-SSS-1: RSI(14) on 5-min > rsi_entry_low (50)
            AND RSI(14) < rsi_entry_high (70)
            RSI > 50 = bullish momentum confirmed.
            RSI < 70 = not overbought.
            RSI uses Wilder's SMMA (AR-076):
              avg_gain = (prev_avg_gain*13 + gain) / 14
              avg_loss = (prev_avg_loss*13 + loss) / 14
              RS  = avg_gain / avg_loss
              RSI = 100 - (100 / (1 + RS))
            DO NOT use standard EMA for RSI.

  SC-SSS-2: EMA(9) on 5-min > EMA(21) on 5-min
            Short-term EMA crossover on entry timeframe.
            EMA(9):  alpha = 2/10 = 0.2 (standard EMA).
            EMA(21): alpha = 2/22 (standard EMA).
            Standard EMA is correct for EMA(9) and EMA(21).

  SC-SSS-3: current_candle_volume > volume_ma_20 *
            volume_sss_threshold (1.0x starting)
            Above-average volume = genuine participant interest.

  SSS output: signal_params dict (logged by CIATS):
    { rsi_14, ema_9, ema_21, volume_ratio, sss_pass }
  Logged regardless of pass or fail. SSS FAIL rejection
  code passed to Gate 5 (SELECTION_REJECTED — SSS_SIGNAL_FAIL).

============================================================
9. GATE 5 — SELECTION CONTROLLER (AR-072, AR-073)
============================================================

  Six sequential quality gates. All 6 must pass.

  SC-GATE-1: SSS PASS (all three SSS conditions true).
             Reject: SSS_SIGNAL_FAIL

  SC-GATE-2: abs(candle_close - candle_open) >
             ATR(14) * sc_body_threshold (0.3 starting)
             Momentum candle must have directional commitment.
             Eliminates doji-like candles. Reject: WEAK_CANDLE_BODY

  SC-GATE-3: symbol NOT in position_mirror.
             No pyramiding. One position per pair maximum.
             Reject: POSITION_ALREADY_OPEN

  SC-GATE-4: symbol NOT in exit_cooldown_log
             OR (time.monotonic() - exit_cooldown_log[symbol])
             >= sc_cooldown_seconds (300s starting = 1 candle).
             Post-exit cooldown prevents immediate re-entry
             on stopped-out pair. Reject: PAIR_IN_COOLDOWN

  SC-GATE-5: quantized_qty >= qty_min
             AND quantized_qty * entry_limit_price >= cost_min
             Pre-validates position size meets Kraken minimums.
             Calculated from Gate 8 preview (or iterate).
             Reject: POSITION_TOO_SMALL

  SC-GATE-6: consecutive_loss_count[symbol] <
             sc_consecutive_limit (3 starting).
             3 consecutive losses on one pair → block.
             CIATS-owned. Resets on win or CIATS instruction.
             Reject: CONSECUTIVE_LOSSES_EXCEEDED

  All rejections: FAIL = SKIP + log reject code + CIATS
  EWMA monitors signal.

============================================================
10. GATE 6 — REGIME GATE
============================================================

  Position sizing adjustment based on regime.
  PASS always (Gate 6 never blocks — only sizes).

  TRENDING_POSITIVE (any vol): proceed at full per_trade_pct
  NON_DIR + NORMAL_VOL:        proceed at 50% per_trade_pct
  All NO-ENTRY cases already blocked by Gate 3.

  Sizing modifier passed to Gate 8.

============================================================
11. GATE 7 — RISK GUARD
============================================================

  Three independent checks. Any fail = HALT entry.

  Check 1: Drawdown circuit breaker
    Computed continuously (ticker-driven per I-7):
      current_portfolio_USD = spot_usd_balance
          + sum(bid_price[sym] * qty[sym]
                for sym in position_mirror)
      drawdown_pct = max(0, (portfolio_baseline -
                          current_portfolio) / portfolio_baseline)
    At Gate 7 evaluation:
      drawdown_pct >= full_halt_drawdown (10%):
        system_state = FULL_HALT. No entries. Alert operator.
        Does NOT auto-close positions. Bill decides.
        Rejection code: FULL_HALT_DRAWDOWN
      drawdown_pct >= session_pause_drawdown (5%):
        system_state = SESSION_PAUSE. No new entries.
        Existing positions monitored normally.
        Resumes when drawdown recovers below 5%.
        Rejection code: SESSION_PAUSE_DRAWDOWN

  Check 2: Concentration check
    No more than max_concurrent (20 starting) concurrent
    positions. Enforced by asyncio.BoundedSemaphore (AR-043).
    Gate 7 checks semaphore.locked() — non-blocking.
    Rejection code: MAX_CONCURRENT_REACHED

  Check 3: Available USD check (AR-053)
    available_USD = spot_usd_balance
                    - sum(pending_orders.values())
    If available_USD < per_trade_USD:
      Rejection code: SKIP_INSUFFICIENT_USD

  Note: ticker-driven continuous drawdown check (I-7):
  Exit Controller checks drawdown on EVERY bbo ticker event
  for open-position pairs AND at every Gate 7 evaluation.
  Gate 7 is not the only drawdown check point.

============================================================
12. GATE 8 — POSITION SIZER
============================================================

  Never blocks — only sizes. Computes all order parameters.

  12.1 Position sizing

    trade_capital = spot_usd_balance * tradeable_pct (0.50)
    per_trade_USD = trade_capital * per_trade_pct (0.05)
    If Gate 6 modifier = 50%: per_trade_USD *= 0.5
    After 200 closed trades: Half-Kelly replaces per_trade_pct
      K_full = W - ((1-W) / R)
      W = win_rate (from Trade Outcome Bus realized net P/L)
      R = mean(net_gains) / mean(|net_losses|) (net, incl fees)
      Applied_pct = min(K_full * 0.5, tradeable_pct / max_concurrent)
      (Prevents overcommitment across concurrent positions)

  12.2 ATR computation (AR-016)
    ATR(14) incremental — O(1) per update. From cache.
    ATR = (prev_ATR * 13 + current_TR) / 14.

  12.3 R:R formula (SACRED — AR-011)
    mae_pct      = (ATR(14) * mae_mult) / entry_fill_price
    net_loss     = mae_pct + 0.16% + 0.26%
    net_gain     = net_loss * 1.5   ← HARDCODED SACRED
    gross_target = net_gain + 0.16%
    emergSL_dist = (ATR(14) * emergency_sl_mult) / entry_fill_price

  12.4 Order parameters computed
    entry_qty = per_trade_USD / entry_limit_price
    entry_qty_quantized = quantize(entry_qty, qty_min, ROUND_DOWN)
    tp_price = entry_fill_price * (1 + gross_target)
    sl_trigger_price = entry_fill_price * (1 - emergSL_dist)
    entry_limit_price = quantize(candle_close, price_increment,
                                 ROUND_DOWN)   (AR-069)
    entry_timeout_sec: 30-60s (CIATS-owned starting range)

  12.5 Validation before dispatch
    entry_qty_quantized >= qty_min
    entry_qty_quantized * entry_limit_price >= cost_min
    (AR-028 — if fails, log POSITION_TOO_SMALL, skip)

  12.6 Output to Execution Engine (0511003)
    {symbol, entry_limit_price, entry_qty, tp_price,
     sl_trigger_price, entry_timeout_sec, cl_ord_id,
     regime_context, signal_params}

============================================================
13. INTERFACES
============================================================

13.1 From WS Manager (0511001)
  Receives: closed candle data per symbol, pre-computation
  cache, Parameter Store snapshot.

13.2 To Execution Engine (0511003)
  Passes: Gate 8 output dict on full 8-gate pass.

13.3 To Position Mirror (0511005)
  Reads: open positions (via pre-computation cache).

13.4 To Logger (0511006)
  Logs every gate outcome for every symbol evaluation.
  Every pipeline run: gate-by-gate decision record.

13.5 From CIATS Parameter Store
  Reads frozen snapshot at pipeline start (I-4).
  Never reads live during evaluation.

13.6 From Regime Engine (1011012)
  Reads regime cache (updated daily at 00:00 UTC).
  Not a live call — reads from pre-computation cache.

============================================================
14. HARD RULES
============================================================

HR-SP-001  Parameter Store snapshot frozen BEFORE any gate
           evaluation begins. The same snapshot used for
           the full evaluation. No live parameter reads
           during pipeline execution.

HR-SP-002  Pre-computation cache read-only during pipeline.
           No cache updates during gate evaluation.

HR-SP-003  Gate evaluation is strictly sequential (1 → 8).
           No gate may be skipped except as defined.
           Gate 4 does not apply to NON_DIR+NORMAL pairs.

HR-SP-004  RSI(14) MUST use Wilder's SMMA (alpha=1/14).
           Standard EMA (alpha=2/15) is PROHIBITED for RSI
           calculation (AR-076).

HR-SP-005  SSS runs ONLY when Gate 3 (Regime Pre-Filter)
           passes. No SSS computation on blocked regimes.

HR-SP-006  Gate 8 never blocks. It only sizes. Any sizing
           issue (position too small) is caught in Gate 5
           SC-GATE-5 pre-validation.

HR-SP-007  The sacred constraint net_gain = net_loss * 1.5
           is HARDCODED in Gate 8. CIATS does not own this
           value. It is never a parameter (AR-011).

HR-SP-008  All Decimal arithmetic: Decimal(str()) conversion
           on all numeric inputs. All calculations in Decimal.
           No float arithmetic in R:R or sizing (AR-047).

HR-SP-009  response[-1] of GetOHLCData: EXCLUDED from all
           regime and indicator computations. Use only
           response[:-1] (AR-017).

HR-SP-010  Pipeline DOES NOT fire during WS reconnect.
           Candle events queued during reconnect discarded
           after reconnect completes.

HR-SC-005  SC-GATE-5 MUST use entry_qty_quantized (already
           ROUND_DOWN quantized by Gate 8). Never use
           raw computed qty for minimum size validation.
           Migrated from 0811002 dv1_0 §9 HR-SC-005 at
           TB00301 PROSE-UPDATE-A1 per DEC-012(a-extended)
           DD-012 v2_38 0500000-canonical-all-docs
           retirement cascade S-3 (bucket (b) coding-unique
           contract migration to parent spec per
           DD-001/DD-002 architectural-hierarchy reasoning).

HR-SC-006  Cooldown MUST use time.monotonic() exclusively.
           Never time.time() for cooldown interval.
           Monotonic clock never jumps backward on system
           time corrections. Migrated from 0811002 dv1_0
           §9 HR-SC-006 at TB00301 PROSE-UPDATE-A2 per
           DEC-012(a-extended) DD-012 v2_38 0500000-
           canonical-all-docs retirement cascade S-3
           (bucket (b) coding-unique contract migration
           to parent spec per DD-001/DD-002 architectural-
           hierarchy reasoning).

============================================================
15. WHAT TRIGGERS IT
============================================================

  WS Manager fires pipeline once per symbol per 5-min
  OHLC candle close event. One pipeline evaluation per
  symbol per candle — never concurrent for the same symbol.

============================================================
16. WHAT IT LOGS
============================================================

  Per evaluation per symbol:
    PIPELINE_START   — symbol, candle close time, snapshot_id
    STATUS_BLOCKED   — if instrument status pre-check fails
    GATE_1_PASS/FAIL — engine state
    GATE_2_PASS/FAIL — liquidity_usd, threshold
    GATE_3_PASS/FAIL — regime classification
    GATE_4_PASS/FAIL — htf_ema_20, htf_ema_50
    SSS_RESULT       — rsi_14, ema_9, ema_21, volume_ratio,
                       sss_pass (always logged)
    GATE_5_RESULT    — which SC gate failed (if any),
                       all 6 gate outcomes
    GATE_6_RESULT    — regime gate sizing modifier
    GATE_7_RESULT    — drawdown_pct, semaphore state,
                       available_USD
    GATE_8_RESULT    — all sizing parameters computed
    PIPELINE_PASS    — all 8 gates passed, entry dispatched
    PIPELINE_FAIL    — gate number and rejection code
