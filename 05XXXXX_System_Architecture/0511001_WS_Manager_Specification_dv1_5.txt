============================================================
WS MANAGER SPECIFICATION
============================================================

============================================================
1. PURPOSE
============================================================

This document is the system-level specification for the
WS Manager component of TothBot V2. It defines what the
WS Manager does, its interfaces, its hard rules, what
triggers it, and what it logs. It is the authoritative
parent document for 1011002 WS_Manager_Coding_Spec.

The WS Manager is TothBot's sole interface to all Kraken
WebSocket v2 connections and is the central event processor
for the system. All Kraken push events flow through the WS
Manager. It is the heart of the TothBot runtime.

============================================================
2. COMPONENT SUMMARY
============================================================

What it does:
  Maintains all Kraken WS v2 connections. Receives all
  Kraken push events and dispatches them to the correct
  internal handlers via O(1) dispatch table (AR-015).
  Manages all per-symbol state (indicators, position
  tracking, cooldowns). Runs the pipeline trigger on
  each 5-minute candle close. Executes all WS outbound
  messages (orders, amendments, cancels). Manages
  startup warm-up, mid-session reconnect, and all
  connection health monitoring. Supports paper trading
  mode. In paper mode, universe population, REST Ticker
  liquidity filtering, subscriptions, indicator warm-up,
  candle processing, pipeline triggers, and CIATS data
  flows execute IDENTICALLY to live mode per D-06. Only
  private WS connection, auth, executions/balances
  subscription, and order dispatch are skipped in paper
  mode — all orders are simulated locally.

Primary inputs:
  Kraken WS v2 push events (all channels)
  Internal calls from Signal Pipeline, Execution Engine,
  Exit Controller, CIATS (via Parameter Store)
  Config key paper_trading_mode (bool)

Primary outputs:
  Dispatched Kraken WS v2 outbound messages (orders,
  cancels, amendments, pings) — LIVE MODE ONLY
  Simulated order events (paper mode only)
  Pipeline trigger events to Signal_Pipeline
  Internal state updates (Position Mirror, indicator
  caches, drawdown state, cooldown state)
  Logger calls (all events)
  Operator alerts

============================================================
3. WEBSOCKET CONNECTIONS
============================================================

3.1 Connection Inventory

  PUBLIC WS v2 (wss://ws.kraken.com/v2):
    Connection model: N_conns shards (PATH 2 multi-
                      connection batched-subscribe per
                      §15A ADR). Each shard is an
                      independent WebSocket connection
                      to the same Kraken public endpoint.
                      Each shard owns a partition of the
                      tradeable_universe and subscribes
                      its own copies of the per-pair
                      channels for its assigned symbols.
                      Connection-wide channels
                      (instrument, status) are subscribed
                      ONCE on shard index 0 only (one
                      copy of global engine state is
                      sufficient).

    Subscriptions on shard 0 ONLY:
      instrument  — per-pair specs + status cache (startup)
      status      — global engine state + connection_id

    Subscriptions per shard (each shard subscribes its
    own assigned symbol partition):
      ohlc(5)     — 5-minute SYSTEM CLOCK
      ohlc(60)    — NOT subscribed via WS. Kraken WS v2
                    rejects a second ohlc interval per
                    symbol (HR-WM-021). 1H HTF cache
                    sourced from REST only.
      ticker      — price data (per-pair, event_trigger
                    managed based on position state)

  PRIVATE WS v2 (wss://ws-auth.kraken.com/v2):
    Connection model: SINGLE connection (private
                      operations are not symbol-sharded —
                      a single account-scope private feed
                      is sufficient and authoritative).
    Subscriptions inbound:
      executions  — fills, expirations, rejections, status
      balances    — real-time settlement
    Outbound messages:
      add_order, amend_order, batch_add, cancel_order,
      batch_cancel
    NOTE: Private WS is NEVER connected in paper mode.
          Public WS shards connect and operate normally
          in paper mode. All order operations are
          simulated.

  Total connection count at runtime:
    Live mode:   N_conns (public shards) + 1 (private)
    Paper mode:  N_conns (public shards), no private

3.1.1 Connection Sharding (PATH 2)

  N_conns is computed at startup as:

    N_conns = ceil(universe_size / SYMBOLS_PER_CONN_SAFE)

  where:

    SYMBOLS_PER_CONN_SAFE = 500
      CIATS-owned starting value. Empirically validated
      ceiling between 650 and 700 symbols per connection
      for ticker+ohlc back-to-back subscribe (TB00141
      §3.5 Phase B bisection). Starting value of 500
      provides 23-29% safety margin. CIATS may revise
      via parameter update; never hardcoded in code.

  Symbol distribution: alternating-index assignment
  across the sorted tradeable_universe. For symbol at
  sorted index i:

    shard_index = i % N_conns

  This produces approximately balanced shards
  (universe_size / N_conns symbols each, ±1).

  Each shard holds its assigned symbol partition for
  the session lifetime. Re-shard occurs only on:
    (1) Universe re-evaluation (detects added/removed
        pairs in tradeable_universe), or
    (2) Per-shard reconnect (the affected shard
        re-subscribes its existing partition without
        re-shard across other shards).

  Subscribe count per shard is decoupled from
  max_concurrent (CIATS-owned trading-position cap).
  The full D-03 universe is always subscribed
  regardless of concurrent-position count.

3.2 Connection Library Configuration (AR-058, AR-059, AR-060)

  REQUIRED import:
    from websockets.asyncio.client import connect
  DEPRECATED (DO NOT USE):
    import websockets; websockets.connect()

  All connections — including every PUBLIC shard and
  the PRIVATE connection — MUST set:
    max_queue=None        — unlimited message queue (AR-058)
    ping_interval=None    — disable library TCP PING (AR-059)
    max_size=10MB         — AR-029
    open_timeout=10       — AR-029

  Application JSON ping is the sole keepalive mechanism,
  applied per-connection (every PUBLIC shard runs its own
  30-second ping; PRIVATE runs its own ping). Library
  built-in PING is explicitly disabled on all connections.

3.3 REST Connection Configuration (AR-035)

  aiohttp ClientSession settings (applied to all REST):
    ClientTimeout(total=10, connect=5, sock_read=8)
    TCPConnector(limit=10, limit_per_host=5,
                 force_close=False)
  All REST calls via aiohttp (AR-025). asyncio.gather()
  for parallel calls across different pairs. asyncio.sleep
  (1.1) between sequential calls to same pair (AR-036).

============================================================
4. STARTUP SEQUENCE
============================================================

4.1 Pre-Connection Checks

  Step 0: Query Kraken Status API at startup (AR-038).
          GET https://status.kraken.com/api/v2/
          scheduled-maintenances/upcoming.json
          If maintenance within 2 hours: log
          KRAKEN_MAINTENANCE_SCHEDULED, alert operator.
          Informational only — does not block startup.
          Executed in BOTH paper and live mode.

  Step 1: Acquire WS token via REST GetWebSocketsToken
          using TRADE API key. Token valid 900 seconds.
          Reconnect logic also acquires new token.
          SKIPPED in paper mode (no private WS needed).

4.2 WS Connection, Subscription, and Universe Population

  PAPER-TO-LIVE PARITY BINDING (D-06):
    Steps 2 through 8 below execute IDENTICALLY in paper
    mode and live mode. Paper-mode skip is limited to
    Step 9 (private WS connect, auth), Step 10 (executions
    and balances subscribe), and Step 11 (snap_orders
    reconciliation). All universe population, REST
    Ticker liquidity filtering, subscriptions, and
    indicator warm-up execute in BOTH modes. Skipping
    any of Steps 2-8 in paper mode is a defect
    (OI-044 root cause; HR-WM-026).

  Step 2: Connect N_conns public WS shards in parallel
          via asyncio.gather. Each shard opens its own
          websockets.asyncio.client.connect to
          wss://ws.kraken.com/v2 with the same
          connection parameters (§3.2). Log
          connection_id from each shard's status
          channel message (AR-064). N_conns is computed
          per §3.1.1 after the universe size is known
          (Step 4) — for the public connect at Step 2,
          a provisional N_conns=1 is sufficient because
          the instrument and status subscriptions
          (Step 3, Step 5) live on shard 0 only and
          shard 0 is needed before universe is known.
          Shards 1..N_conns-1 are connected after Step
          4 once the final tradeable_universe size is
          known. Executed in BOTH modes.

  Step 3: Subscribe instrument channel on shard 0.
          Receive full instrument snapshot. Build per-
          pair status cache. Populate
          tradeable_universe per 0711003 dv1_3 AS-001
          criteria:
            (1) Quote currency: USD, USDC, or USDT
                (D-03 amended TB00130, 0500000 dv1_20
                AR-070)
            (2) Instrument status = online
            (3) 24h volume >= min_volume_usd_daily
                ($500k starting — filter applied in
                Step 4 after REST Ticker call)
          NO top-N cap is applied (D-08 retirement of
          prior monitored_universe_n=50).
          Register the regime anchor handle:
          regime_anchor = "BTC/USD" (0711003 dv1_3 AS-003).
          Under D-03 amended BTC/USD is a member of
          tradeable_universe (USD quote is in scope) AND
          the regime_anchor handle. regime_anchor is
          subscribed for ohlc(5), ohlc(60) cache seed,
          and daily regime. Per AR-074 (unchanged) and
          0711003 dv1_3 HR-AS-009, BTC/USD pipeline
          evaluation for entry is CIATS-OWNED and
          DISABLED BY DEFAULT — Gate 1 default-excludes
          BTC/USD from entry evaluation unless CIATS
          has explicitly enabled BTC/USD pipeline
          evaluation via parameter update. Parse and
          log subscription ACK warnings[] (AR-031).
          Executed in BOTH modes.

  Step 4: Call REST Ticker (0411002 REST-TKR-001) for
          all AS-001 candidate pairs. BTC/USD is naturally
          included as a candidate under D-03 amended
          (USD quote is in scope); no separate append is
          required. Compute USD volume per pair:
            usd_volume_24h = Decimal(v[1]) * Decimal(p[1])
          Populate liquidity_24h cache. Apply the
          min_volume_usd_daily filter: retain only pairs
          where liquidity_24h[pair] >= $500k. regime_anchor
          (BTC/USD) is retained regardless of volume per
          AR-074 (always exceeds $500k/day in practice,
          but the rule holds architecturally). The
          resulting filtered set is the final
          tradeable_universe. Executed in BOTH modes.
          (0711003 dv1_3 AS-004 Steps 4, 5, 6.)

  Step 5: Subscribe status channel on shard 0. Log
          engine state transitions. Executed in BOTH
          modes.

  Step 5a: SHARDING. Compute N_conns per §3.1.1 from
          the final tradeable_universe size. If
          N_conns > 1: connect shards 1..N_conns-1 in
          parallel via asyncio.gather and capture
          connection_id from each shard's status
          channel message. Build pair_to_shard_index
          mapping using alternating-index assignment
          across the sorted tradeable_universe.
          Executed in BOTH modes.

  Step 6: Subscribe ohlc(5) for each pair in
          tradeable_universe, dispatching the subscribe
          to the pair's assigned shard per
          pair_to_shard_index mapping. BTC/USD
          (regime_anchor) is a member of
          tradeable_universe under D-03 amended, so no
          separate iteration append is required. Note:
          ohlc(60) for all pairs is NOT subscribed via
          WS — Kraken WS v2 rejects a second ohlc
          interval per symbol (HR-WM-021). Subscribe
          ohlc(5) via WS only. 1H HTF cache is seeded
          via REST in Step 8. Executed in BOTH modes.

  Step 6.5: Silent-Pair Handling. After all Step 6
          subscribes ack, start a per-pair silent-pair
          timer of T_silent (60s starting value, CIATS-
          owned) for each pair. State machine:

            INITIAL ─[subscribe ack]→ SUBSCRIBED
            SUBSCRIBED ─[snapshot or update received
                         within T_silent]→ DATA_READY
            SUBSCRIBED ─[no snapshot or update within
                         T_silent]→ DATA_PENDING
            DATA_PENDING ─[any update received]→ DATA_READY
            (any state) ─[shard disconnect]→ on
                         reconnect: re-subscribe, reset
                         pair to SUBSCRIBED.

          DATA_PENDING pairs remain in tradeable_universe
          and remain subscribed. They are skipped by
          Signal Pipeline at evaluation (HR-WM-030).
          DATA_PENDING > 1 hour: log
          PAIR_DATA_PENDING_LONG (level=WARN, pair, age).
          No automatic universe removal under any
          circumstance. (TB00142 Rabbit 1 closure: 6 of
          748 pairs (~0.8%) observed silent in long
          Phase D probe; all 6 had effectively zero
          recent activity and would not clear D-04
          $500k/day liquidity filter at signal layer
          regardless.) Executed in BOTH modes.

  Step 7: Subscribe ticker channel for pairs based on
          Position Mirror state (AR-034), dispatching
          each subscribe to the pair's assigned shard
          per pair_to_shard_index mapping. At startup,
          no positions are open (pending snap_orders in
          live mode), so all pairs initially subscribe
          with event_trigger:trades. Mode switches to
          bbo when a position opens. In paper mode:
          ticker subscribed for all tradeable_universe
          pairs (including BTC/USD as regime_anchor
          member) regardless of position state (needed
          for paper fill detection per §13.3). Ticker
          subscribes are also subject to the §4.2 Step
          6.5 silent-pair handling state machine
          (silent on ticker == silent on ohlc almost
          always; per-pair state is unified). Executed
          in BOTH modes.

  Step 8: Indicator warm-up per §4.3 (AR-044, AR-068).
          For each pair in tradeable_universe:
          GetOHLCData(interval=5) to seed ATR(14), RSI(14),
          EMA(9), EMA(21), VolumeMA(20).
          For each pair: GetOHLCData(interval=60) to seed
          EMA(20) and EMA(50) for HTF cache.
          For regime_anchor: GetOHLCData(interval=1440)
          for daily regime computation.
          Stagger 1.1s same-pair; asyncio.gather() across
          pairs. WARM_UP → READY on all five seeded.
          Executed in BOTH modes.

  -------- PAPER-MODE SKIP BOUNDARY --------

  Paper mode executes Steps 9b and 10b (below), then
  proceeds to main loop.

  Live mode executes Steps 9 through 11 (below).

  Step 9 (LIVE ONLY): Connect private WS with token
          from Step 1. Log connection_id from status
          channel on private connection (AR-064).

  Step 9b (PAPER ONLY): Set spot_usd_balance =
          Decimal(str(config.get(
              "paper_starting_balance", 1000))).
          Default is $1,000 per D-05 / TB00001 line 51
          (corrected from prior $10,000 default in
          dv1_1). Set portfolio_baseline_USD =
          spot_usd_balance. Log PAPER_BALANCE_SET
          (level=INFO, component=WS_MGR,
          balance=spot_usd_balance).

  Step 10 (LIVE ONLY): Subscribe executions channel with:
            ratecounter:true     (A-1)
            snap_orders:true     (A-3, AR-003)
            snap_trades:true     (A-3, AR-003)
            order_status:true    (AR-026 — MANDATORY)
          CRITICAL: order_status:true MUST be present.
          Without it, amended and restated exec_types are
          silently dropped, breaking A-12 and A-13.
          Subscribe balances channel. Begin tracking
          sequence integers for gap detection (A-9).

  Step 10b (PAPER ONLY): No executions or balances
          subscription. Paper fill detection is driven by
          ticker events in _handle_ticker() per §13.3.

  Step 11 (LIVE ONLY): Process snap_orders and snap_trades
          response from executions subscription. Reconcile
          Position Mirror. Populate Pending Order Registry
          for all orders in new or pending_new status
          (AR-053). Capture spot_usd_balance from balances
          snapshot. Set portfolio_baseline_USD =
          spot_usd_balance. This baseline is NEVER updated
          during operation and NEVER reset on reconnect
          (AR-052).

4.3 Indicator Warm-Up (AR-044, AR-068)

  For each pair in tradeable_universe (stagger 1.1s per
  pair for the same-pair sequence; asyncio.gather() across
  different pairs). regime_anchor also seeded via the
  same mechanism for ohlc(5) SSS state (unused for
  trading but needed for consistent cache structure) and
  ohlc(60) / daily regime.

  Step 7a: GetOHLCData(interval=5). Use response[:-1].
           Seed ALL five per-pair indicators:
             ATR(14): SMA of first 14 True Ranges. Then
                      incremental: ATR = (prev_ATR*13 +
                      current_TR) / 14. O(1) per update
                      (AR-016).
             RSI(14): Wilder's SMMA (AR-076). Seed:
                      avg_gain = sum(gains[:14]) / 14
                      avg_loss = sum(losses[:14]) / 14
                      Incremental:
                      avg_gain = (prev*13 + gain) / 14
                      avg_loss = (prev*13 + loss) / 14
                      RS = avg_gain / avg_loss
                      RSI = 100 - (100 / (1 + RS))
                      DO NOT use EMA alpha=2/15 for RSI.
             EMA(9):  SMA seed on first 9 closes. Then
                      alpha = 2/10 = 0.2 (standard EMA).
             EMA(21): SMA seed on first 21 closes. Then
                      alpha = 2/22 (standard EMA).
             Vol MA(20): SMA of first 20 volumes. Then
                         rolling SMA thereafter.
           Initialize last_interval_begin from
           response[-2].interval_begin (AR-045).
           Pair transitions WARM_UP → READY only when ALL
           FIVE indicators seeded (AR-068).

  Step 7b: GetOHLCData(interval=60). Use response[:-1].
           Seed EMA(20) and EMA(50) for HTF cache.
             EMA(20): SMA seed on first 20 closes. alpha = 2/21.
             EMA(50): SMA seed on first 50 closes. alpha = 2/51.
           Initialize last_interval_begin_60 from
           response[-2].interval_begin.

  Step 7c: GetOHLCData(interval=1440). Use response[:-1].
           Regime Engine seeding. Passed to Regime Engine.
           Regime computation: exclude response[-1] ALWAYS
           (AR-017). Use only response[:-1].

  STAGGER RULE (AR-036): 1.1s between calls for the SAME
  pair. asyncio.gather() across DIFFERENT pairs.

  WARM_UP pairs are SKIPPED at pipeline pre-check.
  READY pairs begin trading immediately — system does NOT
  wait for all pairs to reach READY (AR-044).

  This procedure executes IDENTICALLY in paper and live
  mode per HR-WM-026.

4.4 Post-Warm-Up: ticker subscription mode

  Subscribe ticker for all READY pairs using event_trigger
  based on Position Mirror state (AR-034):
    event_trigger:bbo    — pairs WITH open positions
    event_trigger:trades — pairs WITHOUT open positions
  WS Manager manages per-pair trigger mode and updates
  subscription when position state changes.

  Paper mode exception: event_trigger:bbo is used for
  pairs with paper positions (detected via position_mirror
  membership) to enable paper fill detection per §13.3.

============================================================
5. PER-SYMBOL STATE (in-memory, not persisted)
============================================================

5.1 Indicator State (updated on each ohlc(5m) close)

  Per monitored pair, WS Manager maintains:
    atr_14:              Decimal   (incremental running value)
    prev_tr:             Decimal   (previous True Range)
    rsi_14_avg_gain:     Decimal   (Wilder SMMA state — AR-076)
    rsi_14_avg_loss:     Decimal   (Wilder SMMA state — AR-076)
    ema_9:               Decimal   (standard EMA alpha=0.2)
    ema_21:              Decimal   (standard EMA alpha=2/22)
    volume_ma_20:        Decimal   (rolling 20-candle SMA)
    last_interval_begin: str       (candle close detection)
    last_complete_candle: OHLCCandle (closed candle data)

  Per monitored pair for HTF Gate 4:
    htf_ema_20:          Decimal   (1H EMA(20))
    htf_ema_50:          Decimal   (1H EMA(50))
    last_interval_begin_60: str    (1H candle close detection)

  Per-pair status cache (from instrument channel):
    pair_status:         dict[str, str] (symbol → status string)
    price_increment:     dict[str, Decimal]   (AR-028)
    qty_min:             dict[str, Decimal]   (AR-028)
    cost_min:            dict[str, Decimal]   (AR-028)

  Pair warm-up state:
    warm_up_state:       dict[str, str]  WARM_UP | READY

  Universe state:
    tradeable_universe:  set[str]  (USD/USDC/USDT pairs
                                    passing AS-001. NO top-N
                                    cap. Includes BTC/USD
                                    under D-03 amended.)
    regime_anchor:       str       ("BTC/USD" — regime
                                    anchor handle; member
                                    of tradeable_universe;
                                    pipeline evaluation
                                    CIATS-owned per AR-074,
                                    default disabled)

5.2 Position State (managed jointly with Position Mirror)

  position_mirror:       dict[str, PositionRecord]
                         (sole authoritative O(1) record)
  pending_orders:        dict[str, Decimal]
                         cl_ord_id → estimated_USD_cost (AR-053)

  PositionRecord fields include (additions dv1_1):
    tp_price:            Decimal   (TP limit price — paper mode)
    emergsl_price:       Decimal   (emergSL trigger price — paper mode)
  These fields are populated by batch_add() in paper mode
  (where no actual Kraken orders are placed) to enable
  _handle_ticker() paper fill detection.

5.3 Selection Controller State (AR-073)

  exit_cooldown_log:         dict[str, float]
                             symbol → time.monotonic() of last exit
  consecutive_loss_count:    dict[str, int]
                             symbol → consecutive losses without win
  Update on position close:
    Always: exit_cooldown_log[symbol] = time.monotonic()
    If loss exit (MAE_THRESHOLD_BREACH, TIME_EXPIRY,
      HTF_REGIME_REVERSAL, DAILY_REGIME_DOWNGRADE,
      SIGNAL_DECAY): consecutive_loss_count[symbol] += 1
    If TP_FILL (win): consecutive_loss_count[symbol] = 0
  Both dicts PRESERVED across reconnect. NEVER discarded.

5.4 Drawdown State (AR-052)

  portfolio_baseline_USD:   Decimal
      - Live mode: set once at startup Step 11 from snap_orders
        spot_usd_balance.
      - Paper mode: set at startup Step 9b from config
        paper_starting_balance (default $1,000 per D-05).
      - NEVER updated or reset on reconnect.
  spot_usd_balance:         Decimal   (updated on every balances event
                                        in live mode; static in paper mode)
  drawdown_pct:             Decimal   (computed on every bbo event)
  system_state:             str       NORMAL | SESSION_PAUSE | FULL_HALT
  PRESERVED across reconnect. NEVER reset on reconnect.

5.5 Connection Health State

  last_real_data_time_public:  float  (time.monotonic())
  last_real_data_time_private: float  (live mode only)
  executions_last_seq:         int    (gap detection A-10)
  balances_last_seq:           int    (gap detection A-9)
  req_id_registry:             dict[int, RequestRecord]
                               req_id → {method, timestamp, symbol}

============================================================
6. CANDLE-CLOSE DETECTION (AR-045)
============================================================

WS OHLC fires on every trade event within the candle
period — NOT only on candle close. WS Manager MUST
implement candle-close detection:

  On each ohlc(5m) message for symbol S:
    if msg.interval_begin == last_interval_begin[S]:
      Update in-progress candle. DO NOT fire pipeline.
    else:
      Candle for last_interval_begin[S] is NOW CLOSED.
      Fire pipeline with last_complete_candle[S].
      last_complete_candle[S] = current message data.
      last_interval_begin[S] = msg.interval_begin.

  Same logic for ohlc(60) with separate
  last_interval_begin_60 dict.

  OHLC interval field: use interval_begin (AR-027).
  deprecated timestamp field MUST NOT be used.

  OHLC stall: If no trades occur after an interval border,
  no OHLC message is sent until next trade. WS Manager
  MUST handle this — pipeline does not fire on stalled
  pairs. Addressed in 0511002.

  Pipeline is fired for every pair in tradeable_universe.
  regime_anchor (BTC/USD) candle closes update regime
  state but DO NOT trigger entry pipeline evaluation
  (Gate 1 exclusion per HR-AS-009).

============================================================
7. CONNECTION HEALTH MONITORING
============================================================

7.1 JSON Ping / Keepalive (A-7)

  Send {"method":"ping"} on EACH active WS connection
  every 30 seconds. Expect {"method":"pong"} within 10
  seconds. No pong within 10 seconds = dead connection.
  Reconnect immediately.
  Application-level ping only. Library TCP PING disabled
  (AR-059). No dual ping mechanism.
  In paper mode: ping sent on public WS only (private WS
  is None). Private ping section is guarded:
    if self._ws_private is not None: [private ping logic]

7.2 Zombie Connection Detection (A-8, AR-042)

  Track last_real_data_time per connection using
  time.monotonic(). Reset ONLY on real channel events:
    ohlc, ticker, instrument, executions, balances, status
  MUST NOT reset on: heartbeat, pong, ACK messages.
  If elapsed > 90 seconds:
    Log ZOMBIE_CONNECTION_DETECTED (CRITICAL)
    Alert operator (HIGH)
    Reconnect immediately
  In paper mode: private zombie check is guarded:
    if self._ws_private is not None: [private zombie logic]

7.3 Balances Sequence Gap Detection (A-9)

  Track balances_last_seq integer. Any gap (skip > 1):
    Alert immediately (HIGH)
    Trigger REST GetAccountBalance reconciliation
    Log BALANCES_SEQUENCE_GAP
  Missed balance events = incorrect capital calculation
  = direct loss risk.
  Live mode only. In paper mode: no balances subscription.

7.4 Executions Sequence Gap Detection (A-10)

  Track executions_last_seq independently. Any gap:
    Alert immediately (CRITICAL — higher severity than A-9)
    Trigger REST GetOpenOrders reconciliation
    Reconcile Position Mirror
    Log EXECUTIONS_SEQUENCE_GAP
  Missed execution events = Position Mirror desync =
  TothBot does not know position state = direct loss risk.
  Sequence tracking resets on each new subscription
  (reconnect). Do NOT gap-detect across sessions.
  Live mode only. In paper mode: no executions subscription.

7.5 Rate Counter Monitoring (A-1, AR-030)

  executions subscription includes ratecounter:true at
  zero additional cost. WS Manager tracks per-pair rate
  counter. Operative ceiling = maxratecount from
  subscription ACK (AR-030). Use ACK value, not hardcoded
  125. Expose rate_counter_by_pair to CIATS EWMA Monitor.
  Live mode only.

7.6 Connection ID Logging (AR-064)

  Log connection_id (uint64) from status channel on every
  new WS connection. Include in all reconnect, disconnect,
  and gap log entries. Zero additional cost.

8. INBOUND DISPATCH TABLE (AR-015, AR-023)
============================================================

All inbound WS messages routed via O(1) dispatch table
keyed on channel + message type. Unknown message types:
log UNKNOWN_MESSAGE_TYPE (WARN), never silently dropped.

The executions channel exec_type dispatch table MUST handle
ALL 10 values explicitly (AR-023):

  pending_new    — Order accepted by engine. No Mirror update.
  new            — Order active on book. No Mirror update.
  trade          — Partial fill. Update Mirror (cum_qty,
                   avg_price). If entry: check for partial
                   fill protection trigger (AR-054).
                   Capture last_qty, last_price (AR-061).
  filled         — Full fill. Trigger appropriate action:
                   - Entry filled: Execution Engine dispatches
                     batch_add TP+emergSL (0511003).
                   - TP filled: L1b — Exit Controller cancels
                     emergSL (0511004). Fire CIATS.
  iceberg_refill — Log only. No Mirror update.
  canceled       — Clear pending_orders. If entry canceled
                   with cum_qty > 0: partial fill protection
                   (AR-054). If exit canceled: cancel timeout
                   fallback resolution.
  expired        — Same as canceled handling (AR-054 applies).
  amended        — User-initiated amend. TothBot V1 NEVER
                   sends amend_order for its own orders.
                   Any amended event = UNEXPECTED_ORDER_AMENDED
                   (CRITICAL), alert operator HIGH. Do NOT
                   auto-correct. Operator must review (AR-057).
  restated       — Engine maintenance amend. NOT fill/cancel.
                   Do NOT update Position Mirror. Elevated
                   alert if resting order affected (AR-024).
  status         — Order status snapshot. Log. No trade action.

  use reason field (not cancel_reason — deprecated, AR-022).

8.1 TP Partial Fill Handling (AR-066)

  When exec_type=trade for a TP order (identified by
  order_id matching TP order_id in Position Mirror):
    remaining_qty = tp_order_qty - cum_qty
    Update Position Mirror qty to remaining_qty
    Amend emergSL to remaining_qty via amend_order
      (NOT cancel+resubmit — saves rate counter + preserves
      queue position)
    Rate counter: amend_order (+1 fixed) vs cancel_order
      (+8 <5s) + add_order (+1) = +9 total — amend saves 8.
    If remaining_qty < qty_min OR remaining_qty * bid < cost_min:
      cancel emergSL → immediate market sell → clear Mirror
  Fire CIATS Trade Outcome Bus ONCE on full position close
  (aggregate all partial fill data). Not on each partial.
  On exec_type=filled (full TP): L1b logic unchanged.

8.2 Entry Partial Fill + Expiry/Cancel (AR-054)

  GTD post_only entry orders can receive partial fills
  before expiry or cancel. When exec_type=="expired" OR
  exec_type=="canceled" AND cum_qty > 0 (REAL position,
  no TP, no emergSL):
    CASE A (expired, cum_qty > 0) or CASE B (canceled, cum_qty > 0):
      1. Clear Pending Order Registry for this cl_ord_id.
      2. Extract qty=Decimal(str(cum_qty)),
         entry=Decimal(str(avg_price)).
      3. Validate qty >= qty_min AND qty*entry >= cost_min.
         If fails: dispatch market sell immediately.
      4. Recalculate TP and emergSL from actual entry price
         using current ATR(14) and mae_mult / sl_mult.
         Verify net_gain = net_loss * 1.5 (sacred R:R).
      5. Dispatch batch_add: TP limit + emergSL stop.
      6. Enter Position Mirror with cum_qty and avg_price.
      7. Log ENTRY_PARTIAL_FILL_PROTECTED.
    CASE C (expired or canceled, cum_qty == 0):
      No fill. Clear registry. Log. No position.

  No call to cancel_all_orders_after under ANY circumstance.

11. MID-SESSION RECONNECT (AR-056)
============================================================

Mid-session reconnect is DISTINCT from startup. Implemented
as a separate code path.

PER-SHARD RECONNECT (PATH 2). Under PATH 2 multi-connection
architecture, each public WS shard is an independent
reconnect domain. Loss of one shard reconnects only that
shard. The other N_conns - 1 shards continue uninterrupted.
Universe re-shard is NOT performed on per-shard reconnect —
the reconnecting shard re-subscribes its existing symbol
partition. This bounds reconnect blast radius to
universe_size / N_conns pairs, not the entire universe.

Loss of the PRIVATE connection reconnects the PRIVATE
connection only. Public shards are unaffected by PRIVATE
loss.

Key distinctions from startup:
  portfolio_baseline_USD: NEVER reset on reconnect.
  drawdown_pct:           PRESERVED across reconnect.
  system_state:           PRESERVED across reconnect.
  tradeable_universe:     PRESERVED across reconnect.
  regime_anchor:          PRESERVED across reconnect.
  pair_to_shard_index:    PRESERVED across per-shard
                          reconnect; rebuilt only on
                          universe re-evaluation.
  ATR/EMA caches:         PRESERVED unless gap > 15 minutes
                          (stale threshold — re-seed if stale).
  exit_cooldown_log:      PRESERVED.
  consecutive_loss_count: PRESERVED.
  Pair states (DATA_READY / DATA_PENDING per §4.2 Step
  6.5): RESET to SUBSCRIBED on the reconnecting shard's
  pairs only. Silent-pair timer restarts.

Per-shard reconnect sequence (PUBLIC SHARD i, LIVE OR PAPER):
  1. Connect public WS shard i (re-open
     websockets.asyncio.client.connect with same params).
  2. If shard i == 0: resubscribe instrument and status.
  3. Resubscribe ohlc(5) for the symbols owned by shard i
     per pair_to_shard_index.
  4. Resubscribe ticker per §4.4 for the symbols owned by
     shard i (event_trigger per Position Mirror state).
  5. Reset silent-pair timers per §4.2 Step 6.5 for shard
     i's pairs.
  6. Resume normal operation on shard i. Other shards
     unaffected.

Reconnect sequence (PRIVATE, LIVE MODE only):
  1. Acquire new WS token (GetWebSocketsToken).
  2. Connect private WS.
  3. Resubscribe executions and balances (with
     order_status:true, snap_orders:true, snap_trades:true,
     ratecounter:true per §4.2 Step 10).
  4. Process snap_orders: compare against pre-disconnect
     Position Mirror. Detect gap-closed positions.
  5. For each position closed during gap:
     Fire CIATS Trade Outcome Bus with available data.
     Log GAP_CLOSED_POSITION.
  6. Reconcile Pending Order Registry against snap_orders.
  7. Reset sequence counters (executions_last_seq,
     balances_last_seq) — do NOT gap-detect across sessions.
  8. DISCARD any pipeline events queued during reconnect.
     Pipeline evaluations PROHIBITED during reconnect of
     ANY connection (per HR-WM-012).
  9. Resume normal operation.

PIPELINE-DURING-RECONNECT GUARD. Pipeline evaluations are
prohibited while ANY shard or the private connection is
in reconnect state. Pipeline resumes only when all active
connections are healthy. This prevents partial-universe
signal evaluation during a degraded-connectivity window
(HR-WM-012 generalized to multi-connection architecture).

Fatal reconnect (per shard or private): 10 attempts over
120 seconds on the same connection →
  Log FATAL_RECONNECT_FAILURE (CRITICAL, with shard_index
    or "private") →
  systemd restarts TothBot process → full startup sequence
  (full re-shard).

13. PAPER TRADING MODE
============================================================

13.1 Activation

  paper_mode is set from config key paper_trading_mode
  (bool). Defaults to False (live) if not present.
  Read once in WSManager.__init__:
    self.paper_mode: bool = bool(
        config.get("paper_trading_mode", False))

  When paper_mode is True:
    - Private WS is NEVER connected.
    - All order operations are simulated locally.
    - Public WS connects and operates normally.
    - Universe population, REST Ticker liquidity
      filtering, subscriptions, indicator warm-up,
      OHLC processing, ticker events, and pipeline
      triggers execute IDENTICALLY to live mode
      (D-06 / HR-WM-026).
    - Position tracking, drawdown, and CIATS operate
      normally.

13.2 Simulated Order Methods

  All order methods gate on paper_mode at entry and return
  immediately after logging a simulation event:

  add_order():
    Log PAPER_ORDER_SIMULATED (symbol, cl_ord_id, qty, price).
    Schedule _simulate_entry_fill(cl_ord_id, symbol, price,
        qty) as asyncio.create_task().
    return. Do NOT call _send_private().

  _simulate_entry_fill(cl_ord_id, symbol, price, qty):
    Async method. sleep(0.1) to simulate exchange latency.
    Call Execution Engine entry fill callback with simulated
    fill data (price = entry limit price, qty = full qty).
    Log simulated fill event.

  batch_add():
    Populate PositionRecord fields from call arguments:
      pos.tp_price    = tp_limit_price
      pos.emergsl_price = sl_trigger_price
      pos.tp_order_id   = f"PAPER_TP_{cl_ord_id}"
      pos.emergsl_order_id = f"PAPER_SL_{cl_ord_id}"
    Log PAPER_BATCH_ADD_SIMULATED (symbol, tp_price,
        emergsl_price, tp_order_id, emergsl_order_id).
    return. Do NOT call _send_private().

  cancel_order():
    Log PAPER_CANCEL_SIMULATED (cl_ord_id).
    return.

  amend_order():
    Log PAPER_AMEND_SIMULATED (cl_ord_id, new params).
    return.

  batch_cancel():
    Log PAPER_CANCEL_SIMULATED for each order_id.
    return.

  dispatch_market_sell():
    Log PAPER_MARKET_SELL_SIMULATED (symbol, qty).
    Immediately remove position from Position Mirror.
    Fire CIATS Trade Outcome Bus.
    return. Do NOT call _send_private().

13.3 Paper Fill Detection (_handle_ticker)

  In paper mode, _handle_ticker() performs fill simulation
  based on ticker bid/ask prices against stored PositionRecord
  tp_price and emergsl_price fields:

  On each ticker event for symbol S where paper_mode is True
  and symbol S is in position_mirror:

    TP detection:
      if current ask >= pos.tp_price:
        Log PAPER_TP_FILL_DETECTED (symbol, tp_price, ask).
        Remove position from Mirror.
        Fire CIATS Trade Outcome Bus (win).
        Unsubscribe ticker bbo for S → trades mode.

    emergSL detection:
      if current bid <= pos.emergsl_price:
        Log PAPER_EMERG_SL_TRIGGERED (symbol, emergsl_price,
            bid).
        Remove position from Mirror.
        Fire CIATS Trade Outcome Bus (loss).
        Unsubscribe ticker bbo for S → trades mode.

  TP check runs before emergSL check on every event.
  Only one fires per event.

13.4 Main Loop Paper Path

  _main_loop() branches on paper_mode:

  PAPER MODE (3-task group):
    async with asyncio.TaskGroup() as tg:
        tg.create_task(self._recv_loop_public())
        tg.create_task(self._ping_loop())
        tg.create_task(self._zombie_monitor())
    return

  LIVE MODE (4-task group):
    async with asyncio.TaskGroup() as tg:
        tg.create_task(self._recv_loop_public())
        tg.create_task(self._recv_loop_private())
        tg.create_task(self._ping_loop())
        tg.create_task(self._zombie_monitor())

  Private recv loop is excluded from paper mode — there
  is no private WS connection to receive from.

13.5 Private Guards in Supporting Methods

  _ping_loop():
    Private ping section guarded:
      if self._ws_private is not None:
          [private ping logic]
    Public ping executes unconditionally.

  _zombie_monitor():
    Private zombie check guarded:
      if self._ws_private is not None:
          [private zombie detection logic]
    Public zombie check executes unconditionally.

13.6 Paper Starting Balance (D-05) and Synthetic Ledger
     Evolution

  paper_starting_balance config key defaults to $1,000
  per TB00128 Ratified Decision D-05 (source: TB00001
  line 51). Prior dv1_1 default was $10,000 — corrected
  in dv1_2.

  If config key is absent: default $1,000.
  If config key is explicitly set: use the configured value.
  Ops procedure to change the value between runs: edit
  config file, restart process (standard systemd restart
  cycle per 0211005).

  IMPORTANT (dv1_5): The synthetic spot_usd_balance is
  NOT static. It is INITIALIZED to paper_starting_balance
  at startup AND EVOLVES through the run as simulated
  fills realize P/L. Per HR-WM-032 (paper ledger update
  rule), every paper exit (TP fill, emergSL trigger,
  Layer 2 MAE breach, Layer 1 signal exit, time expiry,
  any other close path) updates spot_usd_balance using
  the same fee schedule Kraken applies in live (entry
  maker fee + exit fee). This makes paper-mode capital
  ledger evolution mirror live-mode balance-channel
  evolution wherever physically possible per
  TB00000 v2_18 §4.4 PA-001..010 PAPER-AS-MASTER.

13.7 Paper Synthetic Ledger Update Rule (NEW dv1_5)

  HR-WM-032 PAPER LEDGER UPDATE governs how
  spot_usd_balance evolves in paper mode. The rule is
  cascaded into the coding spec at 1011002 dv1_26 §10A
  WM-PAPER-LEDGER-001 through WM-PAPER-LEDGER-004.

  CONCEPT.

    Paper mode has no Kraken balances channel by
    HR-WM-022 (paper does NOT connect private WS).
    Without the balances channel, spot_usd_balance
    cannot be updated by exchange-pushed events.
    Paper mode therefore maintains a SYNTHETIC LEDGER
    that is updated locally on every simulated fill
    using the same arithmetic Kraken applies in live.

  REQUIRED BEHAVIOR.

    On startup (paper mode):
      spot_usd_balance      = paper_starting_balance
      portfolio_baseline_USD = paper_starting_balance

    On every paper ENTRY simulated fill
    (_simulate_entry_fill):
      entry_cost = entry_qty * entry_price
      entry_fee  = entry_cost * FEE_MAKER_PCT
      spot_usd_balance -= (entry_cost + entry_fee)
      Position is added to position_mirror with
      fees_entry_usd = entry_fee captured.

    On every paper EXIT simulated fill (TP fill,
    emergSL trigger, Layer 2 MAE breach, Layer 1
    signal exit, time expiry):
      exit_proceeds = exit_qty * exit_price
      exit_fee = exit_proceeds * FEE_MAKER_PCT
                 (TP, maker fee — limit order fills)
                 OR
      exit_fee = exit_proceeds * FEE_TAKER_PCT
                 (emergSL trigger, market sell —
                  taker fee)
      spot_usd_balance += (exit_proceeds - exit_fee)
      The Position Mirror entry is then cleared by
      Exit Controller per HR-WM-033.

    portfolio_baseline_USD is NEVER updated after
    startup (HR-WM-011 unchanged in paper mode).

  CONSEQUENCE.

    Drawdown computation (§5.4) operates correctly
    in paper mode because spot_usd_balance reflects
    realized cash + unrealized open-position MTM
    (sum of position_mirror entries × bid). Without
    HR-WM-032, paper drawdown denominators would be
    wrong and circuit breakers (SESSION_PAUSE,
    FULL_HALT) would fire on incorrect numbers.

    CIATS Trade Outcome Bus receives a complete
    TRADE_CLOSE log record per HR-WM-033 with
    realized P/L derivable from entry + exit prices
    + qty + fees. Half-Kelly computation
    (CIATS-KE-002) operates on paper data identically
    to live data. PA-005 byte-identical CIATS data
    flow holds.

  LOG EVENTS REQUIRED.

    PAPER_LEDGER_UPDATED  on every ledger mutation,
                          payload includes
                          {event_type, symbol,
                          delta_usd, fee_usd,
                          new_balance, exit_reason}.

13.8 Paper Exit Routing Through Exit Controller
     (NEW dv1_5)

  HR-WM-033 PAPER EXITS ROUTE THROUGH EC governs the
  paper-mode exit path so that ALL exits (live and
  paper) traverse the same Exit Controller close
  sequence. Cascaded into the coding spec at 1011002
  dv1_26 §6.x and 1011005 dv1_3 EC-PAPER section.
  Cross-referenced from 0511004 dv1_3 §EC-PAPER.

  PROBLEM (pre-dv1_5).

    Paper-mode exits in dv1_25 code (_maybe_paper_fill,
    paper-mode handle_filled, paper-mode
    dispatch_market_sell) bypass the Exit Controller
    entirely. They directly mutate position_mirror via
    pop() and fire a parallel CIATS outcome path
    (_fire_ciats_outcome) that does NOT emit a
    TRADE_CLOSE log record and does NOT carry P/L
    payload. CIATS Half-Kelly cannot operate on paper
    data because TRADE_CLOSE records are absent.

    This violates HR-WM-025 (paper does NOT affect
    CIATS data flows) and TB00000 v2_18 §4.4 PA-005
    (paper-live byte-identical outside PA-004 four
    points). The paper-vs-live exit path divergence
    is NOT one of the four PA-004 points; it is a
    defect.

  REQUIRED BEHAVIOR (dv1_5).

    All paper-mode exit paths MUST route through Exit
    Controller's close sequence:

      Paper TP detected (_handle_ticker, ask >= tp_price):
        1. Compute exit_price = tp_price (limit order
           fills at the limit).
        2. Compute fees_exit = exit_qty * tp_price *
           FEE_MAKER_PCT.
        3. Apply HR-WM-032 ledger update:
           spot_usd_balance += (exit_proceeds - fees_exit).
        4. Call Exit Controller's _close_position(
           symbol, exit_price=tp_price,
           exit_reason="TP_FILL",
           fees_exit=fees_exit, wm=self).
        5. Exit Controller emits TRADE_CLOSE log
           record (EC-TOB-002) with full P/L payload.
        6. Exit Controller clears position_mirror,
           releases semaphore, updates Selection
           Controller state.
        7. Unsubscribe ticker bbo for symbol →
           trades mode.

      Paper emergSL triggered (_handle_ticker,
      bid <= emergsl_price):
        1. Compute exit_price = bid (market sell at
           current bid — taker fill).
        2. Compute fees_exit = exit_qty * bid *
           FEE_TAKER_PCT.
        3. Apply HR-WM-032 ledger update.
        4. Call _close_position(symbol,
           exit_price=bid, exit_reason="EMERGENCY_SL",
           fees_exit=fees_exit, wm=self).
        5. Exit Controller emits TRADE_CLOSE.
        6. Exit Controller cleanup.
        7. Unsubscribe ticker bbo → trades mode.

      Paper Layer 1 signal exit, Layer 2 MAE breach,
      time expiry, regime exit (any path Exit
      Controller normally drives in live):
        Exit Controller's normal close sequence runs
        in paper mode too. The dispatch_market_sell()
        in paper mode does NOT directly clear
        position_mirror; it computes the exit_price
        from current bid + fees_exit at taker rate,
        applies HR-WM-032 ledger update, then yields
        control back to Exit Controller's
        _close_position which finishes the close
        sequence.

  CIATS DATA FLOW PARITY.

    Paper-mode TRADE_CLOSE log records contain the
    same fields as live-mode TRADE_CLOSE records:
      ts, event=TRADE_CLOSE, symbol,
      entry_fill_price, exit_price,
      entry_timestamp_utc, exit_timestamp_utc,
      hold_candle_count, MAE_pct_reached,
      fees_entry_usd, fees_exit_usd, fees_total_usd,
      exit_reason, asset_regime, vol_regime,
      market_regime, signal_params, actual_RR,
      net_PL_USD, net_gain_usd, net_loss_usd.

    CIATS log-file polling reads paper TRADE_CLOSE
    records identically to live records. Half-Kelly,
    Mann-Whitney U, EWMA, CUSUM, and Spearman
    operate on a unified corpus.

  RETIRED PARALLEL PATH.

    The dv1_4 / dv1_25 _fire_ciats_outcome function
    in ws_manager.py is RETIRED in dv1_26. All CIATS
    outcome data flows via Exit Controller's
    TRADE_CLOSE log emission. ws_manager.py paper-
    mode exit code paths must ONLY apply HR-WM-032
    ledger update, then call Exit Controller for the
    rest of the close sequence.

14. HARD RULES
============================================================

HR-WM-001  Two API key pairs: DATA (public WS, REST market
           data) and TRADE (private WS, REST auth). Both
           IP-whitelisted to 87.99.141.44 (AR-037).

HR-WM-002  All WS connections: max_queue=None, ping_interval
           =None, max_size=10MB, open_timeout=10. No exceptions.

HR-WM-003  Application JSON ping every 30 seconds on EACH
           active connection. Library TCP PING disabled.
           Single authoritative keepalive mechanism (AR-059).
           In paper mode: public WS only.

HR-WM-004  last_real_data_time reset ONLY on real channel
           events. Heartbeat, pong, and ACK MUST NOT reset
           the zombie detection timer (AR-042).

HR-WM-005  executions subscription MUST include
           order_status:true (AR-026). Without it, amended
           and restated exec_types are silently dropped.

HR-WM-006  All 10 exec_type values handled explicitly in
           dispatch table. No silent drops (AR-023).

HR-WM-007  cancel_reason is deprecated. Use reason field
           in all executions channel parsing (AR-022).

HR-WM-008  All Decimal values from WS messages: convert via
           Decimal(str()) immediately on receipt (AR-047).

HR-WM-009  stp_type in WS v2: underscore (cancel_newest).
           REST: hyphen (cancel-newest). Never confuse
           (AR-032).

HR-WM-010  cancel_all_orders_after: EXPLICITLY PROHIBITED
           under any circumstance (AR-055, HR-DMS-001).

HR-WM-011  portfolio_baseline_USD: set once at startup.
           NEVER updated or reset during operation or on
           reconnect (AR-052). In paper mode: set from
           config paper_starting_balance (default $1,000
           per D-05). In live mode: set from snap_orders
           spot_usd_balance at Step 11.

17. ARCHITECTURAL DECISION RECORD: PATH 2 MULTI-CONNECTION
    BATCHED-SUBSCRIBE
============================================================

17.1 STATUS

  ACCEPTED. Authored TB00142 / 04-26-2026 UTC.
  Supersedes implicit single-connection assumption in
  dv1_3 and earlier. Implementation contract in 1011002
  dv1_24.

17.2 CONTEXT

  TothBot V2 trades a universe of TOKEN/USD,
  TOKEN/USDC, TOKEN/USDT pairs (D-03) — currently 748
  pairs, drifting daily as Kraken adds and removes
  listings. The trading system requires a real-time
  price feed for the entire D-03 universe. Kraken
  WebSocket v2 is the authoritative feed.

  Empirical evidence from TB00141 STREAM 1 and TB00142
  STREAM 1 long-window probe:

    Single-connection batched-subscribe ceiling for
    ticker+ohlc back-to-back lies between 650 and 700
    symbols. Above ceiling: immediate TCP close with
    no warning frame. (TB00141 §3.5 Phase B
    bisection.)

    748-pair universe exceeds the single-connection
    ceiling. Single-connection architecture cannot
    carry the D-03 universe on any batching technique.

    Multi-connection batched-subscribe at 2
    connections × 374 symbols runs clean over a 2-hour
    observation window (TB00142 §3.4 long Phase D):
      Disconnects:           0
      Rate-limit errors:     0
      Steady-state rate:     ~10 msg/s aggregate
                             ~5 msg/s per conn
      Heartbeat cadence:     1.0/s/conn (matches
                             Kraken spec)

17.3 DECISION

  PATH 2: multi-connection batched-subscribe.

  Number of connections is computed at startup as:

    N_conns = ceil(universe_size / SYMBOLS_PER_CONN_SAFE)

  where SYMBOLS_PER_CONN_SAFE = 500 (CIATS-owned
  starting value; 23-29% safety margin under
  empirically-confirmed 650-700 ceiling).

  Symbols are distributed across connections via
  alternating-index assignment (load-balanced by
  sorted-symbol ordering).

  Each connection holds its assigned symbol partition
  for the session lifetime. Re-shard occurs only on
  universe re-evaluation or per-shard reconnect.

  Subscribe count is decoupled from max_concurrent.
  The full D-03 universe is always subscribed
  regardless of position count.

17.4 ALTERNATIVES CONSIDERED AND RETIRED

  PATH 1 — single-connection batched-subscribe.
    RETIRED. 650-700-symbol ceiling vs 748-pair
    universe. Cannot carry D-03.

  PATH 3 — tiered HOT/WARM (high-liquidity pairs on
    dedicated connection, rest on shared connection).
    RETIRED. Adds operational complexity (re-tiering
    on liquidity drift), creates asymmetric reconnect
    impact (HOT loss = total halt), and PATH 2
    already meets the requirement without tiering.

  PATH 4 — PATH 1 with adaptive backoff on
    rate-limit error.
    RETIRED. PATH 1 base architecture is not viable.
    Backoff layer atop a non-viable base is not a fix.

17.5 CONSEQUENCES

  Positive.
    - D-03 universe fully observable. No silent
      narrowing at the WS layer.
    - Per-connection load is bounded and predictable.
      SYMBOLS_PER_CONN_SAFE acts as a CIATS-tunable
      knob.
    - Universe growth past the single-conn ceiling
      is handled transparently: N_conns grows by 1
      per 500 additional pairs.
    - Reconnect blast radius is limited to one shard.
      Loss of one connection affects universe_size /
      N_conns pairs, not the whole universe.

  Negative.
    - Per-pair memory footprint × N_conns for
      heartbeat tracking and connection-state dicts.
      Negligible at expected N_conns (currently 2;
      would be 3 at 1500-pair universe).
    - Reconnect logic is per-shard. Coordinated
      re-shard on universe change requires care to
      avoid double-subscribe and gap.
    - 0.8% snapshot-silent pairs observed in long
      Phase D (6 of 748). Handled by the silent-pair
      state-machine in §4.2 Step 6.5.

  Neutral.
    - Public WebSocket endpoint (no auth) used for
      market data subscribe/receive. Authenticated
      endpoint (private orders / ownTrades) is
      independent and unaffected by this decision.

  CONFIRMED_CEILING_HIGH             = 700
